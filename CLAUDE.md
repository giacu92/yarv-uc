## Project

RV32IMAC + Zicsr + Zifencei RISC-V core for a **Gowin GW2AR-18C** FPGA (QFN88) on a Tang Nano 20k. Clock: 25 MHz single-ended from an MS5351M generator (CLK0, PIN10, LVCMOS33) — not the stock 27 MHz oscillator. **Active build: 50 MHz via on-chip rPLL** (`clk_core = clk_i × 10/5`, IDIV_SEL=4 / FBDIV_SEL=9 / ODIV_SEL=16, VCO 800 MHz, period 20 ns) — **re-closed at 50.017 MHz on the 64-bit fetch-rewrite + target-span design (2026-08-27)**. A **branch predictor (gshare 64×2b PHT + 6-bit GHR + 8-entry RAS, prediction-at-decode, execute-as-judge) was added 2026-08-28** and is sim-verified (all oracles/cosims/TBs green) with a measured **+2–4% IPC** (CoreMark 0.563→0.585, Dhrystone 0.519→0.535, quicksort 0.538→0.549). Its PnR currently reaches **47.4 MHz**, though — the predictor's flops congest the existing `regfile → forward mux → de_bus.rs2_data` path (the pre-predictor limiter) by ~1.1 ns — so **50 MHz re-closure with the predictor integrated is deferred** (`BP_EN=0` prunes the predictor and restores the pre-predictor path). The pre-fetch-rewrite design closed at 40.281 MHz (2026-08-25) via two register stages (the LSU request and the CSR read). Fallback to a 25 MHz bypass (also the diagnostic config — it removes the rPLL entirely): three lines in `top_module`, re-comment the SDC generated clock, `global_freq 25.000` (recipe in the file).

**Status:** fetch/decode/execute + LSU + Zicsr + trap/exception/interrupt implemented. **Harvard** memory system — read-only I-mem for fetch, native byte-strobed D-mem for the LSU, AXI4-Lite only for peripherals. **Both memories are 16 KiB (`ADDR_W=14`)**: the GW2AR-18C has 46 BSRAM blocks = 828 Kb, so each 16 KiB memory is 8 blocks (4 byte lanes × 2), 16 of 46. The package also carries **8 MiB (64 Mbit) of SDRAM on a separate die**, unused so far (see the plan). Loads/stores/Zilx/CSR ops retire via native D-mem (or the peri bridge) with an **execute→decode forward path** (distance-1 RAW resolved same-cycle, zero bubble).

**Machine-mode traps:** precise sync traps at execute commit — instruction access fault (mcause=1, mtval=unfetchable PC), illegal instr (2), ecall-M (11), ebreak (3), load/store addr-misaligned (4/6, mtval=bad EA); `mret` returns; `wfi`=halt-until-pending-interrupt; `fence`/`fence.i`=nop. `mtvec` direct+vectored; mepc/mcause/mtval on entry. Software interrupt (0x8000_0003) via `msip_peri` @0x1000_3000; timer (…_0007) via `clint_timer` @0x1000_1000+; external (…_000B) = OR of peripheral IRQs (UART today) → `meip_i`. Priority MEI>MSI>MTI. A trapping instruction is not retired.

**Timing:** the pre-fetch-rewrite design closed at **40.281 MHz actual** (2026-08-25), reached from ~27.7 MHz by two register stages: the LSU request (+4.8 ns) and the CSR read. **The 64-bit/2-outstanding fetch rewrite + target-span stitch re-closed at 50.017 MHz (2026-08-27)** — its instruction buffer + room comparator (the one new path, `available = 8 - count - 2*inflight; >=2` feeding `wvalid`) met the 20 ns target, and the `head+1` target-span stitch kept the critical path on the existing `head_q → fe_instr → c_expand → regfile → forward` path. **The branch predictor (added 2026-08-28) dropped PnR to 47.4 MHz** — the prediction path itself (head_q → `pred_dir_target` adder → fetch pc_q) was fixed by truncating the target adder to IMEM_ADDR_W bits, but that change was **reverted** (it gave wrong targets on far jumps, and the in-I-mem kernels never exercise them so it bought nothing IPC); the remaining violation is **congestion**: the predictor's ~430 extra flops (PHT 64×2, RAS 8×32, GHR, de_t.pred_*) bump routing delay on the unchanged `regfile → forward mux → de_bus.rs2_data` path by ~1.1 ns. 50 MHz re-closure with the predictor is **deferred**; `BP_EN=0` prunes the predictor and restores the 50.017 MHz path. Lesson from the sequence: an Fmax measured under a loose constraint understates what PnR will do when actually pushed. Next limiter if more is ever wanted: `regfile → forward mux → branch compare/target → PC redirect` — compute PC-relative targets in decode (only `jalr` needs a register operand) or register the redirect at a cycle on taken branches. The stall histogram (2026-08-27) says the same thing from the cycle side: **the redirect was the largest single cost** (~3.1 cycles per taken redirect, 38-50% of all no-retire cycles) — which is exactly what the predictor targets, dropping redirect CPI 0.374→0.102 on CoreMark. Legacy `VON_NEUMANN` build dropped.

CPU exposes 3 ports: native `imem` (RO), native `dmem` (byte-strobed), AXI4-Lite master `axi_peri`. Native→AXI conversion happens inside the CPU (`axi4_lite_master_bridge`); the board top is pure point-to-point wiring. The LSU decodes `addr[PERI_ADDR_BIT]` itself (0→D-mem, 1→peri). Only non-bus CPU output: `dbg_stall_o`→LED0.

## Simulation (Verilator)

Builds fetch+decode+execute+native I/D-mem+peri bridge. `--public-flat-rw` build.

- `sim/sim_top.sv` — wrapper preloading native I/D-mem via `$readmemh`, plusargs `+IINIT=`/`+DINIT=`. `u_imem` is the 64-bit RO `OUTSTANDING=2` native_ram (I-mem hex is `%016x`, 64-bit words); `u_dmem` is 32-bit RW `OUTSTANDING=1`. Exposes a `PROBE_LEN`-word D-mem window for VCD tracing. Peri bus through `axi4_lite_xbar_3`→uart+timer+msip. **UART RX stimulus**: `uart_rxd_i` is a real port, double-flopped exactly like `top_module` (board parity — the sim used to drive `rxd_i` raw, so the board's synchronizer was never simulated). **UART TX monitor**: every byte pushed into the TX FIFO is logged to `sim/sim_uart_tx.txt` — that is how you read a serial program's output. `UART_CLK_HZ`/`UART_BAUD` default to a fast 5 clocks per bit; pass `-GUART_CLK_HZ=25000000 -GUART_BAUD=115200` for the board's real 217.
- `sim/sim_main.cpp` — drives clk/rst, logs fetch/decode/execute-retire+writeback via internal taps. **UART RX driver**: `UART_RX="2000\r"` types that string as real 8N1 frames (C escapes decoded); `UART_RX_PACED=0` ships frames back-to-back instead of waiting for RX-FIFO room — what a terminal does with a pasted line, and the case the RX FIFO exists to survive. `UART_BIT_CYCLES=217` matches a board-accurate build; `NO_VCD=1` skips the dump (a board-accurate run is millions of cycles = multi-GB VCD). Stops on park detection (8 identical retires) or `MAX_CYC` (default 4000). `STAP()` prints a stall breakdown. **Stall-cause histogram**: every run also partitions the cycles that retired nothing by cause (`load-wait`/`lsu-launch`/`lsu-capture`/`div`/`csr`/`wfi`/`rvc-hold`/`rvc-span`/`redirect`/`imem-starve`/`decode-bubble`), read from the stages' own stall signals via `XTAP`/`DTAP`/`FTAP`, plus event counters (mem-ops, loads, div, redirects). Read that, not the `stalled N/M (X%)` line: `dbg_stall_o = dec_stall | ex_stall` does **not** see a fetch bubble, so removing fetch bubbles lowers the cycle count and raises that percentage at once — it is not comparable across designs or across programs. The same data is also printed as a **CPI decomposition** (each bucket divided by retires instead of by cycles) — that is the form that compares, since a percentage of the run moves when any other bucket changes while cycles-per-instruction stands alone; the terms are additive, so 1.0 + the buckets *is* the CPI. Taxonomy and the measured tables are in `sim/README.md`. Checks the WFI-halt invariant every run.
- `sim/imem.hex` + `sim/dmem.hex` — hand-crafted Harvard oracle: RAW hazards, LSU round-trip + load-use, byte/halfword sign/zero extend.
- `sim/Makefile` — `make run` (default oracle); `RUN_ARGS="+IINIT=... +DINIT=..."` for C programs.
- `sim/sw/` — firmware tree for the Harvard sim. `common/` holds the shared assets (`uart.h`, `start.S`, `link.ld`, `bin2hex.py`, `ee_printf.c` — the minimal integer UART `printf` the two vendored-workload harnesses link) plus `sw_build.mk`, a parameterised build include every harness pulls from (set `ARCH` / `C_SRCS` / `S_SRCS` / `LINK_LD` / `DMEM_BASE` / `IMEM_PAD_WORDS` / `EXTRA_CFLAGS` / `EXTRA_LDFLAGS` / `EXTRA_LDLIBS`, then `include` it; `EXTRA_LDFLAGS` goes before the objects and `EXTRA_LDLIBS` after, which is where a `-l` has to be to resolve; `S_SRCS` alongside `C_SRCS` means library assembly, and only on its own does it mean a program with its own `_start`). `quicksort/`, `coremark/` and `dhrystone/` are the benchmarks; `isa/`, `intr/`, `peri/` hold the oracles. `sw_build.mk` stamps the varying flags into `build/.config` and makes the objects depend on it, so a config change (`PRINT_ARRAY`, `COSIM`) rebuilds instead of leaving the other variant's objects in place with newer timestamps than their sources. `make -C sim/sw` builds everything; `make -C sim/sw/isa` (or `intr`/`peri`) one group. **Toolchain**: buildroot glibc `riscv32-buildroot-linux-gnu` at `~/_toolchains/riscv32-ilp32d--glibc--stable-2025.08-1` (gcc 14.3.0); override `RISCV_PREFIX`. `-march=rv32imac -mabi=ilp32 -nostdlib -ffreestanding -medlow`, plus **`-no-pie -Wl,-N -fno-pie`** — that glibc toolchain emits a PT_PHDR segment the flat `link.ld` does not cover and defaults to PIE, which turns `la sym` into a GOT load and breaks the Harvard split (it needs medlow absolute `lui`+`addi`). Default program `quicksort/main.c`: recursive quicksort over a **256-word** LCG-filled array (same sequence on Spike and RTL, pseudo-random so recursion stays near log2(N) deep), returns `0x600D`/`0xBAD`; `PRINT_ARRAY=0` compiles the printing out for the co-sim.

```bash
cd sim && make run                    # Harvard oracle
make sw-run                           # build C prog + run (from repo root)
```
Build artefacts gitignored.

### Test harnesses
Firmware oracles write `0x600D`/`0xBAD` to a known D-mem word unless noted. Build each in its own directory, then run from `sim/`:
```bash
make run RUN_ARGS="+IINIT=sw/<group>/<name>/build/imem.hex +DINIT=sw/<group>/<name>/build/dmem.hex"
```

- **`sim/hw/native_mem_tb/`** — BFM driving `native_ram`'s flat ports (32-bit, `OUTSTANDING=1`, both a RO and a RW instance): RVALID registered & held until RREADY, byte-strobed partial writes, back-to-back writes, single-outstanding, posted-store commit at launch-accept, read-only ignoring writes. → 37 checks, 0 failures.
- **`sim/hw/native_ram64_tb/`** — BFM driving the 64-bit / `OUTSTANDING=2` / RO config of `native_ram` (the widened I-mem port shape): two back-to-back reads both accepted, a third blocked until the skid frees, RVALID held under delayed RREADY, 64-bit read data lane-correct. → 23 checks, 0 failures.
- **`sim/hw/ram_tb/`** — BFM driving `axi4_lite_ram` (peri-side only now): registered BVALID held under delayed BREADY, AW/W ordering, byte strobes, back-to-back writes, single-outstanding, RVALID held under delayed RREADY.
- **`sim/hw/uart_tb/`** — BFM driving `axi4_lite_uart`, with an 8N1 decoder on `txd_o` and a frame driver on `rxd_i`. Checks: N queued TX bytes ship in order with no polling between; a write to a full FIFO is *held* and still ships in order; an RX burst inside the depth is retained with no overrun; one frame past the depth is dropped and latches RX_OVERRUN while queued bytes survive; reading an empty RX FIFO pops nothing; IRQ is level-sensitive and gated by CTRL. → "146 checks, 0 failures".
- **`sim/cosim/quicksort/`** — the same C ELF on Spike (`--log-commits`, built by `build_spike.sh`) and on the RTL; `cosim_diff.py` diffs per-retire pc + register write. Harvard needs `.data` at a non-zero VMA (`DMEM ORIGIN=0x2000`) so Spike's unified space holds `.text`@0 / `.data`@0x2000 disjoint. `SPIKE_MEM` mirrors the real memory sizes, so an access the hardware would silently alias makes Spike trap instead. `make cosim` → "PASS -- matched N retires". `build_spike.sh` relocates two fixed Spike devices (debug module 0x0→0x100000, boot ROM `DEFAULT_RSTVEC` 0x1000→0x200000 — 4 KiB no `-m` region may overlap, which used to cap a co-simulated `.text` at 4 KiB) and records the patch set in `.patch-stamp` so a change forces a rebuild.
- **`sim/sw/intr/trap/`** — `trap_test.S`, standalone M-mode: ecall / load-misaligned / illegal / MSIP+WFI, self-checking @0x2000. **`sim/cosim/ecall/`** co-simulates a sync trap (illegal instr `.word 0x0000007f`) → "PASS -- matched 17 retires"; ecall itself is not Spike-comparable (Spike hijacks M-mode ecall as htif exit).
- **`sim/sw/intr/wfi_trap/`** — regression for a WFI-halt deadlock: `wfi_halt_q` must clear on `int_pending`, not `take_interrupt` (which loses priority to a sync trap) — otherwise a faulting instr behind `wfi` left the halt flag set, trap entry cleared `mstatus.MIE`, `int_pending` dropped, and the pipe froze unrecoverably. Arms `mtimecmp=400`, fills the pipe with a 32-cycle `div`, then `wfi` + an illegal instr; the illegal trap wins arbitration (@0x2040), then the timer interrupt (@0x2044). `gen_hex.py` hand-encodes it — no toolchain.
- **`sim/sw/intr/timer/`** — arms `mtimecmp=200`, `wfi`s, wakes on MTIP, handler stores marker=7 @0x2040 and clears MTIP. Not Spike-comparable (no CLINT slave).
- **`sim/sw/peri/uart_echo/`** — the only end-to-end test of MEIP (`uart_irq_o`→`meip_i`→`mip.MEIP`→`trap_unit`, plus the `wfi` wake on an external interrupt). Echoes 4 bytes by polling, then enables `CTRL.RX_IE` + `mie.MEIE` + `mstatus.MIE` and echoes 4 more from an `interrupt("machine")` handler. Result @**0x3000** (not 0x2000 — `.rodata` is linked there). Doubles as the bring-up program: type 8 characters, phase 1 says whether bytes reach the CPU, phase 2 whether the interrupt path works. `UART_RX='abcdefgh' make run RUN_ARGS=...` → "ECHO / abcd / IRQ / efgh / GOOD".
- **`sim/sw/isa/rvc_scramble/`** — per-scramble-bit decode oracle for `c_expand()`: every RVC scrambled-immediate form (c.addi4spn/c.addi16sp/c.li/c.addi/c.lui/c.andi/c.srli/c.srai/c.lw/c.sw/c.lwsp/c.swsp/c.j/c.jal/c.beqz/c.bnez) with each immediate bit set in isolation, a `mtvec` handler turning a mis-decoded jump into FAIL rather than a hang. The guard for the scramble-bit class of bugs — cosims and the other oracles never toggle those bits. It caught the c.addi4spn `nz[3]`/`nz[2]` swap that a manual review had dismissed.
- **`sim/sw/isa/span_target/`** — same-cycle target-span stitch oracle for `target_span_complete`: branches (`c.j`) to a 32-bit (or compressed) instr at offset 2 / 6 of an 8-byte-aligned fetch word and self-checks the result; a `mtvec` handler catches a mis-stitched jump/illegal as FAIL. No cosim/oracle placed a 32-bit instr at a 2-byte-aligned branch target, so the stitch path was unguarded. Covers offset-2 (always buffered → `target_span_complete`, 0 bubble), offset-6 (`target_span_wait` then `span_complete`), and compressed-target controls (offset 2/6, the unchanged `target_upper && !target_span` path). Pass = park @ `park` (not `bad`/`th_park`), probe 0x800 = 0x600D.
- **`sim/sw/isa/bp_pred/`** — branch-predictor correctness oracle (2026-08-28): 9 cases exercising every predictor path (always-taken / always-NT / loop-exit mispredict / alternating / correlated / RVC `c.bnez` / nested JAL+JALR call-return for RAS push/pop / mispredict with 2 fetch reads outstanding / ecall-trap-vs-predicted-branch priority), each self-checking a known result with `CHECK`. Guards the invariant a predictor must never alter: a prediction may mispredict freely but must never change architectural state — a flush/hold-buffer bug that lets a wrong-path instr retire corrupts a register and fails a `CHECK`. A `mtvec` handler resumes the one expected case-9 ecall and fails any stray trap. It caught the hold-buffer-survives-predicted-redirect bug (the `pred_redirect_fire` hold-clear). Pass = park @ `park`, probe 0x800 = 0x600D. Pure assembly, own `_start`.
- **`sim/sw/isa/ifault/`** — jumps to 0x100000 (far outside the I-mem) and checks that exactly one trap arrived with `mcause=1` and `mtval` = the address jumped to. The handler does **not** `mret` to `mepc` — that address is still unfetchable — it rewrites `mepc`, which is what a real handler must do.
- **`sim/sw/isa/isa_probe/`** — board bring-up probe reporting through fixed strings and a bit-dump built only from register-register `AND` and mask doubling, never through the hex printer or any instruction under test, because the printer was the thing lying. Covers `c.andi` (hand-encoded halfwords) against 32-bit `andi`, the shifts, `AND`/`OR`, a byte load at each lane, and `lw` / `lbu` at constant offsets / `lbu` at a **computed** address / `lhu` / byte stores read back. The constant-vs-computed split is what isolated the load byte-select bug — a `const` read at a constant index is folded at compile time and proves nothing. `make UART_TX_PACED=1`.

`UART_TX_PACED=1` (in `sim/sw/common/uart.h`) replaces the `TX_READY` poll with a delay longer than a frame, so only one byte is ever in flight. Diagnostic only: it separates "the FIFO filled" from "the poll never returned" when a board goes quiet mid-line.

### CoreMark (`sim/sw/coremark/`, co-sim `sim/cosim/coremark/`)
`eembc/` is upstream EEMBC CoreMark **vendored verbatim** — byte-identical to github.com/eembc/coremark at commit 1f483d5 (Apache-2.0). Provenance and hashes in `eembc/UPSTREAM.md`; `make verify-eembc` runs before anything compiles and fails the build on an edit, because a score from a modified workload is not comparable with anyone else's. It replaced an older fork (taken from the cva6 tree) that differed in three ways: an **extra untimed `iterate()` before `start_time()`** which ran the whole benchmark twice — a 2000-iteration board run reported a correct 30.23 s for its timed half while the board was busy ~60 s, and since `iterate()` zeroes the CRC accumulators on entry the duplicate left no trace in the results, so the wall clock was the only symptom and it reads exactly like a broken cycle counter; a hand-added CoreMark/MHz line that overflowed 32-bit at any reportable iteration count; and an uninitialised `list_data info` upstream had already fixed.

Everything the port needs lives outside `eembc/`: `MEM_METHOD=MEM_STATIC` (no malloc; a 2 KiB stack block would eat the stack), `HAS_FLOAT=0`, `HAS_STDIO=0`, timing from `mcycle`, a small integer `printf` over the UART (`ee_printf.c`, `\n`→CR+LF or a terminal staircases the report), local `memcpy`/`memset`, a banner before the run (otherwise silent for ~31 s and the board looks hung), and a **port summary after CoreMark's own output** — upstream prints duration and rate as `%d` when `HAS_FLOAT=0` and no CoreMark/MHz at all without an FPU, so the port prints ticks, cycles/iteration, seconds, iterations/s and CoreMark/MHz with two decimals. Build flags: **`-O3 -ffunction-sections -fdata-sections -mstrict-align -mbranch-cost=10 -ffp-contract=off -mno-fdiv` + `-Wl,--gc-sections`**, the set comparable published rv32 ports quote; `-mstrict-align` is not optional, the core traps on misaligned rather than fixing up. 11.1 KiB `.text` (of 16) / 4.0 KiB D-mem data. `TOTAL_DATA_SIZE=6000` = 6K profile; `IMEM_PAD_WORDS=2048` pads the 64-bit I-mem image for a board build (16 KiB/8 = 2048 64-bit words). `CLK_HZ` defaults to **50 000 000** — the rPLL makes 25 × 10/5 exactly; this is the frequency run at (the design re-closed PnR at 50 MHz on the fetch-rewrite path), and it is what the reported seconds / iterations-per-second are computed against (CoreMark/MHz comes from `mcycle` ticks alone and is frequency-independent).

**Score on verbatim upstream (after the 64-bit/2-outstanding fetch rewrite): 531025 cycles/iteration = 1.88 CoreMark/MHz, IPC 0.561** (`ITERATIONS=1`, 2K profile, -O3; 339436 instr / 605491 sim cyc). Before the rewrite the single-iteration run read 622006 cycles / 1.63 / IPC ~0.44, so the fetch path was the bottleneck the rewrite removed — a ~15% cycle reduction and ~+0.12 IPC. A 50-iteration run smooths the data-dependent work to a similar figure (the pre-rewrite 50-iter average was 615416 / 1.62). CRCs `list 0xe714`/`matrix 0x1fd7`/`state 0x8e3a` = the official 2K performance-seed values (unchanged — the rewrite is a fetch-path change, not a workload change); a 2000-iteration run gives `crcfinal` 0x4983, the value other cores publish. The **1.65 measured earlier is retired**: it came from the fork, whose untimed warm-up left the data structures in a cheaper state for the timed pass. Rules-valid `ITERATIONS` at 50 MHz: **814..6979** (≥10 s, under the 32-bit `mcycle` wrap; there is no `mcycleh` — the 10-s minimum scales with the clock, the wrap maximum is cycle-based). A shorter run ends in upstream's own "ERROR! Must execute for at least 10 secs" and "Errors detected" — that is the run rule, not a failure; the four CRC lines are what say the benchmark computed correctly. ### Dhrystone (`sim/sw/dhrystone/`)
`sifive/` is SiFive's `benchmark-dhrystone` tree **vendored verbatim** — byte-identical to github.com/sifive/benchmark-dhrystone at commit 0ddff53. Provenance and hashes in `sifive/UPSTREAM.md`; `make verify-sifive` runs before anything compiles and fails the build on an edit. That guard matters more here than for CoreMark: **`strcpy` and `strcmp` are called from inside the measurement loop**, so the loop body *is* the benchmark, which is also why upstream ships its own `strcmp.S` rather than trusting the target's library. Dhrystone 2.1 is 1988 C (K&R parameter lists, implicit-int `main`), so the dialect is pinned — `-std=gnu17`, not the compiler default: gcc 15 defaults to C23 where K&R definitions are gone, and gcc 14 made `-Wimplicit-int` / `-Wimplicit-function-declaration` errors (both downgraded, in both spellings).

Everything the port needs lives outside `sifive/`: `dhry_portme.c` (the real `main()`, `time()` over `mcycle`, a bump allocator for the two records Dhrystone mallocs, a word-at-a-time `strcpy`, `memcpy`/`memset`, banner, summary), `stdio.h` (a freestanding shadow of the toolchain's — `dhry.h` ends with `#include <stdio.h>` "for strcpy, strcmp", and against a *linux glibc* cross-compiler that resolves to a full hosted header set), `dhry_link.ld`, and `common/ee_printf.c`. **Two `-D`s stand in for edits upstream must not receive**: `-Dmain=dhry_main`, scoped to `dhry_1.o` alone so the port can print after the report (`start.S` calls `main` once then spins; Dhrystone has no `portable_fini()`) — putting it in `EXTRA_CFLAGS` instead also rewrites `start.S`'s `call main`, since gcc preprocesses `.S` too, and the only symptom is a missing banner and summary around an otherwise perfect report; and `-Dfloat=long`, because `dhry_1.c`'s seven `float` uses are all in the report block after the timer stops, upstream already prints both results through an `(int)` cast, and there is no FPU while the toolchain's libgcc is built `ilp32d` — `__floatsisf`/`__divsf3`/`__fixsfsi` do not exist to link against. Build flags otherwise `-O3 -mstrict-align -fno-common -falign-functions=4 -DTIME -DNOENUM` (the last two upstream's own). 5.8 KiB `.text` (of 16) / 1.9 KiB `.rodata` + 10.3 KiB `.bss`.

**`Arr_2_Glob` is `int [50][50]` = 10 000 bytes of `.bss`**, which does not fit in the 8 KiB `common/link.ld` leaves above 0x2000. The array is the benchmark, so the memory moved: `dhry_link.ld` starts DMEM at 0 and takes the whole 16 KiB (`DMEM_BASE := 0x0`), with a linker `ASSERT` that `.bss` stays 1 KiB clear of `sp = 0x4000` — an overlap there is silent at runtime and shows up only as the final-value checks disagreeing. The cost is the co-sim: `.text` must also be at 0 (the core boots there) and Spike is one address space, so **Dhrystone is not co-simulated**, unlike quicksort and CoreMark.

**Score: 686 cycles/iteration = 0.82 DMIPS/MHz, 72886 Dhrystones/s at 50 MHz** (`DHRY_ITERS=2000`, -O3; 1372041 ticks, IPC 0.518 over the whole program). All 22 of Dhrystone's own `should be:` final values match. DMIPS/MHz is 1e6/(cycles-per-iteration × 1757) — 1757 Dhrystones/s is the VAX 11/780's rate and the definition of 1 DMIPS — so like CoreMark/MHz it comes from cycles alone and is frequency-independent. **The number is `strcpy`-sensitive by construction**: a plain byte-loop `strcpy` measures 891 cycles/iteration = 0.63 DMIPS/MHz on the same core with nothing else changed. The port ships the word-at-a-time version (aligned-only word loop, byte tail, the same alignment test `strcmp.S` makes — `-mstrict-align` is load-bearing, the core traps rather than fixing up) because published scores are quoted against newlib or equivalent. A run under 2 s ends in upstream's own "Measured time too small to obtain meaningful results" — Dhrystone's run rule (`Too_Small_Time`), needing `DHRY_ITERS` ≈ 145772 at 50 MHz, with the 32-bit `mcycle` capping the other end at ~6.26 M; the port summary is computed from cycles and has no minimum.

## Architecture

Built bottom-up. Every RTL file: `import rv32_pkg::*;` + `` `resetall `` / `` `default_nettype none `` / `` `timescale 1ns/1ps ``.

### Naming
Ports `_i`/`_o`. Flops `_q`, next-state comb `_d`. Instances `u_*`. Stage debug taps `fe_`/`de_`/`ex_`, internal only (`dbg_stall_o` is the sole exported one).

### Files
- **`rv32_pkg.sv`** — `XLEN=32`; `mem_req_t`/`mem_rsp_t`/`ifetch_req_t`/`ifetch_rsp_t`. `PERI_ADDR_BIT`=28; peri windows `UART_BASE`=0x1000_0000/4K, `MTIMER_BASE`=0x1000_1000/8K, `MSIP_PERI_ADDR`=0x1000_3000/4K. Decode types: opcodes (incl `OPC_AMO`), `alu_op_t` (incl `ALU_LX`), `wb_src_t` (incl `WB_CSR`), `csr_op_t`/`csr_addr_t`, `sys_op_t`, `MCAUSE_*`, `MSTATUS_*`, `MTVEC_DIRECT/VECTORED`. Packed `de_t` D/E struct. **Branch-predictor types** (2026-08-28): `pred_source_t` enum `{PRED_NONE,PRED_DIRECT,PRED_PHT,PRED_RAS}`; `bp_lookup_req_t`/`bp_lookup_rsp_t`/`bp_train_t` (split by direction like `mem_req_t`/`mem_rsp_t`); `de_t` carries `pred_valid`/`pred_taken`/`pred_target[32]`/`pred_source[2]`/`pred_pht_index[6]` (~42 bits) so the prediction rides the D/E register to execute, which compares it against the resolved outcome.
- **`fetch_stage.sv`** — 64-bit, 2-outstanding fetch with a depth-8 (32-bit-word) instruction buffer. One 64-bit I-mem access delivers two 32-bit words; the response is split into PC-stamped 32-bit buffer entries (0, 1, or 2 pushes/cycle) and decode consumes the head exactly as it consumed the old F/D word — `fe_instr_o`/`fe_pc_o`/`fe_valid_o`/`fe_fault_o` are unchanged in width and semantics, so **decode is unmodified**. `pc_q` advances by 8; `req_pc_q` holds the real (possibly 2-aligned) PC of the in-flight read. **Split PC stamp**: the half containing the fetch PC is always stamped `req_pc_q` (carries unaligned `[1:0]` for the low half, `[1]` for the high half) so decode's `fe_pc[1]` selects the right halfword — stamping the high half with `(req_pc_q & ~7)+4` instead clears bit[1] and made a `jalr` to 0xee land at 0xec (fixed 2026-08-26; the in-place `sim/imem.hex` oracle never redirected into the high half so it was latent). `inflight_q[1:0]` tracks outstanding reads (cap 2, backed by the I-mem's depth-2 response skid); a redirect sets `pc_q=branch_addr_i`, kills the buffer, and `draining_q` discards the ≤2 stale responses. Buffer-room gating is overflow-safe: `available = 8 - count - 2*inflight`, bus issue needs `available>=2 & inflight<2`, fault push (1 word, no read) needs `available>=1`. `stall_i` (decode) / `branch_valid_i`+`branch_addr_i` (execute redirect incl. trap/mret/interrupt) / **`pred_valid_i`+`pred_addr_i`** (decode's predicted-taken redirect, 2026-08-28 — priority-merged *below* the execute redirect: `pred_redirect = pred_valid_i & ~branch_valid_i`, routed through the same kill path as `branch_valid_i` so the predicted-taken branch kills the buffer + arms the drain one cycle earlier than an execute redirect). **`IMEM_ADDR_W` range check**: a PC outside the implemented I-mem issues no bus request and instead enqueues a fault entry. The parameter is forwarded from the top level and must match the instantiated `native_ram`.
- **`decode_stage.sv`** — RV32I+M+C+Zilx+Zicsr. Expand-then-decode (`c_expand()` RVC→32-bit, one decoder), hold buffer for the upper compressed half. RVC funct3=100 group (c.srli/srai/andi CB + c.sub/xor/or/and CA): selector = `c[11:10]` (00 srli / 01 srai / 10 andi / 11 arith), arith sub-group = `c[6:5]` (00 sub / 01 xor / 10 or / 11 and); rd=rs1=`crs1`={2'b01,c[9:7]}, rs2=`crs2`={2'b01,c[4:2]}; `c[12]` is shamt[5]/imm[5], **NOT a selector**. That group and three RVC immediate-scramble forms (c.addi4spn, c.addi16sp, c.jal/c.j) all decoded wrong until 2026-08-25 — latent because no cosim or oracle emits those bit patterns; now guarded by `sw/isa/rvc_scramble` ([[c-expand-rvc-immediate-scramble-bugs]]). Zilx (`OPC_AMO` funct5 10010/11010; 11110 illegal) swaps rs1/rs2, computes `mem_shamt`. Zicsr (`OPC_SYSTEM` funct3≠0) sets csr_op/csr_wren/csr_addr, `wb_src=WB_CSR`. funct3=0: ecall/ebreak/mret/wfi → `sys_op`; `OPC_MISC_MEM` fence/fence.i → `sys_op` (legal nop); unknown → `dec_illegal=1`. **`fe_fault_i`** outranks every source: no word exists to decode, so it emits a precise trap with `MCAUSE_INSTR_ACC` and `mtval` = the unfetchable PC, dropping any stashed half. `stall_o` = hold-term | execute stall | WFI-halt — **no RAW term**. **Forwarding**: `fwd_rs1`/`fwd_rs2` inject `ex_wb_data_i` into the D/E operands when `ex_wb_en_i` & addr matches — distance-1 RAW, zero bubble. **Branch prediction** (2026-08-28, `BP_EN` param, default 1): classifies the control-flow instr at the buffer head (cond / JAL / JALR-call / JALR-return via `branch_type`+`rd`+`rs1`), computes the direct `src_pc + imm` target (a 32-bit adder off the regfile/forward path — `src_pc` is a flop, `imm` is decoded parallel to `c_expand`), queries the predictor (`bp_lookup_o`→`bp_lookup_i`: PHT direction for cond, RAS top for returns), and stamps `pred_*` into `de_d`. A predicted-taken instr asserts `pred_redirect_valid_o`/`pred_redirect_addr_o` to fetch (one cycle earlier than an execute redirect). **The predictor depends only on PC + GHR, never on register data** — it stays off the `regfile → forward → branch` critical path. **Hold-buffer flush fix**: a predicted-taken redirect must also clear the RVC hold buffer (`pred_redirect_fire` is a hold-clear condition alongside `flush_i`) — without it the half sitting after a predicted-taken branch was re-stashed by `span_complete` the same cycle and a wrong-path fall-through instr retired (caught by the quicksort cosim at retire 94; guarded by `sw/isa/bp_pred`). `BP_EN=0` zeroes `de_d.pred_*` and emits no predicted redirect → execute resolves every control-flow instr with a taken redirect exactly as before the predictor.
- **`reg_file.sv`** — 32×32 BSRAM, async read×2 / sync write×1, x0 hardwired. Confirmed NOT the Fmax limiter. No runtime reset (single write port); sim zero-inits under `` `ifdef VERILATOR ``, HW relies on write-before-read.
- **`csr_regfile.sv`** — 11-entry Zicsr M-mode subset. **Registered read** (decode presents the addr, data lands next cycle) + sync write (execute RMW); the read used to be asynchronous and made `de_q.csr_addr → fetch pc_q` the critical path. Execute holds a CSR op one extra cycle (`EX_CSR_WAIT`) at a measured cost of **zero cycles** — at ~1.8 cycles per instruction (post-fetch-rewrite) it sits inside the fetch bubble already there. Consequence: `mcycle`/`minstret` read back the previous cycle's value. FF+LUT mux, not BSRAM. CSRs reset to architected values (`misa`=0x40002105 RO); unimplemented addrs read 0 / ignore writes. Consumes CSR taps + execute triggers (sync_trap/mret/take_interrupt, cause/tval/pc); produces the fetch redirect (mtvec BASE, BASE+4*code vectored, or mepc) + the CSR trap-write bundle. `int_pending_o = mstatus.MIE & (MEIP&MEIE | MSIP&MSIE | MTIP&MTIE)`, `int_cause_o` picks MEI>MSI>MTI. Entry MPIE←MIE/MIE←0/MPP←11; mret MIE←MPIE/MPIE←1/MPP←11.

Before this the request came straight off `alu_result`: it closed on paper and failed on silicon. Costs one cycle per access (quicksort IPC 0.500 → 0.469), bought +4.8 ns, moved the critical path off the LSU. The mirror change on the return path (latch `rdata`, align and retire next cycle) was measured at IPC 0.436 and **not kept** — reach for it only if a symptom points at `rdata → shift → sign-extend → writeback mux → forward mux`. **Posted store** retires on the launch accept; loads wait in `EX_MEM_WAIT` until `rvalid`. LSU steers `addr[PERI_ADDR_BIT]`. CSR: `csr_new` = RW:src / RS:`old|src` / RC:`old&~src`. Load alignment: shift by **`mem_addr_q[1:0]`**, the registered address from the capture cycle — **never `alu_result[1:0]`**, which is a cycle stale and was the 2026-08-25 silicon bug (a load addressed by a distance-1 forward selected byte 0; invisible in simulation — see the rule in *Hazard resolution*). A `` `ifdef VERILATOR `` assertion checks the premise the flop relies on. **Traps**: `freeze = stall_i | wfi_stall`; sync traps fire in `EX_IDLE` (never launch on misaligned), `sync_trap_req` exports to the trap unit and wb/mem/csr/branch are suppressed; `mret` retires + redirects to mepc; `take_interrupt` suppresses the next instr at the retire boundary or on WFI wake (mepc=wfi+size); WFI retires once then halts until `int_pending`. A trapping instr is not retired. **Branch prediction resolve** (2026-08-28): execute is the golden resolver — `branch_taken`/`branch_target` are computed exactly as before, then compared against the carried `de_i.pred_*`. `mispredict = (pred_t & ~taken) | (pred_t & taken & wrong target) | (~pred_t & taken)`; a *correct* taken prediction produces **no execute redirect** (the win), a mispredict redirects to `resolved_target` (actual taken) or `pc_link` (pred-taken actual-NT). `branch_valid_o = mispredict | trap_redirect_req` (was `branch_redirect_req | trap_redirect_req`); priority sync trap/interrupt/mret > mispredict > decode prediction > sequential. Training (`bp_train_o`) fires at resolve on every control-flow instr (mispredicted or not): PHT saturating update indexed by the **GHR snapshot** `de_i.pred_pht_index` (so the update uses the history the branch was predicted with, even if an older branch shifted the GHR in between), GHR shift, and RAS push (call) / pop (return). In-order single-issue means squashed wrong-path instr never resolve → never train, so the predictor is not contaminated by speculation. Exports `ex_wb_en_o`/`ex_wb_addr_o`/`ex_wb_data_o` to decode same-cycle.

### Pipeline behaviour
**Fetch**: 64-bit, 2-outstanding, depth-8 (32-bit-word) instruction buffer. One access delivers two 32-bit words; 2 outstanding keeps the BSRAM issuing through decode stalls (DIV/REM, mem-wait) so the response round-trip stops being a bubble — the dominant pre-rewrite bottleneck at ~2.2 cyc/instr. Steady state ~1.8 cyc/instr (CoreMark IPC 0.563 vs ~0.44 before). Harvard, so fetch owns the I-mem port uncontended. A redirect kills the buffer and the ≤2 in-flight reads (drain FSM), and sets a new `pc_q`. The 64-bit response is split into PC-stamped 32-bit buffer entries; the head feeds decode exactly as the old F/D word did. Decode now also reads the buffer's `head+1` word (`fe_next_instr_o`/`fe_next_valid_o`=count≥2) for the same-cycle target-span stitch, and drives `fe_pop2_o` to pop 2 on that stitch.
**Decode** source priority: spanning stitch > compressed hold > odd-half target > fresh low half. RVC spanning: a 32-bit instr split across a word boundary stashes the low half and stitches it with the next word's upper half. **Branch-target span (offset 2/6) is zero-bubble** (`target_span_complete`: stitches `head[31:16]+head+1[15:0]` the cycle the target word is seen, pops 2, re-stashes `head+1[31:16]`; offset-6 falls back to `target_span_wait` when the next fetch has not landed). **Sequential span remains 1 bubble** (`span_wait`, reached by fall-through where offset 0 is a real compressed instr — removing it is dual-issue, deferred). `decoded_valid` excludes wait states. Deferred to execute as traps: unknown opcode, `OPC_AMO` funct5 11110 / sfence.vma (no VM). Legal and retiring in execute: ecall/ebreak/mret/wfi/fence/fence.i. Zicsr decodes and retires fully.
**Branch prediction** (2026-08-28): decode predicts every control-flow instr it classifies — JAL/c.j/c.jal and conditional branches get a direct `pc+imm` target (no BTB, zero cold-start target mispredicts), conditional *direction* comes from the gshare PHT, and JALR *returns* (rs1∈{x1,x5}, rd=x0) get the RAS top; other JALR (indirect) is unpredicted. A predicted-taken instr redirects fetch one cycle earlier than execute would have; execute stays the golden resolver, training at resolve only. The net on the no-retire budget: redirect CPI drops ~3× (CoreMark 0.383→0.102, Dhrystone 0.348→0.112, quicksort 0.420→0.167) but a *new* `imem-starve`/`other` ~0.21 CPI appears with `BP_EN=1` — the kill+refill bubble on every *correct* predicted-taken branch (charged to `imem-starve` instead of `redirect`, since no mispredict fires) — so the gross redirect saving (~0.28) nets to ~+0.06 CPI after that refill cost. Predictor accuracy 74/84/79% (qs/cm/dh), RAS hit 98–100%. The architectural retire stream is identical with the predictor on or off (verified — quicksort retires 29675 both ways; the printing benchmarks retire slightly more with BP on only because their UART `TX_READY` poll loop is a busy-wait whose iteration count scales with IPC).

### Hazard resolution (execute→decode forwarding)
`fwd_rs1`/`fwd_rs2` fire when execute retires a writeback to a register the decoding instr reads (x0 excluded): inject `ex_wb_data_i` into D/E operands instead of the stale async regfile read — zero bubble. Covers ALU-RAW, div-done-then-use, branch-on-dependent, load-use (the load's `EX_MEM_WAIT` holds the consumer in decode via `stall_i`; the load's `wb_en` pulse on `rvalid` drives the forward). Distance-2+ hazards: harmless, the async regfile read returns the already-committed value. Legacy `raw_haz` bubble interlock **disabled**.

**Rule the forward path imposes on the rest of the datapath** (largely defused by the LSU register stage, but still the rule to think with): a combinational value derived from the D/E operands — anything downstream of `alu_result` — may be consumed **only in the cycle it is produced**; anything a later cycle needs must be latched when produced. The operands can come from the bypass, so such a value sits at the end of the critical path: simulation settles it regardless of depth, silicon does not. This is how the load byte-select bug got in, and it is the first thing to check when hardware and simulation disagree. Audited today: `store_wstrb` / `store_wdata` / `mem_req.addr`, `sync_tval`, the trap bundle payload.

**Known limitations:**
- Forward path is distance-1 only (single in-order retire slot); correct because execute retires ≤1 writeback/cycle in order.
- M-mode only (no S/U, no medeleg/mideleg, no PMP). **Instruction access fault implemented** (fetch outside `IMEM_ADDR_W`); instruction-address-misaligned is deliberately absent — with the C extension IALIGN=16, `jalr` clears bit 0 by definition and every branch offset is even, so an odd instruction address cannot arise. Cross-word sub-word accesses unhandled. Timer + external interrupt sourced; MEIP is a single ORed level (only UART today, no PLIC — ISR must poll to find source). Unimplemented CSR addrs still silently read 0/ignore writes (no illegal-instruction trap).
- WFI halts forever if no enabled interrupt ever arrives (legal). `fence.i`/`fence` are nops (Harvard has no D→I write path — no self-modifying code).
- Harvard: I-mem holds `.text`/`.text.init` only; `.rodata`/`.data`/`.bss`/stack live in D-mem. Three linker/startup rules learned the hard way: **every `link.ld` must collect the small-data sections** (`.srodata*`/`.sdata*`/`.sbss*`) into `.rodata`/`.data`/`.bss`, because gcc puts any object up to `-msmall-data-limit` (8 bytes) there and the image is extracted with `objcopy -j .rodata -j .data` — an uncollected `.srodata` never reaches the D-mem hex, so a 4-byte `const` reads 0 at runtime while the same constant folded at compile time reads correctly. **`start.S` zeroes `.bss`** and zeroes `a0`/`a1` before `call main` (nothing else sets them, so CoreMark's `main(int, char **)` would read power-up register contents). **`sp = 0x4000`**, the top of the 16 KiB D-mem: it decodes only `ADDR_W` bits, so a stack pointer above the top aliases silently into the data it is meant to sit clear of. `.data` at DMEM ORIGIN 0x2000 keeps the Spike co-sim disjoint; requires `medlow` absolute addressing.

### Plan (2026-08-26, in order)
Done and off the list: Harvard split, LSU, forwarding, trap machinery, all three interrupt sources, UART with FIFOs, silicon bring-up, 40 MHz closure (pre-rewrite design), `.bss` clearing, instruction access fault, CoreMark, **64-bit/2-outstanding fetch + instruction buffer (item 1, 2026-08-26)**, **50 MHz PnR re-closure on the fetch-rewrite + target-span design (2026-08-27)**, **branch predictor — gshare PHT + GHR + RAS, prediction-at-decode, execute-as-judge, `BP_EN` A/B (2026-08-28)**: sim-verified (all oracles/cosims/TBs), +2–4% IPC measured, guarded by `sw/isa/bp_pred`; **50 MHz re-closure with the predictor is the one open item it left** (currently 47.4 MHz).

Items 1 and 2 are one project in two steps: widen and pipeline the fetch path first, then put a cache behind it. That order is deliberate — a cache does not fix the fetch bottleneck, and measuring both changes at once makes neither interpretable.

1. **Pipelined + 64-bit I-mem** — **DONE (2026-08-26).** 64-bit I-mem port + 2-outstanding fetch + depth-8 instruction buffer. IPC ~0.44 → 0.561 (CoreMark 1.63 → 1.88), the substantial IPC move this was the only remaining change to deliver. Decode unmodified (the buffer head feeds it exactly as the old F/D word). The RVC `span_wait` bubble (item 7) is NOT removed by this — it needs a wider F/D, deliberately a separate next change so the two are measured independently. (Item 7's branch-target case was later done 2026-08-27 — see item 7.) D-mem stays 32-bit. **Timing re-closed at 50 MHz (2026-08-27)** — the buffer-room comparator (`available = 8 - count - 2*inflight; >=2` feeding `wvalid`), the one new path the rewrite adds, met the 20 ns target. The 40.281 MHz closure was the pre-rewrite design; the re-closure also raised the target from 40 to 50 MHz.
1a. **Predictor: 50 MHz re-closure + hide the predicted-taken refill bubble** — the predictor (done 2026-08-28) is sim-correct and +2–4% IPC but PnR is 47.4 MHz. Two sub-goals, the first gating the second: (a) **re-close 50 MHz with `BP_EN=1`** — the limiter is congestion on `regfile → forward → de_bus.rs2_data` from the predictor's ~430 flops, *not* the prediction path itself (the adder was fixed then reverted). Levers to try, in risk order: shrink the predictor footprint (RAS 8→4 / PHT 64→32) to ease congestion; move `pred_*` out of `de_t` into a separate `pred_q` flop so `de_q` keeps its pre-predictor width/placement; only if those fail, register the prediction (1-cycle-late predict, note §11). (b) **hide the refill bubble** the predictor introduced — `imem-starve`+`other` ~0.21 CPI on CoreMark with `BP_EN=1` (was ~0 with `BP_EN=0`): the kill+refill on every *correct* predicted-taken branch. Recover it by continuing to fetch into the predicted path without a full buffer kill, or a deeper buffer / fetch-ahead. (a) alone takes CoreMark to ~2.24 CM/MHz; (a)+(b) plus a finer PHT/BTB reach ~2.5 (see the Perf bullet for the full lever analysis). `BP_EN=0` stays the 50 MHz-clean fallback until (a) lands.
2. **Cache controller over the in-package SDRAM** — the GW2AR-18C carries **8 MiB (64 Mbit) of SDRAM on a separate die in the package**, on dedicated pins, currently unused. A write-back set-associative I-cache + D-cache behind it would replace `u_imem`/`u_dmem` while keeping the native `mem_req_t`/`mem_rsp_t` interfaces, so the CPU itself does not change. The point is **capacity, not speed**: BSRAM already answers in one cycle at a 100% hit rate, so a cache can at best match it and will sometimes miss. What it buys is programs larger than 16 KiB. Use the **Gowin soft-IP SDRAM controller** rather than writing one — init sequence and refresh timing are tedious and already solved; check what clock and burst configuration it exposes before fixing the numbers below.
   Sizing (computed, not guessed):
   - **Line = 32 B, not 1 KiB.** The 1 KiB figure is the *full-page burst* (512 columns × 16 bit), one of several burst lengths and not an obligation. A 1 KiB line would cost ~520 SDRAM cycles per miss (≈260 core cycles at 50 MHz), hold a bank for 5.12 µs against a 7.8 µs tREFI while starving the other cache, and leave only ~16 lines total, so conflict thrashing would dominate. At 32 B a miss is 16 transfers + ~8 of tRCD/CL/tRP ≈ 24 SDRAM cycles ≈ 12 core cycles.
   - **8 KiB per cache** — 16 KiB of data total = 16 BSRAM blocks, the same budget the two RAMs use today, out of 46 blocks / 828 Kb.
   - 8 MiB = 23 address bits; 8 KiB / 32 B = 256 lines. **2-way**: 128 sets, offset 5 / index 7 / tag 11 + valid + dirty. **4-way**: 64 sets, index 6 / tag 12. Tag array ≈ 3.5 Kb either way — LUT-RAM or one BSRAM, negligible.
   - Start **2-way**. The new timing path is `tag BSRAM out → compare → hit → way mux → rdata`, all after a flop, so it does not touch today's `regfile → forward mux → branch` limiter, but it competes with it at 50 MHz. A 2:1 way mux is cheap; go 4-way only if the measured slack allows.
   - Confirm the SDRAM data width (16 or 32 bit) before fixing the burst counts — it halves or doubles every transfer number above.
   Things that bite later: **`fence.i` stops being a nop** — one backing store behind two caches, so YarvMon's `R` after a deposit needs a D-cache flush + I-cache invalidate, and on silicon that failure will look like a decoder bug. MMIO must stay non-cacheable (`PERI_ADDR_BIT` already decodes before the cache — keep it *before*). A dirty-line writeback buffer, so a miss on a dirty line is not writeback-then-fill serially. Critical-word-first + early restart (~5 cycles per miss at 32 B). Clock domains: the controller wants 100+ MHz while the core is at 50, so either async FIFOs — breaking today's single-domain, no-CDC property — or run it at 50 MHz and give up bandwidth a 32 B line does not need anyway; do the simple thing first. Keep the 16 KiB of BSRAM as a scratchpad/TCM in its own address window for boot, ISRs and deterministic-latency code rather than deleting it.
3. **GPIO** — direction / output / input registers plus an interrupt, same MMIO template as UART/MSIP/CLINT. Also what makes the next item meaningful.
4. **PLIC-style interrupt controller** — MEIP is one ORed level with no cause register, so with two external sources the ISR must poll to find which fired. Worth doing once GPIO exists.
5. **Illegal-CSR-access trap** — unimplemented CSR addresses read 0 and ignore writes silently, which hides a software bug rather than reporting it.
6. **Vectored-mode interrupt cosim** — `mtvec` MODE=01 is implemented but only direct mode is co-simulated.
7. **RVC spanning bubble** — **branch-target case DONE (2026-08-27).** A 32-bit instr at a 2-byte-aligned branch target (offset 2 / 6 of a fetch word) no longer costs a bubble: decode exposes the buffer's `head+1` word and stitches `head[31:16] + head+1[15:0]` in the cycle the target word is seen (`target_span_complete`), pops 2, and re-stashes `head+1[31:16]` into the existing hold buffer — zero new flops. Offset-2 targets are always buffered (the redirect's 8-byte read pushes both halves); offset-6 falls back to the old stash-and-wait (`target_span_wait`) when the next fetch has not landed, completing next cycle. Guarded by `sw/isa/span_target` (no cosim/oracle placed a 32-bit instr at a 2-byte target). **Sequential span remains 1 bubble** (`span_wait`: a 32-bit instr at offset 2 reached by fall-through, where offset 0 is a real compressed instr) — removing it is dual-issue, deliberately deferred. PnR re-closed at 50 MHz (50.017 actual; critical path is the existing `head_q → fe_instr → c_expand → regfile → forward` path, not the new `head+1` stitch). Measured: quicksort IPC 0.534 → 0.538, CoreMark 0.561 → 0.563 (small — the target-span case is rare in these kernels).
8. **Co-sim MMIO gap** — the diff stops at the first UART access because Spike has no such device; closable by teaching Spike the peripherals or by running a no-MMIO firmware for the comparison.
9. **Deferred by choice**: S/U mode + delegation (`medeleg`/`mideleg`), PMP, cross-word sub-word accesses.
