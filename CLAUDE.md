# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A RV32IMAC + Zicsr + Zifencei RISC-V core targeting a **Gowin GW2AR-18C** FPGA (part `GW2AR-LV18QN88C8/I7`, QFN88 package), on a Tang Nano 20k-based board. The board is clocked by a **25 MHz single-ended reference** from an **MS5351M** clock generator (crystal-fed; CLK0 on **PIN10**, LVCMOS33) — not the stock 27 MHz oscillator. The core is a work-in-progress pipeline: **fetch, decode, and execute stages are implemented** (the pipe reaches the E/M register and writes back to the reg file); **memory (LSU) onward is not yet present**. The execute stage is a **DRAFT** — it drives the reg-file write port, the fetch redirect, and decode's stall/flush, but has **no forwarding/hazard unit** and **no LSU** (loads/stores/Zilx compute their effective address but do not retire a write). The CPU exits **two AXI4-Lite masters** (`imem_axi`, `peri_axi`). The native `mem_req_t` / `mem_rsp_t` → AXI4-Lite conversion is done **inside the CPU** (one `axi4_lite_master_bridge` per master port), so the rest of the system sees the CPU as a plain AXI4-Lite master and the board top stays free of glue.

Key files:
- Board-level top (IDE `TopModule`): `src/rtl/core/top_module.sv` — `module top_module`.
- CPU RTL top: `src/rtl/core/rv32imac_zicsr_zifencei.sv` — `module rv32imac_zicsr_zifencei`; instantiates pipeline stages + two on-die AXI4-Lite bridges.
- Gowin IDE project: `rv32imac_Zicsr_Zifencei.gprj` (file list + device).
- Process/synthesis config: `impl/rv32imac_Zicsr_Zifencei_process_config.json` (`TopModule`, tool options).
- Synthesized netlist/reports: `impl/gwsynthesis/`. PnR bitstream/reports: `impl/pnr/` (gitignored — regenerable).

## Build flow (Gowin EDA)

This is a **Gowin FPGA Designer** project — no open-source flow, no Makefile. Build via the IDE or `gw_sh` Tcl shell. The Gowin toolchain is **not installed in the local WSL env**; it runs on a remote build host (`giacomo@192.168.10.36`) where `gw_sh` lives at `/home/giacomo/gowin_ide/IDE/bin/gw_sh` (Gowin V1.9.11.03 Education, NOT on the remote PATH — use the full path). rsync the repo to `~/gowin_proj/rv32imac_Zicsr_Zifencei/` there to build; see the `remote-gowin-build-host` memory for the exact workflow.

The synthesizer writes its report to `impl/gwsynthesis/rv32imac_Zicsr_Zifencei_syn.rpt.html` — **read that file for errors/warnings**; `gw_sh` itself prints only a banner to stdout.

### Synthesize

A committed Tcl entry point exists: `impl/synth_check.tcl`. It opens the `.gprj`, sets `top_module`, and runs `syn`. Invoke it with the Gowin shell over SSH. The shell links Qt, so it needs the **`offscreen` platform** plus **software OpenGL** — `QT_QPA_PLATFORM=offscreen` alone now crashes `gw_sh` on the build host (`Could not initialize GLX` / `IOT instruction` = SIGABRT); force software GL alongside it:

```bash
QT_QPA_PLATFORM=offscreen QT_OPENGL=software LIBGL_ALWAYS_SOFTWARE=1 gw_sh impl/synth_check.tcl
```

**Gowin CLI quirk (important):** `gw_sh` silently no-ops and produces no output if the target `.vg` / report already exist from a previous run. **Delete them before re-running** synthesis, or the run will appear to succeed while changing nothing. On the build host (zsh) delete by **explicit filename**, not glob — zsh aborts the whole `rm` on a non-matching glob (`rm -f .../*.vg` with no `.vg` → `zsh: no matches found`, nothing removed):

```bash
rm -f impl/gwsynthesis/rv32imac_Zicsr_Zifencei.vg impl/gwsynthesis/rv32imac_Zicsr_Zifencei_syn.rpt.html impl/gwsynthesis/rv32imac_Zicsr_Zifencei_syn_resource.html impl/gwsynthesis/rv32imac_Zicsr_Zifencei_syn_rsc.xml
```

### Place & Route

Driven by `impl/pnr/cmd.do` (targets GW2AR-18C, runs `-bit -tr -ph -timing`, converts SDP32/36 → SDP16/18 BSRAMs, `global_freq 50.000`). PnR device options come from `impl/pnr/device.cfg`:

```bash
QT_QPA_PLATFORM=offscreen QT_OPENGL=software LIBGL_ALWAYS_SOFTWARE=1 gw_sh -pnr -do impl/pnr/cmd.do
```

Outputs `impl/pnr/rv32imac_Zicsr_Zifencei.fs` / `.bin` for programming. `cmd.do` passes `-sdc src/phys/rv32imac_Zicsr_Zifencei.sdc`, so the timing constraints are applied, and sets `global_freq 50.000` to match the 50 MHz `clk_core`.

### Constraints (in `src/phys/`, NOT `impl/pnr/`)

Pin assignment — `src/phys/rv32imac_Zicsr_Zifencei.cst`:
- `clk_i` → PIN10 (25 MHz single-ended from the MS5351M clock generator, crystal-fed; CLK0, `IO_TYPE=LVCMOS33`. The MS5351M drives three independent CMOS clocks — PIN10 is CLK0, PIN11 is CLK1, not a differential P/N pair — so no LVDS primitive or external termination is used.)
- `rstn_i` → PIN88 (mapped; async, active-low)
- `led_o[0..3]` → PIN15, PIN16, PIN17, PIN18 (onboard LEDs; `fe_pc_dbg_o[3:0]`)

Timing — `src/phys/rv32imac_Zicsr_Zifencei.sdc` (applied via the `-sdc` flag in `cmd.do`):
- Primary clock `clk25` at 25 MHz on `clk_i` (period 40 ns).
- Generated clock `clk_core` at 50 MHz on the `clk_core` net (`create_generated_clock -source clk_i -master_clock clk25 -multiply_by 2 -divide_by 1`; 25×10/5, period 20 ns). The whole fabric runs on `clk_core`, so this is the only timing-critical clock; `clk25` only feeds the rPLL and has no user-logic paths. (Target lowered 100→50 MHz: the execute stage + BSRAM regfile combinational depth caps the design around ~50 MHz post-route, so 100 MHz was unachievable. 50 MHz closes PnR with ~0.007 ns worst setup margin.)
- `rstn_i` (false-path-from) and `led_o[*]` (false-path-to) marked non-timing-critical.

There is **no lint config** in the repo. A **Verilator** functional sim harness lives in `sim/` (see **Simulation** below); it exercises the implemented fetch + decode + execute + bridge + RAM logic. A separate **AXI4-Lite RAM protocol-compliance test** lives in `sim/ram_tb/` (see **Simulation** below); it drives the RAM slave directly as a master and verifies the B/R channel handshake rules.

## Simulation (Verilator)

`sim/` holds a Verilator C++ harness that builds the implemented logic (fetch + decode + execute + on-die AXI4-Lite bridge + AXI4-Lite RAM) and logs what fetch delivers, what decode produces, and what execute retires. It is **not** part of the synthesis file list.

- `sim/sim_top.sv` — sim wrapper. Replicates `top_module`'s wiring (CPU `imem_axi` → `axi4_lite_ram`; `peri_axi` tied off) but instantiates the RAM with `INIT_FILE="program.hex"` so a program is preloaded via `$readmemh`, and exposes the CPU's `fe_*` (fetch), `de_*` (decode), AND `ex_*` (execute) debug taps — `pc / instr / valid` per stage — as output ports for the C++ log.
- `sim/sim_main.cpp` — drives clk/rst (async active-low reset for a few cycles), clocks the design, and prints **three** logs, each in its own reset+run pass so they stay aligned (each stage lags the previous by one cycle): a **fetch log** (one line per F/D-valid word: `cycle / fe_pc / fe_instr / c`, with a word-advance-+4 check), a **decode log** (one line per D/E-valid instruction: `cycle / de_pc / de_instr`), and an **execute retire log** (one line per E/M-valid retired op: `cycle / ex_pc / ex_instr`). A VCD (`sim/sim_top.vcd`) is written for GTKWave. The CPU exports only `pc / instr / valid` per stage now, so the logs do not show control/immediates/operands/writeback values — add taps back when those need verifying. **The VCD itself traces the full hierarchy** (Verilator `--trace`, `top->trace(tfp, 99)`), so decode internals ARE named in it even though they are not CPU ports: `u_decode.opcode` (7-bit major opcode), `u_decode.alu_op` (5-bit), `u_alu.alu_op_i` (5-bit), `funct3/5/7`, `imm_*`, `rs1/rs2_*`, `hold_*`, etc. The `de_t` struct is flattened to a 202-bit `de_o`/`de_q`/`de_d` (field names lost unless `--trace-structs` is added to `VFLAGS`). To show a numeric signal as a mnemonic in GTKWave: set its Data Format to Bin, then `Edit → Data Format → Translate Filter File → Enable and Select`, and point it at a translate file (`value label` lines, value in the signal's radix). Two ready files live in `sim/`: `gtkwave_alu_op.txt` (ALU_ADD..ALU_LX, applies to `u_decode.alu_op` / `u_alu.alu_op_i`) and `gtkwave_opcode.txt` (OPC_LUI..OPC_AMO, applies to `u_decode.opcode`). Re-apply the filter if you delete/re-add the signal (it does not auto-reapply).
- `sim/program.hex` — `$readmemh` preload, one 32-bit hex word per line (the word value IS the instruction encoding; a word may hold one 32-bit instr or two 16-bit compressed instrs). The current program is a **hazard-free ALU-only RV32IM test** (no control flow, no loads/stores): every instruction retires in PC order, DIV/REM stall the pipe and retire on their done cycle, and the program ends by running off into zeros (illegal → no retire). It is built to exercise the execute writeback path cleanly. Edit it to test different programs. **There is no assembler** — encodings are hand-computed (with a bit-field script) and verified against the sim retire log (the sim is the oracle).
- `sim/Makefile` — `make run` builds (`obj_dir/Vsim_top`) and runs from `sim/` (so `program.hex` resolves relative to the run cwd). The RTL list includes `reg_file.sv` + `decode_stage.sv` + `alu.sv` + `execute_stage.sv` (not part of synthesis).

Fetch, decode, and execute are implemented; the execute stage writes back ALU / PC4 results to the reg file and resolves branches (redirecting fetch). Loads/stores/Zilx compute their effective address but do not retire (no LSU yet), and illegal ops do not retire, so the retire log ends when the program runs off into zeros. The CPU exports only `pc / instr / valid` per stage, so the writeback VALUE is not directly observable in sim (the retire log verifies sequencing + writeback/branch-resolve; add a writeback tap when values need checking). Requires Verilator installed (the local WSL env has it):

```bash
sudo apt-get install -y verilator
cd sim && make run
```

Build artefacts (`sim/obj_dir/`, `*.vcd`, `*.log`) are gitignored.

### AXI4-Lite RAM compliance test (`sim/ram_tb/`)

A second, independent Verilator harness that does **not** use the CPU — it instantiates `axi4_lite_ram` alone and drives it as an AXI4-Lite master from C++ (`ram_tb.cpp` is a small cycle-accurate BFM). It verifies the RAM's **protocol compliance**, which the main sim cannot (the CPU has no LSU/writeback, so it never writes to the RAM):

- `sim/ram_tb/ram_tb.sv` — wrapper that breaks the `axi4_lite_if` out to flat master-side ports for the C++ BFM.
- `sim/ram_tb/ram_tb.cpp` — BFM + checks. Key checks: **BVALID is registered and held high while BREADY is deliberately kept low for several cycles** (the fix that made the RAM compliant — the old combinational BVALID would have dropped here); AW-first and W-first orderings; byte-strobed partial writes read back correctly; back-to-back writes; **single outstanding** (AWREADY/WREADY low while B pending); RVALID held while RREADY delayed.
- `sim/ram_tb/Makefile` — `make run` builds `obj_dir/Vram_tb` and runs it; exits non-zero on any check failure.

```bash
cd sim/ram_tb && make run     # prints "N checks, 0 failures" on success
```

## Code formatting (Verible)

SystemVerilog is formatted with **Verible** (`verible-verilog-format`). The project policy lives in `verible.flags` (a Verible `--flagfile`); it captures the style the RTL already follows — 4-space indent, 100-column limit, aligned port / named-parameter / named-port / assignment groups, and `end else` kept on one line. Edit `verible.flags` to change the project-wide policy; do not pass overriding flags on the command line or the two drift apart.

A top-level `Makefile` drives the formatter over every `.sv`/`.svh`/`.v` under `src/rtl` and `sim/` (excluding `sim/obj_dir`):

Verible is not in Debian apt on this distro; install the static binary from [chipsalliance/verible](https://github.com/chipsalliance/verible/releases) (the formatter is `verible-verilog-format`, the linter `verible-verilog-lint`). ## Architecture

Built bottom-up; fetch, decode, and execute are implemented (execute is a DRAFT — see its limitations below), memory (LSU) onward is not yet present. Every RTL file does `import rv32_pkg::*;` and starts with `` `resetall `` / `` `default_nettype none `` / `` `timescale 1ns / 1ps `` — **match these in new files**.

### Naming conventions (RTL)

- **Ports:** inputs end `_i`, outputs end `_o` (e.g. `clk_i`, `fe_pc_o`).
- **Internal signals:** **no prefix** — they are neither inputs nor outputs, so they are distinguishable already. Flop registers end `_q`, their next-state combinational counterparts end `_d` (e.g. `pc_q`/`pc_d`, `busy_q`, `state_q`). Plain wires/internals are unadorned (e.g. `imem_req`, `ar_hs`, `axi_bus_imem`). The one exception: a stage's **own output pipeline register** carries that stage's sigil (see next) so it disambiguates from other same-named flops in the stage — e.g. `fe_pc_q` (the F/D register PC) vs `pc_q` (fetch's next-fetch address).
- **Module instance names:** keep `u_*` (e.g. `u_cpu`, `u_imem_bridge`) — not signals.
- **Types (typedef/enum), parameters, localparams, enum labels, and AXI interface member names** (`awvalid`, `arready`, ...) keep their own spelling; AXI members follow the AXI spec.
- **Pipeline debug taps (stage sigil):** every pipeline stage exposes **only** the PC it is treating, the instruction word, and a valid as outputs, prefixed by a stage-identifying sigil — `fe_` (fetch), `de_` (decode), `ex_` (execute), .... Any further debug signals are added on demand (do **not** bake a long control-bundle tap list into the ports). The sigil names the **producing** stage: the F/D register is fetch's output (`fe_pc`/`fe_instr`/`fe_valid`); the D/E register is decode's output, exposed as `de_pc`/`de_instr`/`de_valid`; the E/M register is execute's output, exposed as `ex_pc`/`ex_instr`/`ex_valid`. A stage's **consuming** input ports take the producer's sigil (decode's F/D inputs are `fe_*_i`). The CPU top mirrors the per-stage taps as `fe_*_dbg_o` / `de_*_dbg_o` / `ex_*_dbg_o` (plain `logic`, pc/instr/valid only); the board top leaves them unconnected (swept by synthesis) except `fe_pc_dbg_o[3:0]` → LEDs.

- **`src/rtl/pkg/rv32_pkg.sv`** — package: `XLEN=32`, `STRB_WIDTH`, `AXI4_LEN`, the native memory structs (**split per direction, AXI-style**: `mem_req_t` master→bridge `wvalid`/`we`/`addr`/`wdata`/`wstrb`/`rready`; `mem_rsp_t` bridge→master `wready`/`rvalid`/`rdata`; launch = `req.wvalid && rsp.wready`, read = `rsp.rvalid && req.rready`, `req_handshake()` returns the launch predicate; **no `bvalid` yet** — TODO LSU), **and the decode types**: major-opcode `localparam`s (`OPC_LUI`..`OPC_SYSTEM`, incl. `OPC_AMO` used by Zilx), `alu_op_t` (19 values, 5 bits — base RV32I + M + `ALU_LX` for Zilx indexed-load EA), `branch_t` (`BR_NONE`..`BR_JALR`), `alu_src_a_t` (2 bits — `ALU_A_RS1`/`ALU_A_PC`/`ALU_A_RS2`; `ALU_A_RS2` is the Zilx **base**), `alu_src_b_t` (3 bits — `ALU_B_IMM`/`ALU_B_RS2`/`ALU_B_PC4`/`ALU_B_ZERO`/`ALU_B_RS1_SH`; `ALU_B_RS1_SH` is the Zilx **index**, shifted in the ALU), `wb_src_t`/`mem_size_t`, and the packed **`de_t`** D/E control struct (single-direction, legal as one port — matches `mem_req_t`/`mem_rsp_t`). `de_t` fields: `valid`/`pc`/`instr`/`is_compressed`/`rs1_addr`/`rs2_addr`/`rs1_data`/`rs2_data`/`imm`/`rd`/`reg_write`/`alu_op`/`alu_src_a`/`alu_src_b`/`mem_read`/`mem_write`/`mem_size`/`mem_unsigned`/`wb_src`/`branch_type`/`mem_shamt`/`illegal`. `mem_shamt` (2 bits) is the Zilx index scale (0 unscaled, `log2(size)` scaled). `instr` is the 32-bit word decode treated (native or RVC-expanded), latched alongside `pc`/`valid` so the `de_*` taps stay aligned.
- **`src/rtl/core/fetch_stage.sv`** — fetch stage. Owns the PC and the F/D pipeline register, exposed as `fe_*` taps: `fe_pc_o`/`fe_instr_o`/`fe_valid_o` (pc/instr/valid only — no `fe_is_compressed_o`/`fe_next_pc_o`; decode derives is-compressed from `fe_instr[1:0]`). Exposes a **native** instruction-memory interface (`imem_req_o` / `imem_rsp_i`, direction-split). **No bus protocol here** — it handshakes with the on-die bridge (`req.wvalid && rsp.wready` to launch, `rsp.rvalid && req.rready` to capture) as a single-outstanding **overlap-prefetch** FSM (no explicit `state_t`; uses `busy_q`/`req_pc_q`/`flushed_q` flags). Forward-compat inputs `stall_i` (driven by decode's `stall_o`, which propagates execute's div stall) and `branch_valid_i`/`branch_addr_i` (driven by execute's branch-resolve redirect) are on the port and **now wired** in the CPU top.
- **`src/rtl/core/decode_stage.sv`** — decode stage (phase 1: RV32I + M + C + **Zilx indexed loads**). Consumes fetch's `fe_*` F/D outputs (its input ports are `fe_instr_i`/`fe_pc_i`/`fe_valid_i` — pc/instr/valid only; `is_compressed` is derived locally from `fe_instr_i[1:0]`) and produces the D/E control word (`de_o`, `de_t`) latched into a D/E register. **Expand-then-decode-uniformly**: a 16-bit RVC instr is turned into its 32-bit RV32I equivalent by the local `c_expand()` function, then the same uniform decoder decodes the 32-bit word (native or expanded); M has no compressed forms. A **hold buffer** stashes the upper half of a word when the low half is compressed (decoded next cycle, PC = word_pc+2). Reads rs1/rs2 from `reg_file` asynchronously (addresses out, data back same cycle, latched into `de_o`). **Zilx** is decoded (not gated): the `OPC_AMO` case recognises the indexed-load funct5 encodings (`10010` unscaled, `11010` scaled; `11110` `lxsuw` is RV64-only → illegal), swaps rs1=index / rs2=base, computes `mem_shamt` (0 unscaled, `log2(size)` scaled), and emits `alu_op=ALU_LX`, `alu_src_a=ALU_A_RS2`, `alu_src_b=ALU_B_RS1_SH`, `mem_read=1`, `wb_src=WB_MEM`; real AMOs and remaining aq/rl atomics still decode `illegal=1`. `stall_o` feeds fetch's `stall_i` (propagates execute's div stall — no longer inert). `flush_i` (from execute's branch redirect) kills the D/E register. Deferred opcodes (`OPC_MISC_MEM`/`OPC_SYSTEM`/unknown) decode to `illegal=1`. See **Decode stage behaviour** below.
- **`src/rtl/core/reg_file.sv`** — 32×32 register file, **inferred as BSRAM** (async-read block RAM: the unpacked `logic [XLEN-1:0] regs[31:0]` with sync-write + 2-async-read matches GowinSynthesis's BSRAM template once the writeback port went live → `Bsram=2`). BSRAM's async read is slower than a flop mux (it capped the regfile path ~54 MHz synth / ~50 MHz post-route), but Fmax is not the current goal — the fabric is targeted at 50 MHz, where BSRAM is comfortably fast enough. **2 async read ports + 1 sync write port** (posedge). Explicit `x0` read-zero mux; writes to `x0` ignored. **The whole file resets to 0** via an `if (!rstn_i)` loop in the RTL — Verilator honors it (sim determinism: all regs read 0 until written); in hardware BSRAM contents cannot be runtime-reset, so it relies on BSRAM power-up INIT + write-before-read (standard for a regfile — architectural state is not cleared on warm reset). Ports: `clk_i`/`rstn_i`, `rs1_addr_i`/`rs2_addr_i` → `rs1_data_o`/`rs2_data_o`, `wr_addr_i`/`wr_data_i`/`wr_en_i`. The write port is driven by execute's writeback (`wb_addr`/`wb_data`/`wb_en`) — ALU / PC4 results land in the reg file. (A packed-array form forced distributed RAM instead, which is faster but NOT runtime-resettable and resettable-init-only — reverted to the unpacked/BSRAM form to keep the reset in RTL.)
- **`src/rtl/core/alu.sv`** — combinational ALU (base RV32I + single-cycle MUL via DSP + multi-cycle DIV/REM + Zilx EA). Ports: `operand_a_i`/`operand_b_i`/`alu_op_i`/`shamt_i[1:0]`/`start_i`/`result_valid_o`/`result_o`. Single-cycle ops assert `result_valid_o` immediately; DIV/REM (a 32-iteration restoring-division FSM) are launched with `start_i` and assert `result_valid_o` on the done cycle. `ALU_LX` computes the Zilx effective address `operand_a + (operand_b << shamt)` (operand_a = rs2 **base**, operand_b = rs1 **index**; the ALU does EA only — the load itself is the LSU's job). **Parentheses are mandatory** around the shift: `+` binds tighter than `<<`, so `a + b << n` parses as `(a+b)<<n` — a prior bug.
- **`src/rtl/core/execute_stage.sv`** — execute stage (DRAFT). Consumes the D/E control word (`de_i`), selects ALU operands per `alu_src_a`/`alu_src_b`, drives `u_alu` (launching DIV/REM with `start_i` and stalling the pipe — `EX_IDLE`/`EX_BUSY` FSM — until `result_valid_o`), writes back ALU / PC4 results to the reg file (`wb_*`; mem ops do not retire — no LSU), resolves branches and redirects fetch (`branch_valid_o`/`branch_addr_o`, flushing decode), and exposes a native `mem_req_o`/`mem_rsp_i` port for the future LSU (`wvalid=0` today). `stall_o` back-pressures decode during a div; `flush_o` kills decode's D/E on a taken branch. `ex_*` taps are the E/M register (pc/instr/valid of the retired op). **Known DRAFT limitations**: no forwarding / hazard unit (a consumer in the slot right after its producer reads the stale pre-writeback value — single-cycle ALU and DIV/REM share this); no LSU (loads/stores/Zilx compute EA but do not launch or retire); DIV/REM result is not bypassed. See **Execute stage behaviour** below.
- **`src/rtl/core/rv32imac_zicsr_zifencei.sv`** — CPU RTL top. Instantiates `fetch_stage` + `reg_file` + `decode_stage` + **`execute_stage`** (`u_execute`), plus **two `axi4_lite_master_bridge`** instances: `u_imem_bridge` (driven by `fetch_stage`'s `imem_req_o`/`imem_rsp_i`) and `u_peri_bridge` (driven by execute's `mem_req_o`/`mem_rsp_i` — the future LSU; `wvalid` is gated to 0 today, so the bridge stays idle). The native interface is direction-split, so there are **no `req_ready` wires** — `wready` lives in `mem_rsp_t`. Exits two AXI4-Lite masters. Wiring the execute stage closed the previously-tied-off loops: the reg-file write port ← `wb_addr`/`wb_data`/`wb_en`; `fetch.branch_valid_i`/`branch_addr_i` ← execute's branch-resolve redirect; `decode.stall_i` ← execute's div stall (`ex_stall`); `decode.flush_i` ← execute's branch flush (`ex_flush`). Debug taps: `fe_*` (fetch), `de_*` (decode), and `ex_*` (execute) — **pc/instr/valid only per stage** (the full D/E control stays inside as `de_w`; it is no longer unpacked into flat ports). `fe_pc_dbg_o[3:0]` brought out as the LED tap.
- **`src/rtl/core/top_module.sv`** — board top. **Clock tree:** the 25 MHz single-ended `clk_i` (PIN10, LVCMOS33, MS5351M CLK0) feeds an `rPLL` primitive (FCLKIN=25, IDIV_SEL=4, FBDIV_SEL=9, ODIV_SEL=16) that generates `clk_core` = 25×10/5 = **50 MHz** (VCO = 25×10×16/5 = 800 MHz, in the rPLL's 500–1250 MHz VCO range — GowinSynthesis EX0311 rejects VCO outside 500–1250); a 2-FF reset synchronizer produces `rstn_core` (async-assert on `rstn_i` or `!pll_lock`, sync-deassert on `clk_core`). **Single clock domain** — the CPU, both AXI4-Lite buses (`aclk`), and the `axi4_lite_ram` slave all run on `clk_core`/`rstn_core`; `clk_i` only feeds the rPLL and `rstn_i` only feeds the synchronizer, so there is **no clock-domain crossing**. Wires CPU `imem_axi` → `axi4_lite_ram` slave on `axi_bus_imem`; routes `peri_axi` to `axi_bus_peri` with the slave side tied off (all `*ready=0`/`*valid=0`) so a future peripheral drops in without rewiring. The CPU's `fe_*`/`de_*`/`ex_*` debug taps (pc/instr/valid) are left unconnected here except `fe_pc_dbg_o[3:0]` → LEDs (swept by synthesis otherwise); the sim wrapper (`sim/sim_top.sv`) consumes them. `led_o` = `fe_pc_dbg_o[3:0]`.
- **`src/rtl/bus/axi4_lite_if.sv`** — SystemVerilog interface (32-bit addr/data) with `master`, `slave`, and `trunk` modports. `aclk`/`aresetn` are driven into the trunk from the board top.
- **`src/rtl/bus/axi4_lite_master_bridge.sv`** — native `mem_req_t`/`mem_rsp_t` (direction-split) → AXI4-Lite AR/AW/W + R/B. Single shared FSM (`S_IDLE`/`S_RD_WAIT`/`S_WR_ADDR`/`S_WR_DATA`/`S_WR_WAIT`) — **single outstanding overall** (read OR write, not both). `rsp_o.wready = (state_q == S_IDLE)` is the launch handshake from the producer's side. **Read path**: in `S_RD_WAIT` the master's `req_i.rready` is forwarded straight to `axi.rready`, so the AXI slave holds `rvalid`/`rdata` until the master can accept; `rsp_o.rvalid = r_hs` the cycle data is consumed. For writes, AW+W launch in lock-step; on `b_hs` → `S_IDLE`. **Write retirement is not signalled back** (no `bvalid` in `mem_rsp_t` yet — TODO LSU); `bready` held high.
- **`src/rtl/utils/axi4_lite_ram.sv`** — AXI4-Lite slave single-beat RAM, **protocol-compliant** (verified by `sim/ram_tb/`). `(* ram_style = "block" *)` (infers a simple dual-port BSRAM on Gowin: one write port + one read port, single clock). Params: `ADDR_W` (byte-addressed depth = 2^ADDR_W bytes) and optional `INIT_FILE` for `$readmemh`. **Write path**: AW and W are independent channels and may arrive in either order (each captured into its own holding register, `aw_seen_q`/`w_seen_q`); the transaction completes the cycle both are seen, the BSRAM write fires, and **BVALID is registered and held high until the B handshake** (`bvalid && bready`) — this is the AXI "VALID stays asserted until the handshake" rule and the key compliance point (a previous version had a combinational one-cycle BVALID that only worked because the master bridge holds `bready` high; that was non-compliant). **Single outstanding**: while BVALID is pending, `awready`/`wready` are low. **Read path**: 1-cycle registered latency; `arready` depends only on registers + `rready` (never `arvalid`); RVALID registered and held until `rready`. READY outputs never depend on the same-channel VALID. Synchronous active-low reset (matches the bus layer; memory contents are not reset). Byte-strobed writes use the BSRAM byte enables. Wired as the `axi_bus_imem` slave.

### Fetch stage behaviour (current)

Single-outstanding **overlap-prefetch**. No `state_t` enum — the FSM is a set of flags (`busy_q`/`req_pc_q`/`flushed_q`) plus the F/D register (`fe_*_q`). Handshakes with the on-die bridge: launch = `imem_req_o.wvalid && imem_rsp_i.wready`; capture = `imem_rsp_i.rvalid && imem_req_o.rready`.

- `pc_q`: **next fetch address** — runs ahead of decode. Resets to `boot_addr_i`. On launch it advances to `pc_q + 4`; on redirect it is overwritten with the target. (Note: fetch always reads 32-bit words and advances by 4 — see Compressed below.)
- `req_pc_q`: address of the **in-flight** fetch. Stamped onto the F/D register at capture, so `fe_pc_o` is the **exact** address of the delivered instruction (not the already-advanced `pc_q`).
- `busy_q`: a fetch is in flight (at most one — single outstanding). `imem_req_o.wvalid = !busy_q && !branch_valid_i` (issue only when idle and not redirecting).
- `imem_req_o.rready = !fe_valid_q || flushed_q` — accept read data when the F/D register has room, **or** drain a flushed (redirected) response to free the bridge. This depends **only on registers**, never on `rvalid`, so there is no combinational loop through the bridge's `axi.rready` forwarding.
- **Overlap-prefetch**: on capture of fetch K (busy→0 next cycle), the next fetch K+1 is launched the very next cycle (the bridge is back in `S_IDLE`), while decode consumes K from the F/D register. Only one transaction is ever in flight (K+1; K already sits in F/D). If decode is slower than memory and K+1's response lands while F/D is still full, `rready` stays low and the bridge/AXI slave hold `rvalid`/`rdata` until decode frees F/D — **no skid buffer needed** (single outstanding ⇒ nothing queues behind the waiting response). Steady-state ~2 cycles/instruction (the bridge round-trip floor: 1 issue + 1 response).
- `fe_valid_o`: **held level** — high from a fresh capture until decode consumes it (`fe_valid_q && !stall_i` → `fe_valid_d=0`), or a redirect kills it. Mutually exclusive with capture (capture needs F/D empty; consume needs F/D full).
- **Redirect** (`branch_valid_i`, highest priority): kills stale F/D (`fe_valid_d=0`) and marks the in-flight fetch `flushed_q=1` so its response is drained and discarded; sets `pc_q` to the target. `wvalid` is gated by `!branch_valid_i` so no fetch of the old `pc_q` issues during the redirect cycle. If the flushed response lands the same cycle as the redirect, it is drained immediately.
- **Compressed (C)**: NOT handled here — always fetches 32 bits, advances by 4; decode derives `is_compressed = (fe_instr[1:0] != 2'b11)` itself (it is not a fetch port) and owns RVC expansion (a compressed instr in the low half of a word ⇒ the next instr is the upper half of the same word, handled in decode).
- **stall_i**: downstream back-pressure (driven by decode's `stall_o`). While high the F/D register is held (not consumed); prefetch still issues up to 1 ahead (bounded by single outstanding) and is discarded on redirect.

### Decode stage behaviour (current)

**Expand-then-decode-uniformly** (phase 1: RV32I + M + C). `c_expand(16-bit) → 32-bit RV32I equivalent`; the same uniform decoder then consumes the 32-bit word whether it came native (`fe_instr`) or from expansion. M has no compressed forms, so only RV32I compressed instrs are expanded. `c_expand` returns `32'h0` for illegal/unsupported encodings (opcode `0000000` decodes to `illegal=1`).

- **Hold buffer** (`hold_q`/`hold_word_q`/`hold_pc_q`): when a word's low half is compressed, decode it this cycle and stash the upper half for next cycle (PC = `fe_pc + 2`). Source priority: hold buffer > fresh F/D. `is_compressed` is **recomputed** from `hold_word_q[1:0]` for the upper half (do NOT trust the word-level `fe_is_compressed`, which describes the whole word).
- **Uniform decoder**: one `always_comb` extracts fields + immediates (I/S/B/U/J, sign-extended) and emits control per opcode. `rs1/rs2_addr` (forced to `x0` for instrs that don't use them) drive the reg-file async reads; `rs1/rs2_data` are latched into `de_o`. `de_o.instr` = the 32-bit word decode treated. `illegal` defaults to 1; recognised opcodes clear it; `spanning_illegal` or `dec_illegal` squash `reg_write`/`mem_*`/`branch_type` and set `illegal = decoded_valid`.
- **RVC spanning (phase-1 simplification)**: fetch delivers 32-bit words at 4-byte boundaries; decode derives `is_compressed` from `fe_instr[1:0]`. A 32-bit instr is assumed 4-byte aligned; the spanning case (low half compressed AND upper half `[1:0]==2'b11`) is **undefined → `illegal=1`** (documented limitation). This is the only known RVC limitation today.
- **`stall_o = (hold_q && fe_valid_i) || stall_i`** — register-only (no comb loop through fetch). The `hold_q && fe_valid_i` term is INERT by construction (hold raises the cycle `fe_valid` falls, so they are mutually exclusive), but `stall_i` is now driven by execute's div stall, so `stall_o` propagates a real back-pressure during multi-cycle DIV/REM. No word is lost or double-decoded (priority mux: hold wins).
- **Deferred opcodes** (`illegal=1`, not executed this phase): `OPC_MISC_MEM` (fence/fence.i — Zifencei), `OPC_SYSTEM` (CSR/ecall/ebreak — Zicsr), atomics, any unknown opcode. JAL/JALR/c.j/c.jr/c.jal/c.jalr still produce their control (`branch_type`/`reg_write`/`wb_src`) even without execute — it rides the D/E register to the debug taps.
- **Pitfall — `c.addi` vs `c.li`**: `c.addi rd,imm` → `addi rd,rd,imm` (rs1 = rd); `c.li rd,imm` → `addi rd,x0,imm` (rs1 = x0). Don't confuse them. Related: `c.addi16sp` (rd==x2) vs `c.lui` (else) share quad1 funct3=011; `c.addi4spn` with nzuimm==0 is illegal; `c.mv`/`c.add` (quad2 funct3=100) selected by `c[12]` (0=mv rs1=x0, 1=add rs1=rd), `rd==0` HINT → illegal; `c.jr`/`c.jalr`/`c.ebreak` selected by rs2==0.

### Execute stage behaviour (current — DRAFT)

Consumes the D/E control word (`de_i`) and produces the E/M register (`ex_*` taps: pc/instr/valid of the retired op) plus the reg-file writeback, the fetch redirect, and decode's stall/flush. Instantiates `u_alu`.

- **Operand select**: `alu_src_a` picks rs1 / pc / rs2 (Zilx base); `alu_src_b` picks imm / rs2 / pc-link / 0 / rs1 (Zilx index, the ALU applies `shamt_i`). `pc_link = pc + (is_compressed ? 2 : 4)` is the JAL/JALR link value and the `ALU_B_PC4` operand.
- **DIV/REM FSM** (`EX_IDLE`/`EX_BUSY`): `alu_start = de_i.valid & is_div_op & (state==IDLE) & ~stall_i` launches the ALU's multi-cycle divider for one cycle; `EX_BUSY` holds the pipe (`div_running = state==BUSY & ~result_valid`) until `result_valid_o`. `stall_o = alu_start | div_running | stall_i`. The done cycle drops the stall so decode advances and the same div is **not relaunched** (`ex_state_q` is still `BUSY` at done, so `alu_start=0`; it clears to `IDLE` for the next cycle's new `de_i`). Single-cycle ALU ops retire the cycle they are valid.
- **Writeback**: `wb_data` = `alu_result` (WB_ALU) / `pc_link` (WB_PC4) / `mem_rsp_i.rdata` (WB_MEM, 0 until the LSU lands); `wb_addr = de_i.rd`; `wb_en = de_i.valid & de_i.reg_write & ~de_i.illegal & ~is_mem_op & result_valid & ~stall_i`. Mem ops and illegal ops do **not** write back.
- **Memory interface (future LSU)**: `mem_req_o.addr = alu_result` (the Zilx / base+offset EA), `wdata = rs2_data`, `wstrb` computed from `mem_size` and the low address bits, `we = mem_write`. **`wvalid` is gated to 0** today so the peri bridge stays idle and the pipe never stalls on the (tied-off) peri slave. Wire the launch + `rsp.rvalid` stall + `WB_MEM` writeback when the LSU lands.
- **Branch resolve**: `branch_taken` per `branch_type` (BEQ/BNE/BLT/BGE/BLTU/BGEU on rs1/rs2, JAL/JALR always). `branch_addr` = `(rs1+imm)&~1` for JALR else `pc+imm`. `branch_valid_o = de_i.valid & ~illegal & (branch_type!=NONE) & taken & ~stall_i & result_valid`; `flush_o = branch_valid_o` kills decode's D/E. The redirect propagates to fetch (`branch_valid_i`/`branch_addr_i`), which flushes the in-flight fetch and sets the PC.
- **E/M taps**: `op_retires = de_i.valid & ~illegal & ~is_mem_op & result_valid & ~stall_i`; the E/M register latches `pc`/`instr` and pulses `ex_valid` for one cycle per retire (so the sim retire log is one line per retired op, not a held level). Mem/illegal ops never set `ex_valid`.

**Known DRAFT limitations** (TODO before relying on execute):

- **No forwarding / hazard unit.** Decode's reg-file async read for the next instruction overlaps the current instruction's writeback (both resolve at the same posedge), so an instruction that reads a register written by the **immediately preceding** instruction sees the **stale** (pre-writeback) value. A single intervening instruction (any op, including a NOP) resolves it — the consumer then reads during the intervening op's execute cycle, after the producer's writeback. Add a bypass path or a stall-on-RAW interlock before relying on dependent sequences.
- **No LSU.** Loads / stores / Zilx compute their effective address in the ALU but do not launch a request (`wvalid=0`) and do not retire a register write, so the pipe never stalls on the (today tied-off) peri slave. The retire log ends when a mem-op program would need the load.
- **DIV/REM result is not bypassed** (subset of the hazard note): a consumer in the slot right after the div reads the stale value.
- The `ex_*` taps expose pc/instr/valid only — the writeback **value** is not observable in sim. The ALU test program (`sim/program.hex`) verifies sequencing/retirement order; add a writeback tap when values need checking.

### Open work / things future instances should know

- **Execute stage is a DRAFT and wired** — `decode_stage`'s D/E output (`de_o`) now feeds `execute_stage`, which drives the reg-file write port, the fetch redirect, and decode's stall/flush (see **Execute stage behaviour**). The remaining execute work is the **forwarding / hazard unit** (resolve the RAW hazard), the **LSU** (loads/stores/Zilx retirement + `mem_rsp_t.bvalid` write-ack), and a **writeback tap** if values need observing in sim.
- The **redirect path** (`branch_valid_i`/`branch_addr_i` → fetch PC redirect + in-flight flush) and the **div stall path** (`decode.stall_i` ← `ex_stall`) are now **wired in the CPU top** (no longer tied off). The fetch/decode **stall-from-hazard-unit** input (`fetch.stall_i` / `decode`'s own `hold_q` term) is still inert by construction — reserve it for a future hazard interlock.
- Decode now **decodes Zilx** (indexed loads via `OPC_AMO`), but the **LSU is not present** so Zilx computes its EA and decodes `mem_read=1` without retiring a load. Decode still **defers** Zicsr (CSR file) and Zifencei (fence) — `OPC_SYSTEM` and `OPC_MISC_MEM` decode to `illegal=1`.
- **RVC spanning limitation** (phase 1): a 32-bit instr spanning the *word* boundary (low half compressed AND upper half `[1:0]==2'b11`) is `illegal=1` by design. If fetch is ever widened (e.g. 64-bit fetch to hide the 2-cycle memory latency), the spanning case generalises to the new fetch width — extend the same "spanning → illegal" simplification rather than adding stitch logic, at least initially.
- The CPU exposes `peri_axi`. `execute_stage` already drives the internal `peri_req`/`peri_rsp` (with `wvalid=0` today — no LSU), and `u_peri_bridge` translates that to AW/W on `peri_axi`; when the LSU lands execute will start launching loads/stores (including Zilx indexed loads) on this bus with **no board-top changes**. `mem_rsp_t` still needs `bvalid` (write-ack) added for the LSU. The board `top_module` does **not** connect the CPU's new `ex_*` debug outputs (left unconnected — swept by synthesis); wire them (e.g. to `()`) if synthesis warnings about unconnected outputs are unwanted.
- `cmd.do` passes `-sdc src/phys/rv32imac_Zicsr_Zifencei.sdc` and sets `global_freq 50.000` MHz (matching the 50 MHz `clk_core`); the 25 MHz `clk25` only feeds the rPLL. 50 MHz closes PnR (~0.007 ns worst setup margin). Verify timing closure against `clk_core` before relying on it.
- `rv32imac_Zicsr_Zifencei.gprj.user` is per-machine IDE state (gitignored) — don't rely on it; the canonical file list is the `.gprj`. The `.gprj` now lists `reg_file.sv` + `decode_stage.sv` + `alu.sv` + `execute_stage.sv` (after `fetch_stage.sv`).
