# CLAUDE.md

Guidance for Claude Code in this repo.

## Project

RV32IMAC + Zicsr + Zifencei RISC-V core for a **Gowin GW2AR-18C** FPGA (QFN88) on a Tang Nano 20k. Clock: 25 MHz single-ended from an MS5351M generator (CLK0, PIN10, LVCMOS33) — not the stock 27 MHz oscillator. **Shipping build: 50 MHz via on-chip rPLL** (`clk_core = clk_i × 10/5`, IDIV_SEL=4/FBDIV_SEL=9/ODIV_SEL=16, VCO 800 MHz, period 20 ns) — re-closed at **50.017 MHz** on the 64-bit fetch-rewrite + target-span design (2026-08-27), and **re-closed again with the branch predictor in** (2026-08-28, worst setup slack +0.013 ns at 20 ns) after taking `redirect` off the instruction-buffer write enables. The predictor (gshare 64×2b PHT + 6-bit GHR + 8-entry RAS, prediction-at-decode, execute-as-judge, added 2026-08-28) is sim-verified (all oracles/cosims/TBs green) and worth **+2–4% IPC** (CoreMark 0.563→0.583, Dhrystone 0.519→0.535, quicksort 0.538→0.549); `BP_EN=0` prunes it and remains the fallback. Pre-fetch-rewrite design closed at 40.281 MHz (2026-08-25). Fallback: 25 MHz bypass (also diagnostic — removes rPLL) via 3 lines in `top_module` + re-comment SDC clock + `global_freq 25.000`.

**Status:** fetch / align+expand / decode / execute + LSU + Zicsr + trap/exception/interrupt implemented. **Instruction align + RVC expand lives in its own module, `align_stage.sv`, between fetch and decode**; its A/D pipeline register is a parameter, `AD_REG`, and **defaults to 0 (bypassed, so the pipeline runs 3-stage)** because the measurements say the 4th stage does not pay: `AD_REG=0` gives Fmax 49.590 / 511555 CoreMark cyc-per-iter / **1.95 CoreMark/MHz** / 97.0 iterations-per-second against `AD_REG=1`'s 53.278 / 548500 / 1.82 / 97.1 — +7.4% clock against −6.7% per-MHz is a 0.1% dead heat in absolute throughput and a worse published score. The register starts paying only above ~53.6 MHz, and the cut that would take the clock past that (registering `alu_result`, a writeback stage) costs another **0.30 CPI** (distance-1 RAW forwards are 27–38% of retires, each becoming a bubble once forwarding moves to the post-flop copy) and needs ~62 MHz of its own to break even. The module split is kept regardless: the RVC machinery does not belong in `decode_stage.sv`, and keeping it separate is what makes the remaining span-bubble work tractable. **Harvard** memory — read-only I-mem for fetch, native byte-strobed D-mem for LSU, AXI4-Lite only for peripherals. **Both memories 16 KiB (`ADDR_W=14`)**: GW2AR-18C has 46 BSRAM blocks (828 Kb); each 16 KiB memory = 8 blocks, 16/46 used. Package also carries **8 MiB (64 Mbit) SDRAM** on a separate die, unused (see plan item 2). Loads/stores/Zilx/CSR retire via native D-mem (or peri bridge) with **execute→decode forwarding** (distance-1 RAW, zero bubble).

**Machine-mode traps:** precise sync traps at execute commit — instr access fault (mcause=1), illegal instr (2), ecall-M (11), ebreak (3), load/store misaligned (4/6); `mret` returns; `wfi`=halt-until-pending; `fence`/`fence.i`=nop. `mtvec` direct+vectored. Software interrupt via `msip_peri`@0x1000_3000; timer via `clint_timer`@0x1000_1000+; external = OR of peripheral IRQs (UART)→`meip_i`. Priority MEI>MSI>MTI. Trapping instr not retired.

**Timing:** pre-rewrite closed 40.281 MHz (2026-08-25) via two register stages (LSU request, CSR read). **64-bit/2-outstanding fetch + target-span rewrite re-closed 50.017 MHz (2026-08-27)**. The **branch predictor first dropped PnR to 47.4 MHz** (2026-08-28); three causes were blamed in turn and only the third was dominant: the prediction adder (fixed, then reverted — wrong on far jumps, no in-kernel IPC gain); congestion from ~430 predictor flops on `regfile → forward mux → de_bus.rs2_data` (real, but 4 of the 25 worst paths); and **`redirect` reaching the instruction-buffer write path** (17 of 25, ending at `buf_fault_q…RAMREG/D`) — `redirect = branch_valid_i | pred_valid_i` and `pred_valid_i` is combinational in the buffer head, so every fanout inherited `head_q → buffer read mux → c_expand → decode → PHT → pred_redirect`. Fixed by keeping `redirect` off `rready`/`do_rsp`/`fault_push`/`push_cnt`/`buf_pop_cnt` (each term redundant, reasoning in `fetch_stage.sv`), verified cycle-neutral, and **50 MHz re-closed with `BP_EN=1`** (+0.013 ns worst setup slack, all 25 reported paths positive, the whole `buf_fault_q` cluster gone). The lesson: when a new combinational source is spliced into an existing control wire, audit *every* fanout — the expensive one was a RAM write enable, not the datapath the change was about.

**Where the path sits (65/100 MHz probes, 2026-08-28).** Under an unreachable constraint the netlist measures **20.130 ns / Fmax 49.590 MHz / Logic Level 14 / TNS −2041.789 ns over 1038 endpoints**; the 50 MHz build's 19.952 ns is only what the router achieves when chasing a target it can just meet. The 65 MHz and 100 MHz runs produced **bit-identical placement and routing** (all 25 data delays match to the picosecond, every slack differs by exactly 5.385 ns), so **over-constraining finds no margin** — the "a loose constraint understates the tool" lesson from the 27.7 → 40 → 50 sequence **stops generalising once the target is unreachable**. Those runs also settled that `impl/pnr/cmd.do` is not the option source: the authority is `set_option -global_freq` in `pnr_check.tcl` (keep cmd.do consistent anyway). The top 25 is two clusters that are **the same pipeline stage**, 0.03 ns apart: A `head_q → 8:1 buffer mux → c_expand → rs1_addr → forward compare → de_bus.rs1_data` (12 of 25, 20.100) and B `regfile BSRAM DO → forward mux → operand select → de_bus.rs2_data` (13 of 25, 20.130, plus six `DO → DI` writeback-loop and five `DO → mem_wdata_q` store-lane paths) — RVC expansion + decode + regfile read + forward mux all in one cycle, so cutting one alone buys nothing. `align_stage` cuts A; B is untouched, which is why `AD_REG=1` reaches only 53.278 MHz. **Regfile to flops: TRIED, WORSE, SETTLED** — `syn_ramstyle = "registers"` measured 47.557 MHz / 20.992 ns / Logic Level 16 / TNS −9766.680 ns over 3449 endpoints against BSRAM's 49.590 / 20.130 / 14 / −2041.789 over 1038: the 32:1 LUT mux for an async read is *deeper* than BSRAM's read access, and one write port fanning out to 32 RAMREG copies added 9 new worst paths. Second negative result at this operating point — do not try a third time. The lesson worth keeping: a path *launching* from a memory output does not mean the memory is what makes it long. Legacy `VON_NEUMANN` build dropped.

CPU exposes 3 ports: native `imem` (RO), native `dmem` (byte-strobed), AXI4-Lite master `axi_peri`. Native→AXI conversion inside the CPU (`axi4_lite_master_bridge`); board top is pure wiring. LSU decodes `addr[PERI_ADDR_BIT]` (0→D-mem, 1→peri). Only non-bus CPU output: `dbg_stall_o`→LED0.

## Simulation (Verilator)

Builds fetch+decode+execute+native I/D-mem+peri bridge, `--public-flat-rw`.

- `sim/sim_top.sv` — wrapper preloading native I/D-mem via `$readmemh` (`+IINIT=`/`+DINIT=`). 64-bit RO `OUTSTANDING=2` I-mem, 32-bit RW `OUTSTANDING=1` D-mem. `uart_rxd_i` double-flopped for board parity; every TX-FIFO byte logs to `sim/sim_uart_tx.txt`. `UART_CLK_HZ`/`UART_BAUD` default fast (5 clk/bit); pass `-GUART_CLK_HZ=25000000 -GUART_BAUD=115200` for board-real 217.
- `sim/sim_main.cpp` — drives clk/rst, logs fetch/decode/execute-retire+writeback. `UART_RX="..."` types real 8N1 frames; `UART_RX_PACED=0` ships back-to-back; `UART_BIT_CYCLES=217`=board-accurate; `NO_VCD=1` skips dump. Stops on park (8 identical retires) or `MAX_CYC` (default 4000). Prints a **stall-cause histogram** (load-wait/lsu-launch/lsu-capture/div/csr/wfi/rvc-hold/rvc-span/redirect/imem-starve/decode-bubble) and the same data as a **CPI decomposition** (each bucket ÷ retires — this form is comparable across designs, since `dbg_stall_o` %-of-cycles is not: it doesn't see fetch bubbles). Taxonomy/tables in `sim/README.md`. Checks WFI-halt invariant every run.
- `sim/imem.hex`+`dmem.hex` — hand-crafted Harvard oracle (RAW, LSU round-trip/load-use, byte/halfword sign/zero extend).
- `sim/Makefile` — `make run` (oracle); `RUN_ARGS="+IINIT=... +DINIT=..."` for C programs.
- `sim/sw/` — firmware tree. `common/` = shared assets (`uart.h`, `start.S`, `link.ld`, `bin2hex.py`, `ee_printf.c`) + `sw_build.mk` (parameterised build include: `ARCH`/`C_SRCS`/`S_SRCS`/`LINK_LD`/`DMEM_BASE`/`IMEM_PAD_WORDS`/`EXTRA_CFLAGS`/`EXTRA_LDFLAGS`/`EXTRA_LDLIBS`; stamps `build/.config` so a flag change forces rebuild). `quicksort/`/`coremark/`/`dhrystone/` = benchmarks; `isa/`/`intr/`/`peri/` = oracles. **Toolchain**: buildroot glibc `riscv32-buildroot-linux-gnu` at `~/_toolchains/riscv32-zilx/out` (gcc 14.3.0), override `RISCV_PREFIX`. `-march=rv32imac -mabi=ilp32 -nostdlib -ffreestanding -medlow -no-pie -Wl,-N -fno-pie` (glibc toolchain defaults to PIE/PT_PHDR, breaking the Harvard split — needs medlow absolute addressing). Default program `quicksort/main.c`: recursive quicksort, 256-word LCG array (same seq on Spike/RTL), returns `0x600D`/`0xBAD`.

```bash
cd sim && make run                    # Harvard oracle
make sw-run                           # build C prog + run (from repo root)
```

## Architecture

Built bottom-up. Every RTL file: `import rv32_pkg::*;` + `` `resetall `` / `` `default_nettype none `` / `` `timescale 1ns/1ps ``.

### Naming
Ports `_i`/`_o`. Flops `_q`, next-state comb `_d`. Instances `u_*`. Stage debug taps `fe_`/`de_`/`ex_`, internal only (`dbg_stall_o` is the sole exported one).

### Files
- **`rv32_pkg.sv`** — `XLEN=32`; `mem_req_t`/`mem_rsp_t`/`ifetch_req_t`/`ifetch_rsp_t`. `PERI_ADDR_BIT`=28; peri windows `UART_BASE`=0x1000_0000/4K, `MTIMER_BASE`=0x1000_1000/8K, `MSIP_PERI_ADDR`=0x1000_3000/4K. Decode types: opcodes (incl `OPC_AMO`), `alu_op_t` (incl `ALU_LX`), `wb_src_t` (incl `WB_CSR`), `csr_op_t`/`csr_addr_t`, `sys_op_t`, `MCAUSE_*`, `MSTATUS_*`, `MTVEC_DIRECT/VECTORED`. **Pipeline-register bundles `fa_t` (F/A) / `ad_t` (A/D) / `de_t` (D/E)** — one struct per pipeline register, named after the register not the stage; `fa_t` doubles as the type of fetch's `head+1` read port. **Branch-predictor types**: `pred_source_t` enum `{PRED_NONE,PRED_DIRECT,PRED_PHT,PRED_RAS}`; `bp_lookup_req_t`/`bp_lookup_rsp_t`/`bp_train_t`; `de_t` carries `pred_valid`/`pred_taken`/`pred_target[32]`/`pred_source[2]`/`pred_pht_index[6]` (~42 bits) riding D/E to execute for compare against resolved outcome.
- **`fetch_stage.sv`** — 64-bit, 2-outstanding, depth-8 (32-bit-word) instruction buffer. One 64-bit access delivers two 32-bit words, split into PC-stamped buffer entries (0/1/2 pushes/cyc); the consumer is `align_stage` (since 2026-08-28), which sees the head exactly as decode saw the old F/D word. `pc_q` advances by 8; `req_pc_q` holds the real in-flight PC. **Split PC stamp**: the half containing the fetch PC is always stamped `req_pc_q` so decode's `fe_pc[1]` picks the right halfword — stamping the high half with a computed address instead clears bit[1] and misrouted a `jalr` (fixed 2026-08-26, latent because the in-place oracle never redirected into the high half). `inflight_q[1:0]` caps outstanding at 2 (backed by the I-mem's depth-2 response skid); a redirect sets `pc_q`, kills the buffer, `draining_q` discards ≤2 stale responses. Overflow-safe room gating: `available = 8 - count - 2*inflight`, issue needs `available>=2 & inflight<2`, fault push needs `available>=1`. Inputs: `stall_i` (decode), `branch_valid_i`+`branch_addr_i` (execute redirect incl trap/mret/interrupt), **`pred_valid_i`+`pred_addr_i`** (decode's predicted-taken redirect, priority-merged *below* execute redirect via `pred_redirect = pred_valid_i & ~branch_valid_i`, same kill path, fires one cycle earlier). **`IMEM_ADDR_W` range check**: PC outside implemented I-mem → fault entry instead of a bus request; parameter must match the instantiated `native_ram`.
- **`align_stage.sv`** (2026-08-28) — instruction align + expand between fetch and decode. Owns the depth-8 buffer read mux, the RVC hold buffer (`hold_q`/`hold_word_q`/`hold_pc_q`), both spanning stitches and `c_expand()` — all moved verbatim out of `decode_stage`. Consumes two `fa_t` (buffer head + head+1), drives `fe_pop2_o`, outputs an `ad_t`. **`AD_REG` parameter (default 0)** selects whether that output is registered: 0 bypasses the flop and the pipeline stays 3-stage, 1 inserts the A/D register and makes it 4-stage — measured at 53.278 MHz / 1.82 CoreMark/MHz against 49.590 / 1.95, i.e. a throughput dead heat and a worse score, so it defaults off (see **Status**). Source priority: spanning stitch > compressed hold > odd-half target > fresh low half; `fe_head_i.fault` outranks every source (no word exists, so the fault rides through with the unfetchable PC and any stash is dropped). RVC funct3=100 group (c.srli/srai/andi CB + c.sub/xor/or/and CA): selector = `c[11:10]` (00 srli/01 srai/10 andi/11 arith), arith sub-group `c[6:5]`; `c[12]` is shamt[5]/imm[5], **not** a selector. ### Pipeline behaviour
**Fetch**: 64-bit/2-outstanding/depth-8 buffer. One access delivers two words; 2-outstanding keeps the BSRAM issuing through decode stalls, removing the pre-rewrite dominant bottleneck (~2.2 cyc/instr). Steady state ~1.8 cyc/instr. Harvard so fetch owns the I-mem port uncontended. Redirect kills buffer + ≤2 in-flight reads (drain FSM). The align stage also reads `head+1` (`fe_next_instr_o`/`fe_next_valid_o`=count≥2) for the same-cycle target-span stitch, driving `fe_pop2_o`.
**Align + expand (A/D)**: everything between the buffer and the decoder — the depth-8 buffer read mux, the RVC hold buffer, both spanning stitches, `c_expand()`. Source priority: spanning stitch > compressed hold > odd-half target > fresh low half. **Branch-target span (offset 2/6) is zero-bubble** (`target_span_complete`); **sequential span remains 1 bubble** (`span_wait`, fall-through case — removing it is dual-issue, deferred). `AD_REG=1` registers the output (decode then starts at a flop instead of behind an 8:1 LUT-RAM mux plus the expander) and needs **two** flushes, execute's `flush_i` and decode's `pred_flush_i`; `AD_REG=0` (default) bypasses the flop and the pipeline stays 3-stage.
**Decode** is a pure consumer of one already-expanded 32-bit word. Deferred-to-execute traps: unknown opcode, AMO funct5 11110/sfence.vma (no VM). Retiring in execute: ecall/ebreak/mret/wfi/fence/fence.i. Zicsr fully decoded+retired.
**Branch prediction**: decode predicts every classified control-flow instr — JAL/c.j/c.jal get a direct target (no BTB, zero cold-start mispredicts), conditional direction from PHT, JALR-returns from RAS; other JALR unpredicted. Predicted-taken redirects fetch one cycle early and must flush the fetch buffer **and** the align stage (A/D flop + RVC stash, via `pred_flush_i`); execute stays golden resolver. Net effect on no-retire budget: redirect CPI drops ~3× but a *new* `imem-starve`/`other` ~0.21 CPI appears (kill+refill bubble on every *correct* predicted-taken branch, since no mispredict fires to charge it to `redirect`) — gross redirect saving (~0.28) nets to ~+0.06 CPI after that refill cost. Accuracy 74.7/86.3/78.5% (qs/cm/dh), MPKI 52.9/27.3/41.0, RAS hit 98.2/100/100%. Architectural retire stream identical BP on/off (verified: quicksort 29675 retires both ways).

### Hazard resolution (execute→decode forwarding)
`fwd_rs1`/`fwd_rs2` fire when execute retires a writeback to a register the decoding instr reads (x0 excluded): inject `ex_wb_data_i` instead of the stale async regfile read — zero bubble. Covers ALU-RAW, div-done-then-use, branch-on-dependent, load-use (load's `EX_MEM_WAIT` holds consumer via `stall_i`; `wb_en` pulse on `rvalid` drives forward). Distance-2+: harmless, async regfile read already sees the committed value. Legacy `raw_haz` bubble interlock disabled.

**Rule the forward path imposes**: a combinational value derived from D/E operands (anything downstream of `alu_result`) may be consumed **only in the cycle it's produced** — later-cycle needs must latch it. Operands can come from the bypass, so such a value sits at the end of the critical path: simulation settles it regardless of depth, silicon does not. This is how the load byte-select bug got in — first thing to check when HW/sim disagree. Audited: `store_wstrb`/`store_wdata`/`mem_req.addr`, `sync_tval`, trap bundle payload.

**Known limitations:**
- Forward path distance-1 only (correct — execute retires ≤1 writeback/cyc in order).
- M-mode only (no S/U, medeleg/mideleg, PMP). Instruction access fault implemented; instruction-address-misaligned deliberately absent (IALIGN=16 with C ext means no odd PC can arise). Cross-word sub-word accesses unhandled. MEIP is single ORed level (only UART, no PLIC — ISR must poll). Unimplemented CSR addrs silently read 0/ignore writes.
- WFI halts forever if no enabled interrupt ever arrives (legal). `fence.i`/`fence` are nops (Harvard has no D→I write path).
- Harvard: I-mem holds `.text`/`.text.init` only; rest lives in D-mem. Three learned linker/startup rules: every `link.ld` must collect small-data sections (`.srodata*`/`.sdata*`/`.sbss*`) into `.rodata`/`.data`/`.bss` (gcc's `-msmall-data-limit` default puts objects there; `objcopy -j .rodata -j .data` misses uncollected sections); `start.S` zeroes `.bss` and `a0`/`a1` before `call main`; `sp=0x4000` (top of 16 KiB D-mem — above it aliases silently, only `ADDR_W` bits decoded). `.data`@0x2000 keeps Spike co-sim disjoint; requires `medlow`.

7. **RVC spanning bubble** — **branch-target case DONE (2026-08-27).** 32-bit instr at a 2-byte-aligned branch target no longer costs a bubble: decode exposes `head+1`, stitches in the cycle the target word is seen (`target_span_complete`), pops 2, re-stashes the remainder — zero new flops. Offset-2 always buffered; offset-6 falls back to stash-and-wait when the next fetch hasn't landed. Guarded by `sw/isa/span_target`. **Sequential span remains 1 bubble** (fall-through case) — dual-issue, deliberately deferred. PnR re-closed 50 MHz (critical path unchanged). Measured: quicksort 0.534→0.538, CoreMark 0.561→0.563 (small — rare case in these kernels).
