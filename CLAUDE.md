## Project

RV32IMAC + Zicsr + Zifencei RISC-V core for a **Gowin GW2AR-18C** FPGA (`GW2AR-LV18QN88C8/I7`, QFN88) on a Tang Nano 20k board. Clock: **25 MHz single-ended** from an MS5351M generator (CLK0, PIN10, LVCMOS33) — not the stock 27 MHz oscillator. An on-chip rPLL multiplies it to `clk_core = 35 MHz` (25×7/5; VCO 560 MHz). The 35 MHz closure is knife-edge (+0.004 ns slack); a comfortable **25 MHz PLL-bypass** (`clk_core = clk_i`) is the fallback — see Constraints.

**Status:** fetch/decode/execute + LSU + Zicsr + **trap/exception/interrupt** implemented. **Harvard** memory system — fetch has a dedicated read-only native I-mem, the LSU has a native byte-strobed D-mem, and AXI survives only for peripherals. Loads/stores/Zilx indexed loads and CSR ops (CSRRW/S/C + imm variants) launch/retire via the native D-mem (or peri bridge) with an **execute→decode forward path** (distance-1 RAW resolved same-cycle, zero bubble — no stall-on-RAW interlock). **Machine-mode traps**: precise sync traps at the execute commit point — illegal instruction (mcause=2, mtval=instr), ecall-M (11), ebreak (3), load-addr-misaligned (4, mtval=bad EA), store-addr-misaligned (6); `mret` returns (mstatus MIE←MPIE, MPIE←1); `wfi`=halt-until-pending-interrupt; `fence`/`fence.i`=nop. `mtvec` direct + vectored mode; mepc/mcause/mtval written on entry; mstatus MIE/MPIE/MPP semantics. A machine **software interrupt** (mcause=0x8000_0003) is injected by an `msip_peri` AXI4-Lite MMIO slave at `0x1000_3000` (write bit[0] sets/clears mip.MSIP); taken at a retire boundary (suppressed instr re-runs after mret) or on a WFI wake (mepc=wfi+4). A trapping instruction is **not** retired (matches the RISC-V spec + Spike). Traps sim-verified (oracle + Spike cosim). **Synth/PnR re-confirmed on the remote build host 2026-08-22 (pre-forwarding)** (host back online): the trap + timer path does NOT close a safe 40 MHz (the CLINT 64-bit compare, even two-stage pipelined, plus the trap redirect mux exposed the route-dominated CSR-address fan-out — async CSR read mux + write-decode → fetch `pc_q` / regfile DI — at ~37 MHz actual Fmax), so the target is **35 MHz** via an on-chip rPLL (`clk_core = 25×7/5 = 35 MHz`; IDIV_SEL=4/FBDIV_SEL=6/ODIV_SEL=16, VCO 560 MHz). PnR closes 35 MHz **knife-edge**: 35.004 MHz Actual Fmax, worst setup slack +0.004 ns, TNS 0 (0 failing endpoints) — essentially zero margin; may not repeat run-to-run. A comfortable **25 MHz PLL-bypass** (`clk_core = clk_i` direct, +2.248 ns slack) is the documented fallback (the 25 MHz PLL cannot reach a ≥500 MHz VCO even at ODIV_SEL=16: 25×16=400 < 500, so a clean 25 MHz out bypasses the PLL entirely). To reclaim a safe 40 MHz later, the async CSR read must be pipelined into a registered 1-cycle read (an invasive Zicsr read-latency change, deferred). A machine **timer interrupt** (mcause=0x8000_0007) is sourced by a `clint_timer` AXI4-Lite MMIO slave (64-bit free-running `mtime` + 64-bit `mtimecmp` at peri `0x1000_1000+`; `mtip = mtime >= mtimecmp` → `mip.MTIP`), coexisting with `msip_peri` and the UART behind an `axi4_lite_xbar_3` 1→3 peri mux (base+size decode: UART `0x1000_0000`, timer `0x1000_1000`, MSIP `0x1000_3000`; a peri address matching no window gets a DECERR instead of hanging). A machine **external interrupt** (mcause=0x8000_000B) is the OR of the peripheral level IRQs (`axi4_lite_uart.uart_irq_o` today) → `CPU.meip_i` → `mip.MEIP`. `int_cause` selects MEI>MSI>MTI priority (spec order). `mstatus.MPP` is WARL-forced to `2'b11` (M) — only M-mode exists. The legacy `VON_NEUMANN` build has been **dropped** — Harvard-only now (one topology).

CPU exposes **three** ports (Harvard): a native `imem` (fetch, read-only), a native `dmem` (LSU data, byte-strobed), and an AXI4-Lite master `axi_peri` for memory-mapped peripherals. The native→AXI4-Lite conversion for peripherals is done inside the CPU by one `axi4_lite_master_bridge` (peri-only); the board top is pure point-to-point wires (no crossbar). The LSU decodes `addr[PERI_ADDR_BIT]` itself (`0` → native D-mem, `1` → peri bridge → `0x1000_0000+`). The legacy `VON_NEUMANN` single-AXI-master topology has been **dropped** (Harvard-only). Only non-bus CPU output is `dbg_stall_o` → LED0. Per-stage pc/instr/valid taps stay internal (probed via Verilator hierarchy, not ports).

### Constraints (`src/phys/`)
`.cst`: `clk_i`→PIN10 (25MHz LVCMOS33), `rstn_i`→PIN88 (async active-low), `led_o[0]`=stall indicator, `led_o[3:1]`=counter alive.
`.sdc`: `clk25`@25MHz (40 ns) on `clk_i` (the input), plus a generated clock `clk_core` @ 35 MHz (28.571 ns, `multiply_by 7 / divide_by 5`, the rPLL CLKOUT) — `clk_core` is the constraint that covers the fabric; `clk_i` only feeds the rPLL. PnR closes 35 MHz **knife-edge**: 35.004 MHz Actual Fmax, worst setup slack +0.004 ns, TNS 0 (0 failing endpoints) — verified on the remote build host 2026-08-22 (with the trap + CLINT timer path). History: the target was 50 MHz → 40 MHz → 25 MHz (bypass) → 35 MHz (rPLL). The 40 MHz back-off was forced by the trap + timer additions: the CLINT 64-bit `mtime >= mtimecmp` compare (even two-stage pipelined into `mtip_q`) plus the trap redirect mux exposed the route-dominated **CSR-address fan-out** (async CSR read mux + write-decode → fetch `pc_q` / regfile DI) as the critical path at ~37 MHz actual — too slow for 40 MHz without pipelining the async CSR read (an invasive Zicsr read-latency change, deferred). 35 MHz is the rPLL boundary against that ~37 MHz path (+0.004 ns, essentially zero margin — may not repeat run-to-run). Comfortable fallback: **25 MHz PLL-bypass** (`clk_core = clk_i`, +2.248 ns slack) — the rPLL cannot do a clean 25 MHz out (VCO = 25×ODIV_SEL ≤ 400 < 500 floor). Note Gowin's "Actual Fmax" tracks the constraint effort — a lower target yields a realized Fmax just above it, not the design's true headroom. A/B test proved regfile primitive is NOT the limiter (BSRAM vs `syn_ramstyle="registers"` — identical Fmax); real critical path is route-dominated (~65% route). `rstn_i`/`led_o` false-path.

No lint config. Verilator sim in `sim/` (functional), `sim/hw/native_mem_tb/` (native RAM protocol compliance), `sim/hw/ram_tb/` (AXI4-Lite protocol compliance), and `sim/cosim/quicksort/` (RTL vs Spike golden ISA ref).

## Simulation (Verilator)

`sim/` builds fetch+decode+execute+native I/D-mem+peri bridge (Harvard), logs fetch/decode/execute activity. Requires `apt-get install verilator`. Built with `--public-flat-rw` (CPU has no per-stage debug ports). Harvard-only (the legacy `VON_NEUMANN=1` build has been dropped).

- `sim/sim_top.sv` — wrapper mirroring `top_module`; preloads native I-mem/D-mem via `$readmemh(iinit_file,u_imem.mem)` / `$readmemh(dinit_file,u_dmem.mem)`, plusargs `+IINIT=<path>` (default `imem.hex`) / `+DINIT=<path>` (default `dmem.hex`). Exposes a `PROBE_LEN`-word D-mem window as scalar wires for VCD tracing (32 words @ word 0x800 = D-mem 0x2000). Wires `axi_bus_peri`→`axi4_lite_xbar_3`→`axi4_lite_uart`+`clint_timer`+`msip_peri` (same windows as the board top, taken from the `rv32_pkg` base/size constants). The UART's `rxd_i` is tied idle-high here (no RX stimulus in this harness), so a program that blocks in `uart_getc()` never advances.
- `sim/sim_main.cpp` — drives clk/rst, 3 log passes (fetch/decode/execute-retire+writeback). Reads internal taps (`fe_pc`, `de_pc`, `ex_pc`/`ex_valid`, `wb_en`/`wb_addr`/`wb_data`) via `Vsim_top___024root.h` + `TAP()` macro. wb sampled pre-edge (comb from `de_q`), `ex_valid` post-edge. Writes `sim/sim_top.vcd`. GTKWave mnemonic decode via `sim/gtkwave_alu_op.txt` / `gtkwave_opcode.txt`. Run stops on park detection (8 identical retires) or `MAX_CYC` (default 4000). `STAP()` macro samples `dbg_stall_o` and prints a stall breakdown (RAW bubble / DIV-REM hold / LSU wait %).
- `sim/imem.hex` + `sim/dmem.hex` — hand-crafted Harvard oracle: RAW hazards (ALU-RAW, div-then-dependent, branch-on-dependent) — now resolved by the execute→decode forward path, not a stall interlock — plus LSU round-trip + load-use, byte/halfword sign/zero extend. Code in `imem.hex` (0x00-0x74, read-only I-mem); `dmem.hex` is an empty placeholder (oracle data runtime-written via stores to D-mem 0x100+).
- `sim/program.hex` — von-Neumann single-image oracle (legacy build dropped; file kept on disk, unused).
- `sim/Makefile` — `make run` (default Harvard oracle); `RUN_ARGS="+IINIT=... +DINIT=..."` for C programs.
- `sim/sw/` — C→two images via `riscv32-esp-elf-gcc` 14.2.0 (`-march=rv32imac -mabi=ilp32 -nostdlib -ffreestanding`, `medlow` absolute addressing, link script splits `.text`→IMEM ORIGIN=0 / `.data`→DMEM ORIGIN=0x2000). Output `imem.hex` + `dmem.hex` (bin2hex `--base 0x2000` lands `.data` at D-mem 0x2000). Default `main.c`: recursive quicksort over 32-int array, returns `0x600D` (sorted) or `0xBAD` (broken). `-march=rv32imac` doesn't emit Zilx — that stays covered by `imem.hex`/`dmem.hex`.

```bash
cd sim && make run                    # Harvard oracle (imem.hex/dmem.hex)
make sw-run                           # build C prog + run (from repo root)
```
Build artefacts gitignored.

### Co-sim vs Spike (`sim/cosim/quicksort/`)
Runs the same C-built ELF on Spike (upstream `riscv-isa-sim`, `--log-commits`, built locally once via `build_spike.sh`) and on the Verilator RTL, then `cosim_diff.py` diffs per-retire architectural effects (pc + register write). Spike is the golden ISA ref; Zilx is already upstream (no patch). The RTL sim writes a per-retire trace to `RTL_TRACE` (`sim_main.cpp`), the diff driver skips Spike's boot-ROM stub and parks both sides at the halt self-loop. Harvard co-sim requires `.data` at a non-zero VMA (link.ld `DMEM ORIGIN=0x2000`) so Spike's unified address space holds `.text`@0 and `.data`@0x2000 disjoint — at VMA 0 the LOAD segments clobber each other. The cosim `SPIKE_MEM` (`0x0:0x1000` code, `0x2000:0xE000` data+stack) matches that split.
```bash
make cosim     # build sw + Spike, run both, diff -> "PASS -- matched N retires"
```

Run from `sim/`:

```bash
cd .. && make run RUN_ARGS="+IINIT=sw_trap/build/imem.hex +DINIT=sw_trap/build/dmem.hex"
```
`sim/cosim/ecall/` is the Spike cosim of a sync trap: a minimal illegal-instruction program (`ecall_test.S`, `.word 0x0000007f`), run on Spike + RTL, diffed with the shared `cosim_diff.py` (at `sim/cosim/cosim_diff.py`, symlinked into `sim/cosim/ecall/`). `make cosim` -> "PASS -- matched N retires" (the faulting instr is not retired in either model). ecall itself is **not** Spike-comparable (Spike hijacks an M-mode ecall as the htif host-call exit; MSIP has no Spike slave at 0x1000_0000), so those paths are covered only by the standalone oracle above.

### WFI-wake arbitration oracle (`sim/sw_wfi_trap/`)
Regression test for the WFI-halt deadlock. `wfi_halt_q` must clear on `int_pending`, not on `take_interrupt`: `take_interrupt` loses priority to a synchronous trap, so a faulting instruction sitting directly behind the `wfi` used to leave the halt flag set, and trap entry then cleared `mstatus.MIE` — dropping `int_pending`, re-asserting `wfi_stall`, and freezing the pipe inside the handler with no way to retire the CSR write that would re-enable interrupts (unrecoverable without reset).

`wfi_trap_test.S` arms `mtimecmp=400`, runs a 32-cycle `div` so fetch fills F/D + skid (without the run-ahead, D/E holds a bubble through the halt and the sync trap never races the interrupt — the case goes untested), then `wfi` followed immediately by `.word 0x0000007f`. On the wake the illegal trap wins arbitration (marker 2 at D-mem 0x2040, mepc advanced by 4), then the still-pending timer interrupt is taken (marker 7 at 0x2044, MTIP disarmed). `main` checks both markers and writes `0x600D` at D-mem 0x2000 or `0xBAD`.

`gen_hex.py` hand-encodes the same program so the regression runs without a RISC-V toolchain — keep it in sync with the `.S`. Run from `sim/`:
```bash
cd sw_wfi_trap && python3 gen_hex.py   # no toolchain needed ("make" uses gcc instead)
cd .. && make run RUN_ARGS="+IINIT=sw_wfi_trap/build/imem.hex +DINIT=sw_wfi_trap/build/dmem.hex"
```
`sim_main.cpp` also checks this invariant on **every** program, via the `wfi_halt_q` / `int_pending` taps: it prints `WFI-halt check: OK`, or `WFI-HALT FAIL` plus a nonzero exit if the halt stays set more than `WFI_STUCK_N` (default 64) cycles after an interrupt went pending, or more than `WFI_HALT_N` (default 4000) cycles with no wake at all. Against the pre-fix RTL this oracle hits the 80000-cycle bound at 99.9% stalled and reports `WFI-HALT FAIL`; post-fix it retires 80 instructions in 537 cycles and passes.

### Timer oracle (`sim/sw_timer/`)
`sim/sw_timer/timer_test.S` (built `-march=rv32imac_zicsr_zifencei`) is a standalone M-mode program exercising the machine timer interrupt: sets `mtvec` (direct), enables `mie.MTIE`+`mstatus.MIE`, arms `mtimecmp=200` (writes `mtimecmp_hi=0` then `mtimecmp_lo=200` at `0x1000_1008`/`0x1000_100C`), then `wfi`. The timer interrupt (`mcause=0x8000_0007`) wakes WFI (`mepc=wfi+4`); the handler stores the masked cause code (7) as a marker at D-mem 0x2040, clears MTIP by writing `mtimecmp=0xFFFFFFFF_FFFFFFFF`, and `mret`s. `main` self-checks the marker and writes `0x600D` at D-mem 0x2000 (pass, probe word 0x800) or `0xBAD`. Run from `sim/`:
```bash
cd sw_timer && make       # build build/imem.hex + build/dmem.hex
cd .. && make run RUN_ARGS="+IINIT=sw_timer/build/imem.hex +DINIT=sw_timer/build/dmem.hex"
```

## Architecture

Built bottom-up. Every RTL file: `import rv32_pkg::*;` + `` `resetall `` / `` `default_nettype none `` / `` `timescale 1ns/1ps ``.

### Naming
Ports `_i`/`_o`. Internal signals no prefix; flops `_q`, next-state comb `_d` (a stage's own pipeline reg keeps its stage sigil, e.g. `fe_pc_q`). Instances `u_*`. Stage debug taps prefixed `fe_`/`de_`/`ex_`, stay internal to the CPU (not exported; only `dbg_stall_o` is).

### Files
- **`rv32_pkg.sv`** — `XLEN=32`; `mem_req_t`/`mem_rsp_t` (direction-split AXI-style; `mem_rsp_t` has `wready`/`rvalid`/`rdata`/`bvalid`). `PERI_ADDR_BIT`=28; peri window constants `UART_BASE`/`UART_SIZE`=0x1000_0000/4K, `MTIMER_BASE`/`MTIMER_SIZE`=0x1000_1000/8K, `MSIP_PERI_ADDR`/`MSIP_PERI_SIZE`=0x1000_3000/4K (the board top and sim top pass these to the peri xbar, so the map lives in one place). Decode types: opcode localparams (incl `OPC_AMO` for Zilx), `alu_op_t` (incl `ALU_LX`), `wb_src_t` (incl `WB_CSR`), `csr_op_t`/`csr_addr_t` (MSTATUS/MISA/MIE/MTVEC/MSCRATCH/MEPC/MCAUSE/MTVAL/MIP/MCYCLE/MINSTRET), `sys_op_t` (NONE/ECALL/EBREAK/MRET/WFI/FENCE/FENCE_I), `MCAUSE_*` codes (ILLEGAL=2/BREAKPOINT=3/LAD_MIS=4/SAD_MIS=6/ECALL_M=11/MSI=0x8000_0003/MTI=0x8000_0007/MEI=0x8000_000B), `MSTATUS_MIE_BIT`/`MPIE_BIT`/`MPP_HI`/`MPP_LO`/`MSTATUS_MPP_M`(=2'b11)/`MSTATUS_RESET`(=0x0000_1800, MPP=M), `MTVEC_DIRECT`/`MTVEC_VECTORED`. packed `de_t` D/E struct (adds `sys_op`/`exception`/`exception_cause`/`exception_tval` to the csr fields).
- **`fetch_stage.sv`** — PC + F/D reg + 1-entry skid buffer (2-deep FIFO), single-outstanding overlap-prefetch. Run-ahead response landing while F/D full goes to skid, freeing the I-mem port (Harvard) / shared bus (von-Neumann). `stall_i` (decode) / `branch_valid_i`+`branch_addr_i` (execute redirect, incl. trap/mret/interrupt) wired at CPU top.
- **`decode_stage.sv`** — RV32I+M+C+Zilx+Zicsr. Expand-then-decode-uniformly (`c_expand()` turns RVC→32-bit, one decoder for both); hold buffer stashes upper compressed half. Zilx (`OPC_AMO` funct5 10010/11010; 11110 illegal) swaps rs1/rs2, computes `mem_shamt`. Zicsr (`OPC_SYSTEM` funct3≠0): decodes to `csr_op`/`csr_wren`/`csr_addr`, `wb_src=WB_CSR`; imm variants carry zimm in `imm`. `OPC_SYSTEM` funct3=0: ecall/ebreak/mret/wfi decode to `sys_op` (legal, not illegal) — execute takes the sync trap / mret / WFI-halt. `OPC_MISC_MEM` (Zifencei): fence/fence.i decode to `sys_op` (legal nop). Unknown opcode/bad encoding → `dec_illegal=1`, `exception_cause=MCAUSE_ILLEGAL`, `exception_tval`=faulting instr — execute raises the illegal-instruction trap. `stall_o` = hold-term | execute stall (`stall_i`: DIV/REM busy / mem-wait) | WFI-halt — **no RAW term** (forwarding resolves it); `flush_i` kills D/E on branch/trap/mret/interrupt. **Execute→decode forwarding**: `fwd_rs1`/`fwd_rs2` (`ex_wb_en_i` & `ex_wb_addr_i`≠x0 & source addr matches retire dest) inject `ex_wb_data_i` into the D/E operands (`de_d.rs1_data`/`rs2_data`) instead of the stale async regfile read — distance-1 RAW (ALU, DIV/REM, load-use) resolved same-cycle, zero bubble. Distance-2+ hazards read the regfile after the write committed. The legacy `raw_haz` bubble interlock is disabled (commented out).
- **`reg_file.sv`** — 32×32 BSRAM, async read ×2 / sync write ×1, x0 hardwired. Confirmed NOT the Fmax limiter (A/B vs `registers` style, identical within noise — registers form costs +992FF/+1128LUT for nothing). No runtime reset on `regs` (BSRAM single write port can't clear all 32 words/cycle; forcing it broke timing) — sim zero-inits via `` `ifdef VERILATOR ``; HW relies on BSRAM power-up + write-before-read (arch-legal).
- **`csr_regfile.sv`** — 11-entry Zicsr machine-mode subset (mstatus/misa/mie/mtvec/mscratch/mepc/mcause/mtval/mip + mcycle/minstret). Async read (decode addr) + sync write (execute RMW). Unimplemented addrs read 0 / ignore writes. `mcycle`/`minstret` free-running perf counters, also CSR-writable; branch/jump retire inputs wired but unused (reserved for future `mhpmcounter`). **Trap-write bundle** ports (we/d for mepc/mcause/mtval/mstatus, from the trap unit, priority over RMW) + `msip_i` (drives mip.MSIP, read-only from CSR write — cleared via the MMIO slave) + `mtip_i` (drives mip.MTIP, read-only from CSR write — cleared by writing `mtimecmp > mtime`) + combinational taps `mtvec_o`/`mepc_o`/`mstatus_o`/`mip_o`/`mie_o` for the trap unit. `meip_i` (drives mip.MEIP from the board's peripheral IRQ OR-tree); `mstatus` RMW forces MPP=2'b11 (M, WARL — the only implemented mode) and mstatus resets to `MSTATUS_RESET`; `mtvec` RMW masks MODE to {0,bit[0]}; `mepc`/`mcause`/`mtval` RMW yield to the trap-write port.

- **`trap_unit.sv`** — combinational exception/interrupt entry + mret return, a peer of execute at the CPU top. Consumes CSR taps (mtvec/mepc/mstatus/mip/mie) + execute-resolved triggers/payload (sync_trap/mret/take_interrupt, cause/tval/pc), produces the fetch redirect (mtvec BASE, or BASE+4*code for a vectored interrupt, or mepc for mret) and the CSR trap-write bundle (mepc/mcause/mtval/mstatus). `int_pending_o` = `mstatus.MIE & (MSIP&MSIE | MTIP&MTIE)`; `int_cause_o` selects MSI>MTI priority (MEI not wired) — execute uses it as the interrupt mcause (no loop — depends only on CSR taps). mstatus field semantics: entry MPIE←MIE/MIE←0/MPP←00; mret MIE←MPIE/MPIE←1/MPP←00.
- **`execute_stage.sv`** — selects operands, drives DIV/REM + LSU via unified FSM (`EX_IDLE`/`EX_DIV_BUSY`/`EX_MEM_WAIT`), writes back ALU/PC4/load/old-CSR, resolves branches + fetch redirect, drives native LSU port, does the CSR RMW. Loads/stores/Zilx launch in `EX_IDLE`, stall in `EX_MEM_WAIT` until retire (`rvalid`/`bvalid`). **Posted store**: a store retires on launch-accept (`wvalid && wready && we`) and commits same clock edge — native D-mem 1-cyc, peri via the bridge. Loads wait in `EX_MEM_WAIT` until `rvalid` (native D-mem: 1-cyc; peri: multi-cycle). `mem_rsp_i.bvalid` is 0 from native RAM (no B channel); the bridge asserts `bvalid` on its B handshake (unused by the posted-store path but present). LSU steers `addr[PERI_ADDR_BIT]` itself: `0` → native D-mem, `1` → peri bridge. CSR: `csr_new` = RW:src / RS:`old|src` / RC:`old&~src`; write gated on retire predicate AND (RS/RC) `src!=0`. Load alignment: shift by `addr[1:0]`, sign/zero-extend per size. **Trap machinery**: `freeze = stall_i | wfi_stall` (WFI-halt); sync traps (illegal/ecall/ebreak/misaligned) fire in `EX_IDLE` (misaligned never launches) — `sync_trap_req` exports to the trap unit, normal wb/mem/csr/branch suppressed; `mret` retires (counts) + redirects to mepc; `take_interrupt` at a retire boundary suppresses the next normal instr (re-runs after mret) OR on a WFI wake (`wfi_halt_q`, mepc=wfi+size); WFI retires once then halts until `int_pending`. A trapping instr is **not** retired (`op_commits`=0 for sync_trap/interrupt; mret + normal retire commit) — matches the RISC-V spec + Spike. Trap/mret/interrupt redirect merges with the normal branch on `branch_valid_o`/`branch_addr_o`. Exports `ex_wb_en_o`/`ex_wb_addr_o`/`ex_wb_data_o` to decode the same cycle a writeback retires, feeding the forward path (see decode_stage).

Three ports (Harvard): native `imem`/`dmem` + AXI4-Lite `axi_peri`; the peri `axi4_lite_master_bridge` lives inside the CPU. Plus `msip_i`/`mtip_i` (machine software/timer-interrupt pending, from the board's `msip_peri`/`clint_timer` slaves). `trap_unit` is a combinational peer of execute: execute exports sync_trap/mret/take_interrupt triggers + cause/tval/pc, imports `int_pending` + `int_cause` + `trap_redirect_addr`; the trap unit drives the CSR trap-write bundle (back to `csr_regfile`) + the fetch redirect (merged with the normal branch on `branch_valid`/`branch_addr`). Only non-bus output: `dbg_stall_o`.

Reset sync gated on `pll_lock`. (Comfortable fallback: drop the rPLL, `clk_core = clk_i = 25 MHz`, +2.248 ns slack — see Constraints.) Harvard: native `u_imem` (read-only) on `CPU.imem`, native `u_dmem` (byte-strobed) on `CPU.dmem`, `axi_bus_peri`→`axi4_lite_xbar_3`→`uart_i` (`axi4_lite_uart`, `UART_BASE`) + `u_timer` (`clint_timer`, `MTIMER_BASE`) + `u_msip` (`msip_peri`, `MSIP_PERI_ADDR`); their `msip_o`/`mtip_o`/`uart_irq_o` feed `CPU.msip_i`/`CPU.mtip_i`/`CPU.meip_i`. `localparam CLK_CORE_HZ = 35_000_000` feeds the UART's `CLK_FREQ_HZ` — it MUST track the PLL setting, or the baud rate is wrong. `uart_rxd_i` is double-flopped (`uart_rxd_sync_q`) before reaching the UART: the far-end transmitter has its own oscillator, so the pin is asynchronous even though the fabric is single-domain. `led_o[0]`=stall, `led_o[3:1]`=free-running counter.
- **`native_ram.sv`** (utils) — Harvard native `mem_req_t`/`mem_rsp_t` slave, `READ_ONLY` param (1=I-mem, 0=D-mem), byte-strobed D-mem write. Mirrors `axi4_lite_ram`'s handshake: `wready = !rvalid_q || (rvalid_q && rready)` (accept when no unread response held, or while draining), `rvalid` registered & held until `rready` (not a 1-cycle pulse), `bvalid=0` (native RAM has no B channel — LSU uses posted store). No addr latch: read-launch latches `rdata_q` at the accept cycle.
- **`msip_peri.sv`** (utils) — AXI4-Lite MMIO slave, 1-bit MSIP register at `MSIP_PERI_ADDR` (`0x1000_3000`). Write bit[0] sets/clears `mip.MSIP`; reads return `{31'b0, msip}`; `msip_o` → `csr_regfile.msip_i`. Protocol mirrors `axi4_lite_ram` (registered BVALID held until B handshake, RVALID held until RREADY, single-outstanding).
- **`clint_timer.sv`** (utils) — AXI4-Lite CLINT timer MMIO slave (`MTIMER_BASE` `0x1000_1000`, 8 KiB window). 64-bit free-running `mtime` (RO, +1/cycle) + 64-bit `mtimecmp` (RW, reset all-ones so `mtip=0` at boot), exposed as four 32-bit words (`mtime_lo/hi` @ +0/+4, `mtimecmp_lo/hi` @ +8/+0xC, decode `addr[3:2]`); `mtip_o = mtime >= mtimecmp` → `csr_regfile.mtip_i` (mip.MTIP). **The 64-bit compare is two-stage pipelined**: stage-1 registers two parallel 32-bit compares (`ge_hi`/`eq_hi` on the high halves, `ge_lo` on the low halves — both sample the same cycle-T `mtime`/`mtimecmp`), stage-2 combines `ge_hi | (eq_hi & ge_lo)` into `mtip_q`. This cuts the 64-bit carry chain (~26 logic levels) off the timing path; `mtip_o` is delayed 2 cycles vs `mtime` (harmless for a level interrupt). Same AXI skeleton as `msip_peri` (latches `awaddr`/`araddr` for the decode). `mtime` writes ignored (RO). Software must arm `mtimecmp` in the order hi=all-ones, lo, then the real hi — the compare is only reachable as two 32-bit words, so lo-before-hi can fire a spurious MTIP in the gap.
- **`axi4_lite_master_bridge.sv`** — `mem_req_t`/`mem_rsp_t`↔AXI4-Lite, single FSM, single outstanding. `rsp_o.bvalid` asserted on B handshake (store retire). Now peri-only (inside the CPU in the Harvard build; the sole CPU→bus bridge in von-Neumann).
- **`axi4_lite_xbar.sv`** — 1→2 crossbar, routes by `addr[SEL_BIT]` (default bit 28). Per-direction target latch, single-outstanding pass-through, no comb loop. No longer instantiated anywhere (the peri mux is the 1→3 variant now); kept for reuse.
- **`axi4_lite_xbar_3.sv`** — 1→3 crossbar, routes by three compile-time BASE/SIZE windows. Same single-outstanding pass-through style as the 1→2. A peri address matching no window is completed by a local **decode-error terminator** (BRESP/RRESP = DECERR, RDATA = 0) rather than left with ready low — the LSU routes the whole `0x1000_0000..0x1FFF_FFFF` region here on `addr[PERI_ADDR_BIT]` while only three windows are mapped, so an unmapped access used to park the LSU in `EX_MEM_WAIT` forever.
- **`mem_arbiter.sv`** — **deleted** (was the fetch/LSU arbiter for the dropped VON_NEUMANN build; Harvard gives fetch its own I-mem port).
- **`axi4_lite_ram.sv`** — AXI4-Lite slave, single-beat, protocol-compliant (verified by `ram_tb`). BVALID registered & held until B handshake (the fix vs a naive combinational version). Single-outstanding, byte-strobed via BSRAM byte enables. Von-Neumann mem slave / Harvard peri-side (kept on disk, reusable).

### Fetch behaviour
2-deep FIFO (F/D head + 1-entry skid tail). Issues (`wvalid`) only when FIFO has room; accepts responses (`rready`) whenever there's room — response lands in skid if F/D is full. Harvard: fetch owns the I-mem port uncontended, so the skid's job is just F/D-head-stalls overlap, not bus-arbitration safety. Von-Neumann: the skid frees the shared bus for the LSU (avoids a starvation deadlock). ~2 cyc/instr steady state (single-outstanding native I-mem). Skid gave 15-20% cycle-count improvement over a no-skid gate fix (measured on oracle + Zilx quicksort). Redirect kills F/D+skid, marks in-flight discarded, sets new `pc_q`. Compressed: fetch always reads 32-bit words; decode handles expansion/odd-half alignment.

### Decode behaviour
Source priority: spanning stitch > compressed hold > odd-half target > fresh low half. **RVC spanning** (32-bit instr split across a word boundary) is handled: low half stashed, stitched with next word's upper half when it arrives (one bubble, `span_wait`). Odd-half branch targets that are 32-bit instrs stitch the same way. `decoded_valid` excludes wait states so neither a spurious valid nor a false RAW trigger occurs. Deferred (`illegal=1`, now traps in execute): unknown opcode / bad encoding (`exception_cause=MCAUSE_ILLEGAL`, `exception_tval`=instr), `OPC_AMO` funct5 11110 / sfence.vma (no VM yet — traps as illegal). Legal (decode to `sys_op`, retire in execute): ecall/ebreak/mret/wfi/fence/fence.i. Zicsr ops decode and retire fully.

### Hazard resolution (execute→decode forwarding, in decode_stage)
`fwd_rs1`/`fwd_rs2` fire when execute retires a writeback (`ex_wb_en_i`) to a register the instruction being decoded reads (`rs1_addr_dec`/`rs2_addr_dec` match `ex_wb_addr_i`, x0 excluded). On hit: inject `ex_wb_data_i` into the D/E operands (`de_d.rs1_data`/`rs2_data`) instead of the stale async regfile read — the consumer captures the fresh value the same cycle the producer retires, **zero bubble**. Covers ALU-RAW, div-done-then-use, branch-on-dependent, and load-use (the load's `EX_MEM_WAIT` holds the consumer in decode via `stall_i` through the whole wait window; the load's `wb_en` pulse — valid exactly the cycle `rvalid` retires — drives the forward, no extra bubble). Distance-2+ hazards are harmless: the producer already wrote the regfile, so decode's async read returns the committed value. The legacy `raw_haz` bubble interlock (bubble D/E + hold F/D one cycle, re-read after commit) is **disabled** (commented out) — no longer needed.

**Known limitations:**
- Forward path is distance-1 only (single in-order retire slot). Distance-2+ rely on the regfile write having committed before the async read — correct only because execute retires at most one writeback/cycle in order; no out-of-order or multi-writeback window to miss.
- Machine-mode traps only (no S/U mode, no medeleg/mideleg, no PMP). No instruction-access-fault / instruction-address-misaligned traps. Cross-word sub-word accesses unhandled (the misaligned trap fires on the EA, not a precise sub-word fault). Timer interrupt sourced (`clint_timer` → `mip.MTIP`) and external interrupt sourced (peripheral IRQ OR-tree → `CPU.meip_i` → `mip.MEIP`; only the UART raises one today — no PLIC, so an ISR must poll the peripherals to find the source). Unimplemented CSR addresses still read 0 / ignore writes instead of raising an illegal-instruction trap.
- WFI halts forever if no enabled interrupt ever arrives (legal). `fence.i` is a nop (Harvard has no D→I write path — self-modifying code unsupported); `fence` is a nop.
- Harvard: I-mem holds `.text`/`.text.init` only (fetch port, read-only); `.rodata`/`.data`/`.bss`/stack live in D-mem (LSU port). `.data` is linked at DMEM ORIGIN 0x2000 (not 0) so the von-Neumann co-sim golden model (Spike) can hold `.text`@0 and `.data`@0x2000 disjoint in its single address space — at VMA 0 they'd clobber. `medlow` absolute addressing required (not `medany` — PC-relative `.text`→`.data` offsets would land in I-mem, not D-mem).
