## Project

RV32IMAC + Zicsr + Zifencei RISC-V core for a **Gowin GW2AR-18C** FPGA (`GW2AR-LV18QN88C8/I7`, QFN88) on a Tang Nano 20k board. Clock: **25 MHz single-ended** from an MS5351M generator (CLK0, PIN10, LVCMOS33) — not the stock 27 MHz oscillator.

Pipeline status: **fetch, decode, execute + LSU implemented** (reaches E/M register, writes back to reg file; loads/stores/Zilx indexed loads launch + retire via the shared imem bus). Execute drives regfile writeback, fetch redirect, decode stall/flush, the LSU, and a **stall-on-RAW hazard interlock** (no bypass path). No trap/exception support — a misaligned access is suppressed (not launched, not retired), not trapped.

CPU exposes ONE AXI4-Lite master, `bus_axi`, carrying all memory traffic — von Neumann fetch+data (fetch and the LSU share one port through a `mem_arbiter`, LSU priority) AND memory-mapped-peripheral accesses. Native `mem_req_t`/`mem_rsp_t`→AXI4-Lite conversion happens inside the CPU (one `axi4_lite_master_bridge`). The board top routes `bus_axi` through a 1→2 `axi4_lite_xbar` that splits mem vs peri by address (`addr[PERI_ADDR_BIT]`, bit 28 → peri at `0x1000_0000+`): `m_mem_axi`→`axi4_lite_ram`, `m_peri_axi`→open peripheral bus (UART/GPIO slave not instantiated yet). The CPU is agnostic to mem-vs-peri; address decode is the board top's job. The only non-bus CPU output is `dbg_stall_o` (aggregate pipe-stall status → board LED0); all per-stage pc/instr/valid/writeback taps stay **internal** (the sim probes them via the Verilator hierarchy, not through CPU ports).

**Key files:**
- `src/rtl/core/top_module.sv` — board top (`module top_module`)
- `src/rtl/core/rv32imac_zicsr_zifencei.sv` — CPU top (`module rv32imac_zicsr_zifencei`)
- `src/rtl/bus/axi4_lite_xbar.sv` — 1→2 AXI4-Lite crossbar (mem/peri address decode, in board top)
- `rv32imac_Zicsr_Zifencei.gprj` — Gowin IDE project
- `impl/rv32imac_Zicsr_Zifencei_process_config.json` — synth config (`TopModule`)
- `impl/gwsynthesis/`, `impl/pnr/` — synth/PnR outputs (PnR gitignored, regenerable)

### Constraints (`src/phys/`)
`.cst`: `clk_i`→PIN10 (25 MHz, MS5351M CLK0, LVCMOS33 — 3 independent CMOS clocks, no LVDS); `rstn_i`→PIN88 (async, active-low); `led_o[0:3]`→PIN15-18 (`led_o[0]`=`dbg_stall_o` stall indicator, `led_o[3:1]`=free-running counter alive indicator).

`.sdc`: `clk25` @25 MHz on `clk_i`; generated `clk_core` @50 MHz (`-multiply_by 2 -divide_by 1`) — sole timing-critical clock, whole fabric runs on it. Target lowered 100→50 MHz. PnR closes at ~50.15 MHz Actual Fmax (≈0.060 ns slack at 50 MHz target; varies ~±0.1 MHz run-to-run from PnR placement-seed non-determinism). An A/B run proved the **regfile primitive is NOT the limiter**: BSRAM (`ram_style="block"`) measured 50.151 MHz, `syn_ramstyle="registers"` (FF+LUT-mux async read, +992 FF/+1128 LUT) measured 50.150 MHz — identical within noise. The real critical path is route-dominated (~65% route) and lies elsewhere (execute/ALU/decode combinational depth), not the BSRAM async read. `rstn_i`/`led_o` marked false-path.

No lint config. Verilator sim in `sim/` (functional) and `sim/ram_tb/` (AXI4-Lite protocol compliance).

## Simulation (Verilator)

`sim/` builds fetch+decode+execute+arbiter+bridge+RAM (not in synth file list), logs fetch/decode/execute activity. Requires `apt-get install verilator`. Built with `--public-flat-rw` so the C++ harness can probe CPU-internal nets directly (the CPU exports no per-stage debug ports).

- `sim/sim_top.sv` — wrapper mirroring `top_module` wiring; preloads RAM via `$readmemh`, plusarg `+INIT=<path>` (default `program.hex`). Ports only `clk_i`/`rstn_i`/`led_o` (the CPU's `dbg_stall_o` is sunk to `unused_dbg_stall`, which `sim_main.cpp` samples for the stall breakdown). A generate block exposes a `PROBE_LEN`-word window of `u_ram.mem` (default 16 words at `PROBE_BASE_WORD`=63, i.e. 0xfc — the quicksort `.data` array) as scalar `mem_probe_w` wires so the data lands in the VCD (Verilator does not trace unpacked arrays past `--trace-max-array`); watch it sort in GTKWave at `sim_top.g_mem_probe[<i>].mem_probe_w`.
- `sim/sim_main.cpp` — drives clk/rst, prints 3 logs (fetch, decode, execute-retire+writeback), each its own reset+run pass (stages lag by 1 cycle). The CPU exports no debug ports, so the harness reads the per-stage taps (`fe_pc_w`/`fe_valid_w`, `de_pc_w`, `ex_pc_w`/`ex_valid_w`, `wb_en`/`wb_addr`/`wb_data`) as flat members of the Verilator root object via `#include "Vsim_top___024root.h"` and the `TAP(field)` macro → `top->rootp->sim_top__DOT__u_cpu__DOT__<field>`. The execute pass logs the writeback value (`wb x<n> = 0x...`) by sampling `wb_en`/`wb_addr`/`wb_data` on the clock low half (wb is combinational from `de_q`, so pre-edge sampling aligns the value with the retiring op; `ex_valid` is registered, sampled post-edge) — this makes the RAW interlock and the LSU load-use path verifiable (dependent ops write the correct value; a one-cycle bubble precedes each hazard consumer). Writes `sim/sim_top.vcd` (full hierarchy trace, `--trace`). Decode internals (`u_decode.opcode`, `alu_op`, `funct3/5/7`, `imm_*`, etc.) are named in VCD though not ports (`de_t` flattened to 202-bit unless `--trace-structs`). GTKWave mnemonic decode: Data Format→Bin, then Translate Filter File pointed at `sim/gtkwave_alu_op.txt` / `gtkwave_opcode.txt` (must reapply if signal re-added). The run stops early on park detection (8 consecutive identical retires — the `start.S` `1: j 1b` self-loop); a `MAX_CYC` env var (default 4000) bounds programs that never park (e.g. `MAX_CYC=20000 make run`). A `STAP(field)` macro (sibling of `TAP`) reads sim_top-level nets (not inside `u_cpu`); it samples `unused_dbg_stall_o` (the `dbg_stall_o`=`dec_stall|ex_stall` sink) each cycle and prints a `stalled N/M cycles (P%)` breakdown at exit — the RAW-hazard bubble, DIV/REM hold, and LSU `EX_MEM_WAIT` costs per run.
- `sim/program.hex` — hand-crafted oracle (one 32-bit hex word/line). Part 1 exercises the RAW interlock's three paths: ALU-RAW (`add a0,t0,t1` after `addi t1`), div-then-dependent (`addi t4,t3,1` after `div t3`), and branch-on-dependent (`bne t5` after `addi t5`, taken ⇒ skips a not-taken marker). Part 2 exercises the LSU via the shared imem bus: SW/LW round-trip + load-use (`a4=a3+1` after `lw a3`), byte sign/zero extend (`lb`/`lbu` of an `sb`'d 0xAB), halfword at offset 2 (`lh`/`lhu` of an `sh`'d 0x8000). Data lives at 0x100+ (von Neumann: code 0x00-0x58, data separate so stores never clobber the program). Verified against the retire+writeback log.
- `sim/Makefile` — `make run` (builds+runs from `sim/`); `RUN_ARGS="+INIT=sw/build/program.hex"` loads a C-compiled program. RTL list includes `mem_arbiter.sv` + `axi4_lite_xbar.sv`; VFLAGS includes `--public-flat-rw`.
- `sim/sw/` — C→`program.hex` flow using `riscv32-esp-elf-gcc` 14.2.0 (found automatically under the ESPHome PlatformIO toolchain path). `-march=rv32imac -mabi=ilp32 -nostdlib -ffreestanding`, linked at 0x0, `objcopy`→`bin2hex.py`→hex. Stores/loads now retire (LSU live), so C programs that touch memory are correctness-checkable, not just smoke tests. `make show` disassembles ELF. The default `main.c` is a recursive quicksort over a 16-int `.data` array (Lomuto partition, `volatile` to defeat constant-folding); it exercises array load/store, stack spill/fill from recursion, and branches on loaded values, then verifies ascending order and returns `0x600D` in `a0` (sorted) or `0x00000BAD` (broken). `-march=rv32imac` does NOT emit Zilx indexed loads; those stay covered by the hand-crafted `sim/program.hex` oracle.

```bash
cd sim && make run                    # oracle program
make sw-run                           # build C prog + run (from repo root)
make sw && cd sim && make run RUN_ARGS="+INIT=sw/build/program.hex"
```

## Architecture

Built bottom-up. Every RTL file: `import rv32_pkg::*;` + `` `resetall `` / `` `default_nettype none `` / `` `timescale 1ns/1ps `` — match in new files.

### Naming conventions
- Ports: `_i`/`_o` suffix.
- Internal signals: no prefix. Flops end `_q`, next-state comb `_d` (e.g. `pc_q`/`pc_d`). Exception: a stage's own output pipeline register keeps that stage's sigil (e.g. `fe_pc_q`) to disambiguate from other same-named flops.
- Instances: `u_*`.
- Types/params/localparams/enum labels/AXI member names: own convention (AXI follows spec).
- **Stage debug taps:** each stage exposes PC/instr/valid, prefixed by producing stage's sigil — `fe_`/`de_`/`ex_`. Consuming inputs use the producer's sigil (e.g. decode's `fe_*_i`). These taps stay **internal to the CPU** — they are NOT exported through `rv32imac_zicsr_zifencei`'s ports (the only CPU output besides the two AXI masters is `dbg_stall_o`, an aggregate stall-status bit). The board top sinks `dbg_stall_o` to `led_o[0]`; the sim probes the internal taps via the Verilator hierarchy (`--public-flat-rw`), not through ports.

### Files
- **`src/rtl/pkg/rv32_pkg.sv`** — `XLEN=32`, `mem_req_t`/`mem_rsp_t` (direction-split, AXI-style; launch=`req.wvalid&&rsp.wready`, read=`rsp.rvalid&&req.rready`, store-retire=`rsp.bvalid`). `mem_rsp_t` has `wready`/`rvalid`/`rdata`/`bvalid` (bvalid = write-ack this cycle, added with the LSU so a store retires on the B handshake). `PERI_ADDR_BIT` = 28 (the address bit the board-top crossbar uses to split mem vs peri; `addr[PERI_ADDR_BIT]=1`→peri at `0x1000_0000+`, `=0`→mem; moveable here so the map lives in one place). Decode types: opcode localparams (incl. `OPC_AMO` for Zilx), `alu_op_t` (19 vals/5b, incl `ALU_LX`), `branch_t`, `alu_src_a_t`/`alu_src_b_t` (incl Zilx base/index selects), `wb_src_t`/`mem_size_t`, packed `de_t` D/E struct (`valid/pc/instr/is_compressed/rs1_addr/rs2_addr/rs1_data/rs2_data/imm/rd/reg_write/alu_op/alu_src_a/alu_src_b/mem_read/mem_write/mem_size/mem_unsigned/wb_src/branch_type/mem_shamt/illegal`).
- **`fetch_stage.sv`** — owns PC + F/D register (`fe_pc_o`/`fe_instr_o`/`fe_valid_o`) and a 1-entry skid buffer. Native imem interface, single-outstanding overlap-prefetch FSM (flags `busy_q`/`req_pc_q`/`flushed_q`, plus `skid_valid_q`/`skid_pc_q`/`skid_instr_q`; no `state_t`). Fetch runs ahead of decode into a 2-deep FIFO (F/D head + skid tail); a run-ahead response that arrives while F/D is full lands in the skid (freeing the single-outstanding shared imem bus for the LSU — the deadlock-free form of run-ahead). `stall_i` (from decode) and `branch_valid_i`/`branch_addr_i` (from execute redirect) wired in CPU top.
- **`decode_stage.sv`** — RV32I+M+C+Zilx indexed loads. Expand-then-decode-uniformly: `c_expand()` turns 16-bit RVC into 32-bit equivalent, one uniform decoder handles both. Hold buffer stashes upper half when low half is compressed. Reads `reg_file` async. Zilx (`OPC_AMO` funct5 `10010`/`11010`; `11110` RV64-only→illegal) swaps rs1/rs2, computes `mem_shamt`, emits `alu_op=ALU_LX`. `stall_o` feeds fetch (propagates execute div stall **and** the RAW hazard stall); `flush_i` kills D/E on branch. **RAW interlock**: `ex_wb_en_i`/`ex_wb_addr_i` (from execute's writeback) compared against decode's live source addresses → `raw_haz` bubbles the D/E register (`de_next='0`, not a hold — avoids execute re-run/div relaunch) and holds F/D one cycle so decode re-reads the regfile after the producer's writeback commits; `stall_o` adds the `raw_haz` term to back-pressure fetch. `OPC_MISC_MEM`/`OPC_SYSTEM`/unknown → `illegal=1`.
- **`reg_file.sv`** — 32×32, BSRAM (async-read, sync-write, `(* ram_style = "block" *)`, `Bsram=2`). 2 async read + 1 sync write port. `x0` hardwired zero. **Regfile primitive is NOT the Fmax limiter**: an A/B PnR run measured `clk_core` Actual Fmax at 50.151 MHz on BSRAM vs 50.150 MHz on `syn_ramstyle = "registers"` (FF + LUT-mux async read) — identical within PnR noise; the registers form costs +992 FF/+1128 LUT for no gain, so BSRAM is kept. `distributed_ram` (Gowin SSRAM) would be sync-read (SUG949E §8.2, 1-cycle latency) and breaks decode's same-cycle operand read — ruled out. **No runtime reset on `regs`**: a BSRAM primitive's single write port can't clear all 32 words in one cycle, and forcing an `if(!rstn_i) for(...) regs[i]<=0` loop made GowinSynthesis add LUT/FF/SSRAM logic to fake the clear, creating spurious DO→DI paths inside the memory primitive that blew setup timing — so the reset branch is intentionally omitted. Sim zero-inits via a `` `ifdef VERILATOR `` `initial` block (determinism); HW relies on BSRAM power-up INIT + write-before-read (arch-legal — RISC-V leaves regfile state undefined at reset, x0 excepted). `rstn_i` kept as a port for interface consistency, unused here. Write port driven by execute writeback.
- **`alu.sv`** — combinational: base RV32I + single-cycle MUL (DSP) + multi-cycle DIV/REM (32-iter restoring FSM, `start_i`/`result_valid_o`) + Zilx EA (`ALU_LX = operand_a + (operand_b << shamt_i)`, parens mandatory — `+` binds tighter than `<<`).
- **`execute_stage.sv`** — selects ALU operands, drives DIV/REM and the LSU through one unified FSM (`EX_IDLE`/`EX_DIV_BUSY`/`EX_MEM_WAIT`), writes back ALU/PC4/load results to regfile (stores carry no reg writeback), resolves branches + redirects fetch, drives the native `mem_req_o`/`mem_rsp_i` LSU port. Loads/stores/Zilx launch in `EX_IDLE` (`wvalid=1`), stall in `EX_MEM_WAIT` until the read response (`rvalid`, load) or write-ack (`bvalid`, store) retires them. Load alignment: shift the returned word down by `addr[1:0]` then sign/zero-extend per `mem_size`/`mem_unsigned`; store data pre-shifted into the addressed byte lanes with byte strobes. A misaligned access is suppressed (not launched, not retired — no trap). `ex_*` taps = E/M register. **Limitations:** no bypass path (the stall-on-RAW interlock in `decode_stage` resolves register AND load-use hazards by bubbling, not forwarding); no trap/exception (misaligned suppressed).
- **`rv32imac_zicsr_zifencei.sv`** — CPU top: `fetch_stage`+`reg_file`+`decode_stage`+`execute_stage`+`mem_arbiter`+1×`axi4_lite_master_bridge` (`u_bus_bridge`). Von Neumann: fetch (`fe_req`/`fe_rsp`) and the LSU (`lsu_req`/`lsu_rsp`) go through `u_mem_arbiter` (LSU fixed priority) → `imem_req`/`imem_rsp` → `u_bus_bridge` → `bus_axi` (the single AXI4-Lite master port — carries mem AND peri traffic; the board top's crossbar splits them). No `req_ready` wires (direction-split). Wires regfile write port, fetch redirect, decode stall/flush from execute; feeds execute's `wb_en`/`wb_addr` back into decode's `ex_wb_en_i`/`ex_wb_addr_i` (RAW interlock). Per-stage pc/instr/valid taps and the writeback nets (`wb_en`/`wb_addr`/`wb_data`) stay internal (left unconnected here); the sim probes them via the Verilator hierarchy. Only non-bus output: `dbg_stall_o` (=`dec_stall|ex_stall`).
- **`top_module.sv`** — board top. Clock tree: 25 MHz `clk_i`→rPLL (FCLKIN=25, IDIV=4, FBDIV=9, ODIV=16)→`clk_core`=50 MHz (VCO=800 MHz, in 500-1250 MHz range); 2-FF reset sync→`rstn_core`. **Single clock domain** (CPU+xbar+both AXI buses+RAM on `clk_core`) — no CDC. Topology: CPU `bus_axi`→`axi_bus_cpu`→`u_xbar` (`axi4_lite_xbar`, `SEL_BIT=PERI_ADDR_BIT`)→`axi_bus_mem`→`axi4_lite_ram` (von Neumann: instructions + data) and `axi_bus_peri` (slave tied off — reserved for future MMIO; drop in a UART/GPIO with no board-top change). `dbg_stall_o`→`led_o[0]` (stall indicator); `led_o[3:1]`=`led_cnt_q[27:25]` (free-running counter, alive indicator).
- **`axi4_lite_if.sv`** — interface (32b addr/data), `master`/`slave`/`trunk` modports.
- **`axi4_lite_master_bridge.sv`** — `mem_req_t`/`mem_rsp_t`→AXI4-Lite. Single FSM (`S_IDLE`/`S_RD_WAIT`/`S_WR_ADDR`/`S_WR_DATA`/`S_WR_WAIT`), single outstanding overall. `rsp_o.wready=(state==S_IDLE)`. Read: `req_i.rready`→`axi.rready` forwarded in `S_RD_WAIT`. Write: AW+W lock-step launch, `b_hs`→IDLE; `rsp_o.bvalid=b_hs` in `S_WR_WAIT` (symmetric with rvalid) so a store retires on the B handshake. `bready` held high.
- **`axi4_lite_xbar.sv`** — 1→2 AXI4-Lite crossbar (in board/sim top, NOT the CPU). Routes the CPU's single `bus_axi` to `m_mem_axi` (`addr[SEL_BIT]=0`) or `m_peri_axi` (`addr[SEL_BIT]=1`); `SEL_BIT` defaults to `rv32_pkg::PERI_ADDR_BIT` (bit 28 → peri at `0x1000_0000+`), overridable at instantiation. Single-outstanding pass-through (the CPU bridge is single-outstanding overall): no buffering/skid. Per-direction target latch (`wr_sel_q`/`rd_sel_q` + `wr_busy_q`/`rd_busy_q`) set on AW/AR handshake, cleared on B/R handshake; `awready`/`arready` gated by `!busy` so a second txn is not accepted in the same direction. Write ordering: on the launch cycle W routes by the live `awaddr` decode (matches the AW target); while busy W/B follow the latched `wr_sel_q`. The bridge asserts AW+W together but either may handshake first — both cases covered. No comb loop: slave ready outputs depend on the masters' register-based readys + this xbar's registered busy flags, never on the slave's own valids. Two named master ports (not an interface array) for Gowin-synth friendliness.
- **`mem_arbiter.sv`** — 2-master (fetch M0 low-pri, LSU M1 high-pri) → 1-slave native arbiter for the shared imem bridge. Re-arbitrates by priority every cycle the slave is free (`slv_rsp_i.wready=1`): grant LSU if it asserts `wvalid`, else fetch. The registered `owner_valid_q`/`owner_is_lsu_q` only routes the slave response back to the launcher during the busy stretch (set on a free-cycle launch, cleared when free with no new launch). Re-arbitrating every free cycle (NOT auto-relaunching the previous owner) is what stops fetch's continuous prefetch from starving the LSU — fetch.wvalid is almost always 1, so an "owner relaunches if still wvalid" rule would hand the bridge back to fetch forever.
- **`axi4_lite_ram.sv`** — AXI4-Lite slave single-beat RAM, protocol-compliant (verified by `ram_tb`). `ram_style=block`. Params `ADDR_W`, optional `INIT_FILE`. AW/W independent (holding regs `aw_seen_q`/`w_seen_q`), fires on both seen; **BVALID registered, held until B handshake** (the compliance fix — see ram_tb). Single-outstanding (awready/wready low while BVALID pending). Read: 1-cycle registered latency, arready depends only on regs+rready, RVALID held until rready. Sync active-low reset (mem contents not reset). Byte-strobed via BSRAM byte enables.

### Fetch behaviour
Overlap-prefetch, single-outstanding, with a 1-entry skid buffer. `pc_q` = next fetch addr (advances to next word boundary `(pc_q&~3)+4` on launch; overwritten on redirect — realigns after odd-half RVC redirect). `req_pc_q` = in-flight addr, stamped onto the captured word so the PC carried in the FIFO is exact. `busy_q` gates issue. Fetch is a 2-deep FIFO: head = F/D register (`fe_valid_q`/`fe_pc_q`/`fe_instr_q`), tail = 1-entry skid (`skid_valid_q`/`skid_pc_q`/`skid_instr_q`). `buf_room = !fe_valid_q || !skid_valid_q`. `imem_req_o.rready = flushed_q || buf_room` and `imem_req_o.wvalid = !busy_q && !branch_valid_i && buf_room` (both register-only, no comb loop): a read is issued only when the FIFO has a free slot, and a response is accepted whenever there is room. This is what keeps the shared imem bus drainable: a run-ahead response that arrives while F/D is full lands in the skid (`rready=1`), freeing the single-outstanding bus for the LSU immediately — instead of sitting on the bus with `rready=0` (which deadlocks: the undrainable fetch blocks the LSU, the LSU stall stalls decode, decode keeps F/D full, the response never drains). When the FIFO is full (2 words) fetch stops issuing and the bus is idle for the LSU. FIFO drain: a response lands in F/D if empty, else in the skid; decode consuming F/D promotes the skid into F/D the same cycle (no bubble); with F/D empty and no response the skid promotes on its own. ~2 cycles/instr steady-state (the bridge round-trip floor), with short decode stalls hidden behind the buffered words. Measured gain vs the no-skid "issue only when drainable" gate fix (no run-ahead): oracle 143→122 cyc (−14.7%), Zilx quicksort 3586→2865 cyc (−20.1%) — the skid hides the fetch round-trip behind buffered words so decode rarely waits on the bus. (The `stalled N/M` breakdown's stall count *rises* with the skid: the bubbles removed were fetch-latency idle cycles, not hazard stalls, so decode hits the real RAW/LSU hazards denser — but the total cycle count drops.) `fe_valid_o` held level until consumed or flushed; the skid is internal, never exported. Redirect (`branch_valid_i`, highest prio): kills F/D AND skid, marks in-flight `flushed_q=1`, sets `pc_q`=target; `wvalid` gated by `!branch_valid_i`, `rready` stays high to drain the flushed in-flight response and discard it. Compressed: fetch always reads 32b words; decode derives `is_compressed`/does expansion — fetch just aligns down on odd-half targets (`fe_pc[1]` tells decode which half). `stall_i`: F/D held (not consumed); fetch keeps running ahead into the skid (up to 2 words buffered), then stops issuing with the bus idle once the FIFO is full; any in-flight fetch is discarded on redirect.

### Decode behaviour
Expand-then-decode-uniformly (RV32I+M+C phase 1). `c_expand()` returns 0 for illegal encodings. Source-selection priority: spanning stitch > compressed hold > odd-half target > fresh low half; `is_compressed` recomputed from `hold_word_q[1:0]` for upper half. Odd-half branch target (`fe_pc[1]=1`): decode expands `fe_instr[31:16]` directly, doesn't stash (`target_upper` gates `buffer_upper` off); fetch's word-boundary advance realigns after. Uniform decoder extracts fields/immediates per opcode; `rs1/rs2_addr` forced `x0` when unused; `illegal` defaults 1, cleared by recognized opcodes, re-set only by `dec_illegal`. **RVC spanning (handled):** a 32-bit instr at a 2-byte-aligned but not 4-byte-aligned address (offset 2 of a fetch word) splits across two fetch words — low halfword = bytes 2-3 of word W (stashed in the hold buffer, recognized by `[1:0]==2'b11`), upper halfword = bytes 0-1 of word W+1. When W+1 arrives, the two are **stitched** into the full 32-bit instr (`{fe_instr[15:0], hold_word[15:0]}`) and decoded by the uniform decoder. No new flop: the compressed-vs-spanning distinction is derived from the stashed halfword's `[1:0]`. The stitch costs one bubble (`span_wait`: the cycle the low half is detected but W+1 is not yet in F/D — F/D is 1-deep so W+1 cannot be in F/D the same cycle as W; the 1-entry skid may already hold W+1, but it promotes to F/D only the cycle after W is consumed). Consecutive spanning instrs are handled (a stitch stashes W+1's upper half, which may itself be a spanning low half). An odd-half branch target that is a 32-bit instr (`fe_pc[1]=1` and `[17:16]==2'b11`) stashes the low half and stitches the same way (one bubble). `decoded_valid` = "a *complete* instr is available" (excludes `span_wait` and a just-stashed spanning target) — it feeds `de_d.valid` and the RAW interlock so neither wait state emits a spurious valid or false-triggers `raw_haz`. `stall_o = (hold_q && !hold_is_span && fe_valid_i) || stall_i || raw_haz` — the hold term fires for a compressed-upper hold alongside a fresh F/D word and is gated on `!hold_is_span` so a spanning stitch (which *consumes* W+1) does not false-stall fetch; `stall_i` carries execute's div stall, `raw_haz` is the RAW interlock (see **Hazard interlock behaviour**). Deferred (`illegal=1`): `OPC_MISC_MEM` (Zifencei), `OPC_SYSTEM` (Zicsr), atomics, unknown — JAL/JALR/compressed-jump variants still decode control despite no execute-time effect yet. **Pitfall:** `c.addi` (rs1=rd) vs `c.li` (rs1=x0); `c.addi16sp`(rd==x2) vs `c.lui` share quad1 funct3=011; `c.addi4spn` nzuimm==0 illegal; `c.mv`/`c.add` selected by `c[12]`, `rd==0` HINT→illegal; `c.jr`/`c.jalr`/`c.ebreak` selected by rs2==0.

### Execute behaviour
Operand select: `alu_src_a`∈{rs1,pc,rs2(Zilx base)}, `alu_src_b`∈{imm,rs2,pc4-link,0,rs1-shifted(Zilx index)}. `pc_link = pc + (compressed?2:4)`. Unified FSM `EX_IDLE`/`EX_DIV_BUSY`/`EX_MEM_WAIT`. DIV/REM: `alu_start` launches for 1 cycle when idle+not-stalled; `EX_DIV_BUSY` holds pipe until `result_valid_o`; done cycle drops stall without relaunch. LSU: a mem op launches in `EX_IDLE` (`mem_launch = valid & is_mem_op & ~mem_misaligned & EX_IDLE & ~stall_i`; `wvalid=mem_launch`), the FSM moves to `EX_MEM_WAIT` on the launch handshake, and `mem_done = EX_MEM_WAIT & (mem_read ? rvalid : bvalid)` retires it. `stall_o = alu_start | div_running | mem_launch | mem_running | stall_i` (`mem_running=EX_MEM_WAIT & ~mem_done`). `result_ready = is_mem_op ? mem_done : alu_result_valid`. Writeback: `wb_data`=alu_result/pc_link/load_data; `wb_en = valid & reg_write & ~illegal & ~stall_i & result_ready & ~mem_misaligned`. **`mem_misaligned` is gated by `is_mem_op`** — non-mem ops reuse `mem_size` as a don't-care decode default (MS_W) and must NOT be suppressed (a bare `|alu_result[1:0]` check would wrongly kill writebacks of any ALU op whose result has low bits set). Load alignment: `load_shifted = rdata >> {addr[1:0],3'b000}`, then sign/zero-extend per `mem_size`/`mem_unsigned` (MS_B/MS_H; MS_W=rdata). Store data: `store_wdata = rs2_data << {addr[1:0],3'b000}`, `store_wstrb` per size+addr. `mem_req_o`: addr=alu_result (EA), wdata=store_wdata, wstrb=store_wstrb, we=mem_write, rready=(EX_MEM_WAIT)&mem_read. Misaligned access (LH/LHU at addr[0]=1, LW/SW at addr[1:0]!=0, cross-word sub-word): suppressed — `mem_misaligned` blocks launch and retire, no trap. Branch resolve: BEQ/BNE/BLT/BGE/BLTU/BGEU + JAL/JALR-always; `branch_addr=(rs1+imm)&~1` for JALR else `pc+imm`; `flush_o=branch_valid_o` kills decode D/E, propagates to fetch redirect. E/M taps pulse `ex_valid` once per retire (`op_retires = valid & ~illegal & ~stall_i & result_ready & ~mem_misaligned`; misaligned/illegal never retire).

### Hazard interlock behaviour
Stall-on-RAW, in `decode_stage` (no separate module, no bypass). `raw_haz = decoded_valid & ~flush_i & ex_wb_en_i & (ex_wb_addr_i!=0) & (rs1 or rs2 matches ex_wb_addr_i)` where `decoded_valid = is_hold || fe_valid_i` — gated on `decoded_valid` (NOT `fe_valid_i`) so the interlock also covers a hold-buffer upper-half RVC consumer (which decodes with `fe_valid_i=0`); gating on `fe_valid_i` alone would miss a hazard where the low half of a compressed pair writes rd and the stashed upper half reads it. Fires only the cycle execute retires a writeback (so DIV/REM busy and LSU EX_MEM_WAIT cycles don't false-trigger; the div's done cycle / the load's rvalid cycle do). On `raw_haz`: **bubble** the D/E register (`de_next='0` — not a hold, so execute does NOT re-run E_N or relaunch a finished div / LSU op) and **hold** F/D for one cycle (via `stall_o`'s `raw_haz` term → `fetch.stall_i`), so decode re-reads the regfile after the producer's writeback commits. Covers all 1-cycle-distance (execute vs decode) cases: ALU-RAW, div-done-then-use, branch-on-dependent (the branch resolves with the fresh operand → correct control flow, not just a correct register), and **load-use** (a consumer right behind a load: the load's extra `EX_MEM_WAIT` cycles hold the consumer in decode, and the load's `wb_en` pulse triggers the one-cycle bubble — so the consumer re-reads the fresh loaded value, one bubble, no bypass). `~flush_i` skips the stall when E_N is a taken JAL/JALR (writes link AND redirects — the fall-through is discarded). Source addresses are forced to `x0` for instrs that don't use them, so unused sources never false-trigger. Verified by `sim/program.hex` + the retire+writeback log (RAW + LSU sections). No combinational loop: `raw_haz` depends only on registered sources + decode's combinational source addresses, not on `stall_o`/`fetch.stall_i`; execute's `stall_i` stays `1'b0` (the interlock bubbles execute's input, it does not stall execute).

**Known limitations:**
- No bypass path — the stall-on-RAW interlock resolves register AND load-use hazards by **bubbling** (one-cycle stall), not by forwarding. Each dependent op pays the bubble.
- No trap / exception support. A misaligned access is suppressed (not launched, not retired), not trapped. Cross-word sub-word accesses that need two beats are not handled.
- The LSU reaches peripherals by address through the board-top `axi4_lite_xbar` (`addr[PERI_ADDR_BIT]=1`→peri). However **no peripheral slave is instantiated yet** — the peri bus slave side is tied off (`awready`/`arready`=0), so a peripheral access currently **stalls the LSU** (the bridge never sees a handshake). This is fine until code targets the peri region; a real UART/GPIO slave on `axi_bus_peri` is the remaining MMIO work.
- `ex_*` taps expose pc/instr/valid (internal); the writeback **value** is observable via the internal `wb_en`/`wb_addr`/`wb_data` nets, logged by the sim through the Verilator hierarchy.

### Open work
- LSU is in: loads/stores/Zilx indexed loads launch + retire via the shared imem bus + `mem_arbiter`; `mem_rsp_t.bvalid` added and driven by the bridge; load-use covered by the existing stall-on-RAW interlock.
- Remaining memory work: **MMIO address decode is done** — the board-top `axi4_lite_xbar` routes `addr[PERI_ADDR_BIT]=1` accesses to the peri bus (`axi_bus_peri`), and the CPU's single `bus_axi` carries both mem and peri traffic. What remains is a **real UART/GPIO slave** on `axi_bus_peri` (today the peri slave side is tied off, so a peri access stalls the LSU — drop in an `axi4_lite_*` slave with no other board-top change).
- Decode decodes Zilx (now retires through the LSU); Zicsr/Zifencei still deferred (`illegal=1`).
- No trap/exception machinery — misaligned accesses are suppressed, not trapped. Add CSR/exception support before relying on aligned-only code.
- RVC spanning-across-word-boundary is now **handled** (stitched in decode, one bubble — see **Decode behaviour**); odd-half branch targets that are 32-bit instrs are stitched too. Compiled RVC code runs. Verified: `fib` built `-march=rv32imac` (generates a spanning `bge` at offset 2) computes fib(20)=6765 and stops; the `-march=rv32imac` and `-march=rv32ima` builds produce byte-identical `x10` writeback sequences (the stitch is transparent to the architected result). The Zilx quicksort (`sim/sw/main.c`, also `-march=rv32imac`) spans too (the `lxs.w` `.insn` itself lands at offset 2) and returns `a0=0x600D` with the 1-entry fetch skid in place, so the stitch is exercised and correct end-to-end with run-ahead fetch. The remaining RVC cost is the 1-cycle `span_wait` bubble per spanning instr — the fetch skid pre-captures W+1 so it promotes to F/D the cycle after W is consumed (matching the original overlap-prefetch timing); fully avoiding the bubble would need a wider F/D so W+1 is in F/D the same cycle as W. The skid buffer's primary role is shared-imem-bus deadlock freedom, not span_wait — see **Fetch behaviour**.
- `cmd.do` targets 50 MHz (`clk_core`); PnR closes at ~50.15 MHz Actual Fmax (≈0.060 ns slack; ±0.1 MHz run-to-run from placement-seed non-determinism). Regfile primitive is NOT the limiter (A/B: BSRAM vs `registers` identical) — headroom needs attacking the route-dominated execute/ALU/decode critical path. The LSU + arbiter + `axi4_lite_xbar` add combinational depth (EA / alignment / store-shift) and arbitration/routing muxes on the imem path; the spanning stitch adds a 32-bit mux (`{fe_instr[15:0], hold_word[15:0]}`) into the decode field-extraction path — re-measure Fmax after a PnR run (the xbar is a pass-through with no data-register, so it adds a mux delay but no latency).
