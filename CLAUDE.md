## Project

RV32IMAC + Zicsr + Zifencei RISC-V core for a **Gowin GW2AR-18C** FPGA (QFN88) on a Tang Nano 20k. Clock: 25 MHz single-ended from an MS5351M generator (CLK0, PIN10, LVCMOS33) — not the stock 27 MHz oscillator. **Active build: 50 MHz via on-chip rPLL** (`clk_core = clk_i × 10/5`, IDIV_SEL=4/FBDIV_SEL=9/ODIV_SEL=16, VCO 800 MHz, period 20 ns) — re-closed at **50.017 MHz** on the 64-bit fetch-rewrite + target-span design (2026-08-27). A **branch predictor** (gshare 128×2b PHT + 7-bit GHR + 8-entry RAS, prediction-at-decode, execute-as-judge) was added 2026-08-28 and resized 2026-08-30, sim-verified (all oracles/cosims/TBs green). With linker relaxation also enabled the same day: **CoreMark 1.98 CM/MHz, Dhrystone 0.88 DMIPS/MHz**. PHT depth is set by TIMING, not accuracy — it is read combinationally at decode and that read feeds fetch's launch/inflight logic in the same cycle, so a 512-entry table cost ~1 ns of slack for 0.65% of cycles (see `rv32_pkg.sv`). **50 MHz re-closed WITH the predictor on 2026-08-31** (worst setup slack **+0.093 ns**), after three changes landing together: PHT sized down to 128, the ALU result mux reordered by arrival time, and the PnR algorithms set to timing priority. `BP_EN=0` remains the fallback but is no longer needed. Pre-fetch-rewrite design closed at 40.281 MHz (2026-08-25). Fallback: 25 MHz bypass (also diagnostic — removes rPLL) via 3 lines in `top_module` + re-comment SDC clock + `global_freq 25.000`.

**Status:** fetch/decode/execute + LSU + Zicsr + trap/exception/interrupt implemented. **Harvard** memory — read-only I-mem for fetch, native byte-strobed D-mem for LSU, AXI4-Lite only for peripherals. **Both memories 16 KiB (`ADDR_W=14`)**: GW2AR-18C has 46 BSRAM blocks (828 Kb); each 16 KiB memory = 8 blocks, 16/46 used. Package also carries **8 MiB (64 Mbit) SDRAM** on a separate die, unused (see plan item 2). Loads/stores/Zilx/CSR retire via native D-mem (or peri bridge) with **execute→decode forwarding** (distance-1 RAW, zero bubble).

**Machine-mode traps:** precise sync traps at execute commit — instr access fault (mcause=1), illegal instr (2), ecall-M (11), ebreak (3), load/store misaligned (4/6); `mret` returns; `wfi`=halt-until-pending; `fence`/`fence.i`=nop. `mtvec` direct+vectored. Software interrupt via `msip_peri`@0x1000_3000; timer via `clint_timer`@0x1000_1000+; external = OR of peripheral IRQs (UART)→`meip_i`. Priority MEI>MSI>MTI. Trapping instr not retired.

**Timing:** pre-rewrite closed 40.281 MHz (2026-08-25) via two register stages (LSU request, CSR read). **64-bit/2-outstanding fetch + target-span rewrite re-closed 50.017 MHz (2026-08-27)** — new instruction-buffer room comparator met 20 ns; critical path stayed on `head_q → fe_instr → c_expand → regfile → forward`. **Branch predictor dropped PnR to 47.4 MHz** (2026-08-28) — prediction-adder path fix was tried then reverted (wrong on far jumps, no IPC gain in-kernel). **Re-closed 50 MHz with the predictor on 2026-08-31, +0.093 ns worst slack**, by three independent moves:
1. **PnR algorithm selection** (`impl/pnr_check.tcl`): `-place_option 2` (timing priority) + `-route_option 1` (route by timing). Both had been at 0, which optimises compile speed. These are algorithm *selectors*, not effort levels — `-route_option 2` is *faster compiling*, not better timing. This was the single largest contributor and cost no silicon.
2. **PHT 512 → 128.** The PHT is read combinationally at decode and that read feeds fetch's launch/inflight in the same cycle, so depth is a timing parameter. At 512 the read was 6.1 ns, **3.36 ns of it pure routing** between spread-out LUT-RAM primitives. Costs 0.65% of cycles.
3. **ALU result mux reordered by measured arrival time** — see `alu.sv`.

**Lesson (measured twice):** run-to-run placement noise on this design is ~0.7 ns on the same path, comparable to the whole gap being closed, so a single PnR run is not evidence about an RTL change. Also: Fmax under a loose constraint understates what PnR does when pushed.

**Current limiter: MUL.** Every top path is `regfile → forward → operand → DSP (3.78 ns) → alu_result ×6 → wb_data → forward`. The `mul_result` selection (4-way among the three DSP products) still sits ~6 mux levels deep; collapsing it is worth ~1.5-2 ns if more headroom is ever wanted. Next limiter after that: `regfile → forward mux → branch compare/target → PC redirect`. Stall histogram (2026-08-27) agrees from the cycle side: redirect was the largest single no-retire cost (~3.1 cyc/taken redirect, 38–50%) — exactly what the predictor targets (redirect CPI 0.374→0.102 on CoreMark). Legacy `VON_NEUMANN` build dropped.

CPU exposes 3 ports: native `imem` (RO), native `dmem` (byte-strobed), AXI4-Lite master `axi_peri`. Native→AXI conversion inside the CPU (`axi4_lite_master_bridge`); board top is pure wiring. LSU decodes `addr[PERI_ADDR_BIT]` (0→D-mem, 1→peri). Only non-bus CPU output: `dbg_stall_o`→LED0.

## Simulation (Verilator)

Builds fetch+decode+execute+native I/D-mem+peri bridge, `--public-flat-rw`.

- `sim/sim_top.sv` — wrapper preloading native I/D-mem via `$readmemh` (`+IINIT=`/`+DINIT=`). 64-bit RO `OUTSTANDING=2` I-mem, 32-bit RW `OUTSTANDING=1` D-mem. `uart_rxd_i` double-flopped for board parity; every TX-FIFO byte logs to `sim/sim_uart_tx.txt`. `UART_CLK_HZ`/`UART_BAUD` default fast (5 clk/bit); pass `-GUART_CLK_HZ=25000000 -GUART_BAUD=115200` for board-real 217.
- `sim/sim_main.cpp` — drives clk/rst, logs fetch/decode/execute-retire+writeback. `UART_RX="..."` types real 8N1 frames; `UART_RX_PACED=0` ships back-to-back; `UART_BIT_CYCLES=217`=board-accurate; `NO_VCD=1` skips dump. Stops on park (8 identical retires) or `MAX_CYC` (default 4000). Prints a **stall-cause histogram** (load-wait/lsu-launch/lsu-capture/div/csr/wfi/rvc-hold/rvc-span/redirect/imem-starve/decode-bubble) and the same data as a **CPI decomposition** (each bucket ÷ retires — this form is comparable across designs, since `dbg_stall_o` %-of-cycles is not: it doesn't see fetch bubbles). Taxonomy/tables in `sim/README.md`. Checks WFI-halt invariant every run.
- `sim/imem.hex`+`dmem.hex` — hand-crafted Harvard oracle (RAW, LSU round-trip/load-use, byte/halfword sign/zero extend).
- `sim/Makefile` — `make run` (oracle); `RUN_ARGS="+IINIT=... +DINIT=..."` for C programs.
- `sim/sw/` — firmware tree. `common/` = shared assets (`uart.h`, `start.S`, `link.ld`, `bin2hex.py`, `ee_printf.c`) + `sw_build.mk` (parameterised build include: `ARCH`/`C_SRCS`/`S_SRCS`/`LINK_LD`/`DMEM_BASE`/`IMEM_PAD_WORDS`/`EXTRA_CFLAGS`/`EXTRA_LDFLAGS`/`EXTRA_LDLIBS`; stamps `build/.config` so a flag change forces rebuild). `quicksort/`/`coremark/`/`dhrystone/` = benchmarks; `isa/`/`intr/`/`peri/` = oracles. **Toolchain**: buildroot glibc `riscv32-buildroot-linux-gnu` at `~/_toolchains/riscv32-zilx/out` (gcc 14.3.0), override `RISCV_PREFIX`. `-march=rv32imac -mabi=ilp32 -nostdlib -ffreestanding -medlow -no-pie -Wl,-N -fno-pie` (glibc toolchain defaults to PIE/PT_PHDR, breaking the Harvard split — needs medlow absolute addressing). **Linker relaxation is ON** (2026-08-30; `-Wl,--no-relax` removed): without it every `call` stayed `auipc ra,X; jalr ra,off(ra)`, costing an instruction *and* a guaranteed mispredict, since decode predicts PC-relative targets but not indirect ones. Relaxing to `jal` removed 110 of Dhrystone's 111 static `jalr`/`jr` sites, −11.8% `.text`, −5.8% cycles/iteration. gp-relative relaxation stays inert (no linker script defines `__global_pointer$`, `start.S` never loads gp) — do not define one without also setting gp. Default program `quicksort/main.c`: recursive quicksort, 256-word LCG array (same seq on Spike/RTL), returns `0x600D`/`0xBAD`.

```bash
cd sim && make run                    # Harvard oracle
make sw-run                           # build C prog + run (from repo root)
```
Build artefacts gitignored.

### Test harnesses (build in own dir, run from `sim/` with `+IINIT=.../build/imem.hex +DINIT=.../dmem.hex`)

Compliance TBs: `sim/hw/native_mem_tb/` (32-bit native_ram, 37 checks), `sim/hw/native_ram64_tb/` (64-bit/OUTSTANDING=2 config, 23 checks), `sim/hw/ram_tb/` (AXI4-Lite peri RAM), `sim/hw/uart_tb/` (TX/RX FIFO ordering, overrun, IRQ — 146 checks).

Cosim: `sim/cosim/quicksort/` diffs per-retire pc+regwrite vs Spike (`cosim_diff.py`); Harvard needs `.data`@non-zero VMA (0x2000) so Spike's unified space matches; `SPIKE_MEM` mirrors real sizes so hardware-silent aliasing traps in Spike instead; `build_spike.sh` relocates 2 fixed Spike devices to avoid a 4 KiB overlap capping `.text`. `make cosim` → "PASS -- matched N retires". `sim/cosim/ecall/` covers a sync trap (ecall itself isn't Spike-comparable — Spike hijacks M-mode ecall as htif exit) → PASS 17 retires. `sim/cosim/coremark/` → PASS 332803 retires (`COSIM=1 -O2`, no cycle counter/banner — Spike is one address space so `.text` must end below 0x2000).

Firmware oracles (self-checking, `0x600D`/`0xBAD` unless noted):
- `sim/sw/intr/trap/` — ecall/load-misaligned/illegal/MSIP+WFI, standalone M-mode.
- `sim/sw/intr/wfi_trap/` — regression for a WFI-halt deadlock (halt flag must clear on `int_pending` not `take_interrupt`); hand-encoded, no toolchain.
- `sim/sw/intr/timer/` — arms `mtimecmp`, wakes on MTIP. Not Spike-comparable (no CLINT slave).
- `sim/sw/peri/uart_echo/` — only end-to-end MEIP test (UART IRQ→mip.MEIP→trap→wfi wake); doubles as board bring-up. Result @0x3000.
- `sim/sw/isa/rvc_scramble/` — per-bit decode oracle for every RVC scrambled-immediate form; caught the c.addi4spn `nz[3]/nz[2]` swap.
- `sim/sw/isa/span_target/` — same-cycle target-span stitch oracle (branch to 32-bit instr at offset 2/6 of an 8-byte fetch word); no other cosim/oracle exercised this path.
- `sim/sw/isa/bp_pred/` — branch-predictor correctness oracle (9 cases: always-T/NT, loop-exit mispredict, alternating, correlated, RVC c.bnez, JAL+JALR RAS push/pop, mispredict w/ 2 outstanding, ecall-vs-predicted-branch priority). Guards that mispredict never corrupts architectural state; caught a hold-buffer-survives-predicted-redirect bug. Pure assembly.
- `sim/sw/isa/ifault/` — jump to 0x100000, checks single trap with mcause=1/mtval=target; handler rewrites mepc (unfetchable) rather than mret-ing back.
- `sim/sw/isa/isa_probe/` — board bring-up probe using only register-register AND/mask doubling (never the hex printer, which was once itself buggy); found the load byte-select bug via constant-vs-computed-address load comparison.

`UART_TX_PACED=1` — one byte in flight at a time; diagnostic for isolating "FIFO filled" vs "poll never returned".

### CoreMark (`sim/sw/coremark/`, cosim `sim/cosim/coremark/`)
`eembc/` vendored verbatim (commit 1f483d5, Apache-2.0, hashes in `UPSTREAM.md`); `make verify-eembc` fails the build on any edit — a modified workload isn't comparable. Replaced an older fork with 3 bugs: duplicate untimed `iterate()` (2× runtime, invisible in CRCs), 32-bit overflow in a hand-added CoreMark/MHz line, an uninitialised `list_data info` upstream already fixed.

Port additions (all outside `eembc/`): `MEM_METHOD=MEM_STATIC` (no malloc), `HAS_FLOAT=0`, `HAS_STDIO=0`, timing from `mcycle`, `ee_printf.c` UART printf, local memcpy/memset, pre-run banner, post-run summary (ticks/cyc-per-iter/sec/iter-per-sec/CoreMark-MHz w/ 2 decimals, since upstream prints only `%d` without FPU). Flags: `-O3 -ffunction-sections -fdata-sections -mstrict-align -mbranch-cost=10 -ffp-contract=off -mno-fdiv -Wl,--gc-sections` (`-mstrict-align` load-bearing — core traps on misaligned). 11.1 KiB `.text`/4.0 KiB data. `CLK_HZ=50_000_000` (rPLL 25×10/5).

**Score (post predictor + linker relaxation + ALU restructure, 2026-08-31): 504977 cyc/iter = 1.98 CoreMark/MHz** (was 531025 / 1.88 / 0.561 post-fetch-rewrite, `BP_EN=0`) (before: 622006 cyc / 1.63 / IPC~0.44 — the fetch path was the bottleneck the rewrite removed). CRCs match official 2K seed values; 2000-iter `crcfinal`=0x4983 matches published cores. Valid `ITERATIONS` at 50 MHz: 814–6979 (≥10s, under 32-bit `mcycle` wrap). Reference: SiFive E31 publishes 1.61, NEORV32 performance-config 0.95 — 1.98 sits above that band. gcc 15.1.0 measured ~2% slower than 14.3.0. Zilx unusable (neither toolchain accepts it in `-march`; would need hand `.insn`, against run rules).

### Dhrystone (`sim/sw/dhrystone/`)
`sifive/` vendored verbatim (SiFive benchmark-dhrystone, commit 0ddff53, `make verify-sifive` guards edits) — matters more here since `strcpy`/`strcmp` run inside the measured loop. Dialect pinned `-std=gnu17` (K&R style; gcc15 defaults C23, gcc14 needs implicit-int/decl warnings downgraded).

Port additions: `dhry_portme.c` (main, `mcycle` timer, bump allocator, word-at-a-time strcpy, banner/summary), freestanding `stdio.h` shadow, `dhry_link.ld`. Two `-D`s stand in for upstream edits: `-Dmain=dhry_main` (scoped to `dhry_1.o` only, so port can print after the report) and `-Dfloat=long` (7 float uses are post-timer report-only; no FPU, libgcc is ilp32d so soft-float symbols don't exist). Flags `-O3 -mstrict-align -fno-common -falign-functions=4 -DTIME -DNOENUM`. 5.8 KiB text / 1.9 KiB rodata / 10.3 KiB bss.

`Arr_2_Glob` (`int[50][50]` = 10000 B bss) doesn't fit above the default 0x2000 D-mem split, so `dhry_link.ld` moves DMEM to start at 0 (whole 16 KiB), with a linker `ASSERT` keeping bss 1 KiB clear of `sp=0x4000`. Cost: `.text` also at 0 → **not co-simulated** (unlike quicksort/CoreMark).

**Score (post predictor + linker relaxation + ALU restructure, 2026-08-31): 644 cyc/iter = 0.88 DMIPS/MHz @50 MHz** (all 22 final-value checks match; was 686 / 0.82). Dhrystone gains most from relaxation because it is call-dense: `-Wl,--no-relax` had left every `call` as `auipc ra,X; jalr ra,off(ra)`, an indirect jump the predictor cannot predict. DMIPS/MHz = 1e6/(cyc-per-iter×1757). Number is strcpy-sensitive by construction: a plain byte-loop strcpy measures 0.63 DMIPS/MHz on the same core — port ships word-at-a-time to match published-score convention. Needs `DHRY_ITERS`≈145772 at 50 MHz for the ≥2s run rule; `mcycle` wrap caps ~6.26M.

## Architecture

Built bottom-up. Every RTL file: `import rv32_pkg::*;` + `` `resetall `` / `` `default_nettype none `` / `` `timescale 1ns/1ps ``.

### Naming
Ports `_i`/`_o`. Flops `_q`, next-state comb `_d`. Instances `u_*`. Stage debug taps `fe_`/`de_`/`ex_`, internal only (`dbg_stall_o` is the sole exported one).

### Files
- **`rv32_pkg.sv`** — `XLEN=32`; `mem_req_t`/`mem_rsp_t`/`ifetch_req_t`/`ifetch_rsp_t`. `PERI_ADDR_BIT`=28; peri windows `UART_BASE`=0x1000_0000/4K, `MTIMER_BASE`=0x1000_1000/8K, `MSIP_PERI_ADDR`=0x1000_3000/4K. Decode types: opcodes (incl `OPC_AMO`), `alu_op_t` (incl `ALU_LX`), `wb_src_t` (incl `WB_CSR`), `csr_op_t`/`csr_addr_t`, `sys_op_t`, `MCAUSE_*`, `MSTATUS_*`, `MTVEC_DIRECT/VECTORED`. Packed `de_t` D/E struct. **Branch-predictor types**: `pred_source_t` enum `{PRED_NONE,PRED_DIRECT,PRED_PHT,PRED_RAS}`; `bp_lookup_req_t`/`bp_lookup_rsp_t`/`bp_train_t`; **BP geometry localparams** `BP_PHT_DEPTH`=128/`BP_PHT_IDX_W`=7/`BP_GHR_W`=7/`BP_RAS_DEPTH`=8 (single source of truth — the index-carrying struct fields are all `BP_PHT_IDX_W` wide); `de_t` carries `pred_valid`/`pred_taken`/`pred_target[32]`/`pred_source[2]`/`pred_pht_index[7]` (~43 bits) riding D/E to execute for compare against resolved outcome.
- **`fetch_stage.sv`** — 64-bit, 2-outstanding, depth-8 (32-bit-word) instruction buffer. One 64-bit access delivers two 32-bit words, split into PC-stamped buffer entries (0/1/2 pushes/cyc); decode still consumes the head exactly as the old F/D word — decode itself unmodified. `pc_q` advances by 8; `req_pc_q` holds the real in-flight PC. **Split PC stamp**: the half containing the fetch PC is always stamped `req_pc_q` so decode's `fe_pc[1]` picks the right halfword — stamping the high half with a computed address instead clears bit[1] and misrouted a `jalr` (fixed 2026-08-26, latent because the in-place oracle never redirected into the high half). `inflight_q[1:0]` caps outstanding at 2 (backed by the I-mem's depth-2 response skid); a redirect sets `pc_q`, kills the buffer, `draining_q` discards ≤2 stale responses. Overflow-safe room gating: `available = 8 - count - 2*inflight`, issue needs `available>=2 & inflight<2`, fault push needs `available>=1`. Inputs: `stall_i` (decode), `branch_valid_i`+`branch_addr_i` (execute redirect incl trap/mret/interrupt), **`pred_valid_i`+`pred_addr_i`** (decode's predicted-taken redirect, priority-merged *below* execute redirect via `pred_redirect = pred_valid_i & ~branch_valid_i`, same kill path, fires one cycle earlier). **`IMEM_ADDR_W` range check**: PC outside implemented I-mem → fault entry instead of a bus request; parameter must match the instantiated `native_ram`.
- **`decode_stage.sv`** — RV32I+M+C+Zilx+Zicsr. Expand-then-decode (`c_expand()` RVC→32-bit, one decoder), hold buffer for the upper compressed half. RVC funct3=100 group selector = `c[11:10]` (00 srli/01 srai/10 andi/11 arith-subgroup `c[6:5]`); `c[12]` is shamt[5]/imm[5], not a selector. That group + 3 immediate-scramble forms decoded wrong until 2026-08-25 (latent — no cosim/oracle emitted those patterns), now guarded by `sw/isa/rvc_scramble`. Zilx (`OPC_AMO` funct5 10010/11010; 11110 illegal) swaps rs1/rs2, computes `mem_shamt`. Zicsr sets csr_op/csr_wren/csr_addr, `wb_src=WB_CSR`. funct3=0: ecall/ebreak/mret/wfi→`sys_op`; `OPC_MISC_MEM` fence/fence.i→`sys_op` (nop); unknown→`dec_illegal`. **`fe_fault_i`** outranks every source (unfetchable PC → precise trap `MCAUSE_INSTR_ACC`). `stall_o` = hold-term | execute stall | WFI-halt — **no RAW term**. **Forwarding**: `fwd_rs1`/`fwd_rs2` inject `ex_wb_data_i` on match when `ex_wb_en_i` fires — distance-1 RAW, zero bubble. **Branch prediction** (`BP_EN` param, default 1): classifies the control-flow instr at buffer head (cond/JAL/JALR-call/JALR-return via `branch_type`+`rd`+`rs1`), computes direct `src_pc+imm` target (adder off the regfile/forward path — parallel to `c_expand`), queries predictor (PHT for cond, RAS top for returns), stamps `pred_*` into `de_d`. Predicted-taken instr asserts `pred_redirect_valid_o`/`_addr_o` (one cycle earlier than execute would). **Depends only on PC+GHR, never register data** — stays off the `regfile→forward→branch` critical path. **Hold-buffer flush fix**: a predicted-taken redirect must also clear the RVC hold buffer, else a wrong-path fall-through instr retired (caught by quicksort cosim at retire 94; guarded by `sw/isa/bp_pred`). `BP_EN=0` zeroes `de_d.pred_*` and emits no predicted redirect.
- **`reg_file.sv`** — 32×32 BSRAM, async read×2/sync write×1, x0 hardwired. Confirmed NOT the Fmax limiter. No runtime reset (single write port); sim zero-inits under `` `ifdef VERILATOR ``, HW relies on write-before-read.
- **`csr_regfile.sv`** — 11-entry Zicsr M-mode subset. **Registered read** (decode presents addr, data lands next cycle — used to be async and made `de_q.csr_addr→fetch pc_q` critical) + sync write (execute RMW). Execute holds a CSR op one extra cycle (`EX_CSR_WAIT`) at measured **zero** cost — fits inside the existing fetch bubble. Consequence: `mcycle`/`minstret` read back the previous cycle's value. FF+LUT mux, not BSRAM. Reset to architected values (`misa`=0x40002105 RO); unimplemented addrs read 0/ignore writes. Trap-write bundle (priority over RMW) + `msip_i`/`mtip_i`/`meip_i` + comb taps. `mstatus` RMW forces MPP=11 (M-only); `mtvec` RMW masks MODE.

Entry: MPIE←MIE/MIE←0/MPP←11; mret: MIE←MPIE/MPIE←1/MPP←11.

Straight-off-`alu_result` closed on paper, failed on silicon. Costs 1 cyc/access (quicksort IPC 0.500→0.469), bought +4.8 ns, moved critical path off the LSU. Mirror change on the return path was tried (IPC 0.436) and **not kept**. **Posted store** retires on launch accept; loads wait in `EX_MEM_WAIT` for `rvalid`. Training (`bp_train_o`) fires at resolve for every control-flow instr: PHT update indexed by the **GHR snapshot** `de_i.pred_pht_index` (uses the history the branch was predicted with), GHR shift, RAS push/pop. In-order single-issue → squashed wrong-path instrs never train.

### Pipeline behaviour
**Fetch**: 64-bit/2-outstanding/depth-8 buffer. One access delivers two words; 2-outstanding keeps the BSRAM issuing through decode stalls, removing the pre-rewrite dominant bottleneck (~2.2 cyc/instr). Steady state ~1.8 cyc/instr. Harvard so fetch owns the I-mem port uncontended. Redirect kills buffer + ≤2 in-flight reads (drain FSM). Decode also reads `head+1` (`fe_next_instr_o`/`fe_next_valid_o`=count≥2) for the same-cycle target-span stitch, driving `fe_pop2_o`.
**Decode** priority: spanning stitch > compressed hold > odd-half target > fresh low half. **Branch-target span (offset 2/6) is zero-bubble** (`target_span_complete`); **sequential span remains 1 bubble** (`span_wait`, fall-through case — removing it is dual-issue, deferred). Deferred-to-execute traps: unknown opcode, AMO funct5 11110/sfence.vma (no VM). Retiring in execute: ecall/ebreak/mret/wfi/fence/fence.i. Zicsr fully decoded+retired.
**Branch prediction**: decode predicts every classified control-flow instr — JAL/c.j/c.jal get a direct target (no BTB, zero cold-start mispredicts), conditional direction from PHT, JALR-returns from RAS; other JALR unpredicted. Predicted-taken redirects fetch one cycle early; execute stays golden resolver. Net effect on no-retire budget: redirect CPI drops ~3× but a *new* `imem-starve`/`other` ~0.21 CPI appears (kill+refill bubble on every *correct* predicted-taken branch, since no mispredict fires to charge it to `redirect`) — gross redirect saving (~0.28) nets to ~+0.06 CPI after that refill cost. Accuracy 74/84/79% (qs/cm/dh), RAS hit 98–100%. Architectural retire stream identical BP on/off (verified: quicksort 29675 retires both ways).

### Hazard resolution (execute→decode forwarding)
`fwd_rs1`/`fwd_rs2` fire when execute retires a writeback to a register the decoding instr reads (x0 excluded): inject `ex_wb_data_i` instead of the stale async regfile read — zero bubble. Covers ALU-RAW, div-done-then-use, branch-on-dependent, load-use (load's `EX_MEM_WAIT` holds consumer via `stall_i`; `wb_en` pulse on `rvalid` drives forward). Distance-2+: harmless, async regfile read already sees the committed value. Legacy `raw_haz` bubble interlock disabled.

**Rule the forward path imposes**: a combinational value derived from D/E operands (anything downstream of `alu_result`) may be consumed **only in the cycle it's produced** — later-cycle needs must latch it. Operands can come from the bypass, so such a value sits at the end of the critical path: simulation settles it regardless of depth, silicon does not. This is how the load byte-select bug got in — first thing to check when HW/sim disagree. Audited: `store_wstrb`/`store_wdata`/`mem_req.addr`, `sync_tval`, trap bundle payload.

**Known limitations:**
- Forward path distance-1 only (correct — execute retires ≤1 writeback/cyc in order).
- M-mode only (no S/U, medeleg/mideleg, PMP). Instruction access fault implemented; instruction-address-misaligned deliberately absent (IALIGN=16 with C ext means no odd PC can arise). Cross-word sub-word accesses unhandled. MEIP is single ORed level (only UART, no PLIC — ISR must poll). Unimplemented CSR addrs silently read 0/ignore writes.
- WFI halts forever if no enabled interrupt ever arrives (legal). `fence.i`/`fence` are nops (Harvard has no D→I write path).
- Harvard: I-mem holds `.text`/`.text.init` only; rest lives in D-mem. Three learned linker/startup rules: every `link.ld` must collect small-data sections (`.srodata*`/`.sdata*`/`.sbss*`) into `.rodata`/`.data`/`.bss` (gcc's `-msmall-data-limit` default puts objects there; `objcopy -j .rodata -j .data` misses uncollected sections); `start.S` zeroes `.bss` and `a0`/`a1` before `call main`; `sp=0x4000` (top of 16 KiB D-mem — above it aliases silently, only `ADDR_W` bits decoded). `.data`@0x2000 keeps Spike co-sim disjoint; requires `medlow`.
